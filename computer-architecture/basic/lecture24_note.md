## 0. 本講地圖

計算機算術這章（課本 Ch8）的第 4 講，也是第二組投影片的開始。前三講是加法器和乘法器（第 21–23 支），這一講是**整數除法**，之後是浮點數的加法（第 25 支）、乘除法（第 26 支）。

```
N = D·Q + R
  → 一次決定商的一個 bit（從最高位開始），問題一位一位縮小
  → 硬體：U（n+1 位元）、V（n 位元）、D；每次 UV 左移、U 減 D
     restoring：減成負的就加回去（每一圈最多 2 次加減）
     non-restoring：不加回去，下一圈改成加 D（每一圈剛好 1 次）
  → 兩個都是 O(n log n)
```

---

## 1. 只考慮正數

[00:48] 只討論**正數**的除法。負數的除法很麻煩：

- [01:09] 餘數的符號有不同的慣例：有的規定餘數一定是正的，有的規定餘數跟除數同號。
- [01:33] 大部分函式庫或處理器的做法：先**轉成正數**、做除法、再依慣例調整商和餘數的符號。
- [02:01] 除法本來就很慢，不容易有 O(log n) 的演算法，多做一點轉換沒關係。

【課本補充】課本 p.334：有些架構保證餘數一定是正的，這時要適當調整商和餘數。

## 2. 名詞與兩個性質

[02:37] 算 N / D：

```
N = D·Q + R        （Equation 1，課本 Eq. 8.15）
```

| 名稱 | 意思 | 101 / 20 的例子 |
|---|---|---|
| N | **dividend**（被除數） | 101 |
| D | **divisor**（除數） | 20 |
| Q | **quotient**（商） | 5 |
| R | **remainder**（餘數） | 1 |

[03:51] 任何除法演算法都要滿足（課本 p.334）：

| 性質 | 內容 | 反例 |
|---|---|---|
| **Property 1** | 0 ≤ R < D | 101 / 20 不能是商 4、餘 21 |
| **Property 2** | Q 是滿足 Equation 1（和 Property 1）的**最大**正整數 | 商 6 的話 R = 101 − 120 = −19 < 0 |

[06:05] 老師說這兩個性質合起來就足以確定答案；投影片上 Property 2 應該寫成「滿足 Equation 1 **和 Property 1**」。

## 3. 把問題一位一位縮小

[06:29] 商是 n 位元的二進位：Q = Qₙ…Q₁。把最高位拆出來（第 2 章的技巧，見 [第 4 支](lecture04_note.md)）：

```
Q = Qₙ · 2ⁿ⁻¹ + Q′          （Q′ 是剩下 n − 1 個 bit）

N = D·(Qₙ·2ⁿ⁻¹ + Q′) + R
N − D·Qₙ·2ⁿ⁻¹ = D·Q′ + R
└──── N′ ────┘
```

[09:06] 新的式子 **N′ = D·Q′ + R** 跟原來的**結構一模一樣**：

- 除數 D 一樣、餘數 R 一樣。
- 商少了一個 bit（n − 1 位元）。
- 被除數變成 N′ = N − D·Qₙ·2ⁿ⁻¹。

[10:17] 所以只要知道**最高位 Qₙ**，就能算出新的被除數 N′，變成一個商少一位的**較小的除法問題**。一直重複，最後只剩 D·Q₁ + R，再決定 Q₁，剩下的就是餘數。

[12:30] 「計畫聽起來很好，只是缺了祕方」：Qₙ 要怎麼算？

---

## 4. 怎麼決定最高位：猜 1 試試看

[13:51] Qₙ 只是一個 bit，只有 0 或 1 兩種可能，可以**暴力試**。

[14:49] 因為 Property 2 要商**越大越好**，先猜 Qₙ = 1：

```
N′ = N − D · 2ⁿ⁻¹
```

| N′ | 結論 |
|---|---|
| ≥ 0 | 猜對了：**Qₙ = 1**，用 N′ 繼續 |
| < 0 | 不能是 1：**Qₙ = 0**，N′ = N（不變） |

[17:08] 然後**遞迴**：用較小的參數做同一件事，直到剩一個 bit。

## 5. 手算例子：13 / 3

[18:23] 4 位元（n = 4），13 / 3 = 商 4（**0100**）、餘 1。

| 輪 | 試 | 結果 | 商的 bit | 新的被除數 |
|---|---|---|---|---|
| 1 | 13 − 3·2³ = 13 − 24 | < 0 | Q₄ = 0 | 13 |
| 2 | 13 − 3·2² = 13 − 12 = 1 | ≥ 0 | Q₃ = 1 | 1 |
| 3 | 1 − 3·2¹ | < 0 | Q₂ = 0 | 1 |
| 4 | 1 − 3·2⁰ | < 0 | Q₁ = 0 | 1（餘數） |

商 = 0100 = 4，餘數 = 1。✓

⚠️ [21:01] 老師口誤說「13 − 3 × 2² 等於 1，所以 Qₙ = 1」，馬上更正：是 **Qₙ₋₁**（也就是 Q₃），不是 Qₙ。

## 6. 硬體：U、V、D 三個暫存器

[23:19] 跟 iterative multiplier（[第 22 支](lecture22_note.md)）很像：

| 暫存器 | 一開始 | 最後 |
|---|---|---|
| **D** | 除數 | 除數 |
| **U** | 0 | **餘數** |
| **V** | 被除數 N | **商** |

- U 和 V 在位移時**當成一個暫存器**（UV）。
- 乘法每一輪是加法；除法是重複的**減法**：每一輪可能從 U 減掉 D，寫回 U。
- 乘法是**右**移，除法是**左**移。

【課本補充】課本 p.335：D 是 32 位元、V 是 32 位元，U 是 **33 位元**，避免溢位（跟 iterative multiplier 一樣）。課本 p.337 的證明說 U 最多要存 2D − 1，所以要 33 位元。

## 7. Restoring 演算法

[24:12] 課本 Algorithm 3（p.335）：

```
for i = 1 to 32:
    UV ← UV << 1              # 左移一位
    U ← U − D                 # 試著減
    if U ≥ 0:  q ← 1
    else:      U ← U + D      # 減過頭了：加回去（restore）
               q ← 0
    V 的最低位 ← q
# 結束：U = 餘數、V = 商
```

[25:48] 叫 **restoring**：先減，發現變負的，就把除數**加回去**，U 恢復原來的值。

## 8. 為什麼它是對的（圖解）

[26:41] 老師畫圖說明第一輪：

1. 一開始被除數全部在 V 裡。
2. 左移一位：被除數往左移，V 的最右邊空出一格（之後放商的 bit）。
3. 把「從被除數開頭到 U 的最左邊」看成一個數。D 在 U 裡，相對於被除數的開頭，是往左移了 **n − 1 位**。
4. 所以 `U ← U − D` 實際上算的是 **N − D · 2ⁿ⁻¹**，就是 [§4](#4-怎麼決定最高位猜-1-試試看) 的 N′（假設 Qₙ = 1）。
5. 結果 ≥ 0：Qₙ = 1，放進 V 空出來的那一格。結果 < 0：restore，Qₙ = 0。

[32:02] 第二輪一樣：被除數從新的位置開始，最右邊是已算好的 Qₙ 和這一輪要算的 Qₙ₋₁。因為式子是**遞迴**的（n = 32、31、30…），硬體每一輪都照同樣的邏輯做。

[33:29] 最後：**V 全部是商，U 剩下的就是餘數**。

【課本補充】課本 p.336 的正式證明：sign(U − D) = sign(N − 2ⁿ⁻¹·D)（Eq. 8.20），所以每一輪的判斷就是在決定那個商的 bit；再用歸納法證明每一輪都正確。

## 9. 例子：7 / 3（restoring）

[34:02] 課本 p.338 的例子：4 位元，7（0111）/ 3（0011）。U 是 5 位元（避免溢位），V 是 4 位元。X 是還沒算的位置。

| | U | V | 說明 |
|---|---|---|---|
| 開始 | 00000 | 0111 | |
| 1 左移後 | 00000 | 111X | 0 − 3 < 0 |
| 1 結束 | 00000 | 1110 | restore，商 bit 0 |
| 2 左移後 | 00001 | 110X | 1 − 3 < 0 |
| 2 結束 | 00001 | 1100 | 商 bit 0 |
| 3 左移後 | 00011 | 100X | 3 − 3 = 0 ≥ 0 |
| 3 結束 | 00000 | 1001 | 商 bit 1 |
| 4 左移後 | 00001 | 001X | 1 − 3 < 0 |
| 4 結束 | 00001 | 0010 | 商 bit 0 |

商 = **0010 = 2**，餘數 = **0001 = 1**。7 / 3 = 2 餘 1 ✓（本機重跑一模一樣，見 [§15.1](#151-照課本的暫存器跑一遍)）。

## 11. Non-restoring 演算法

[39:05] Restoring 的問題：減完發現是負的，要**再加回去**。這要多一次加法；或者先把 U 複製到另一個暫存器、減、再搬回來。不管怎樣都多做事。

[40:15] **Non-restoring** 的做法（課本 Algorithm 4，p.339）：U、V、D 一樣。

```
for i = 1 to 32:
    UV ← UV << 1
    if U ≥ 0:  U ← U − D      # 正的就減
    else:      U ← U + D      # 負的就加（上一輪沒有 restore）
    if U ≥ 0:  q ← 1
    else:      q ← 0
    V 的最低位 ← q
if U < 0:  U ← U + D          # 最後如果還是負的，修正一次
# 結束：U = 餘數、V = 商
```

[40:53] 減成負的**就讓它負著**，下一輪改成**加** D。每一輪只做**一次**加法**或**減法。

【課本補充】課本 p.338：restoring 每一輪最多兩次加減。用另一個暫存器暫存 U − D、只在 ≥ 0 時才搬回 U，也可以避開，但要多電路，U 暫存器會變複雜、變慢。

## 12. 例子：7 / 3（non-restoring）

[42:53] 一樣是 7 / 3。減 D 就是加 D 的 2's complement（−3 = 11101）。

| | U | V | 說明 |
|---|---|---|---|
| 1 左移後 | 00000 | 111X | U ≥ 0 → 減 3 |
| 1 結束 | 11101 | 1110 | U = −3 < 0 → 商 bit 0 |
| 2 左移後 | 11011 | 110X | U < 0 → 加 3 |
| 2 結束 | 11110 | 1100 | U = −2 < 0 → 商 bit 0 |
| 3 左移後 | 11101 | 100X | U < 0 → 加 3 |
| 3 結束 | 00000 | 1001 | U = 0 ≥ 0 → 商 bit 1 |
| 4 左移後 | 00001 | 001X | U ≥ 0 → 減 3 |
| 4 結束 | 11110 | 0010 | U = −2 < 0 → 商 bit 0 |
| 最後修正 | 00001 | | U < 0 → 加 3 |

[46:52] 商 = **2**、餘數 = **1** ✓。

[47:29] 漸近複雜度沒變：n 輪、每輪一次加減 → 仍是 **O(n log n)**，只是不用 restore。

[48:04] Non-restoring 是標準、非常常用的演算法，很多處理器用它做除法。

## 13. 為什麼 non-restoring 也是對的

[49:14] 老師說證明有點複雜，用投影片講不容易，詳細證明在課本（p.340），只給概要：

1. 從頭開始，只要 U − D ≥ 0，兩種演算法的狀態都**一樣**。
2. 某一輪 U − D < 0：兩者**分開**。
   - Restoring：UV（不算商的 bit）的值是 **A**。
   - Non-restoring：沒 restore，是 **A − 2ⁿD**。
3. 下一輪左移後：
   - Restoring：**2A**。
   - Non-restoring：**2A − 2ⁿ⁺¹D**。
4. 如果這一輪商的 bit 是 1：
   - Restoring 減 2ⁿD → **2A − 2ⁿD**。
   - Non-restoring 因為是負的，加 2ⁿD → 2A − 2ⁿ⁺¹D + 2ⁿD = **2A − 2ⁿD**。
   - **兩者又一樣了。**

[53:51] 結論：商的 bit 是 0 時兩者走不同的路（但算出的 bit 都是 0）；**每次商的 bit 是 1，兩者的狀態就重新合併**。Restoring 是對的，所以 non-restoring 也是對的。

【口頭】[52:34] 老師承認這個證明「有點 hand-wavy」，正式的請看課本。

## 15. 【實測】

程式在 `experiments/lecture24/`。

### 15.1 照課本的暫存器跑一遍

`divide.py` 照 Algorithm 3、Algorithm 4 實作 U（n + 1 位元）、V（n 位元）、D：

```
restoring：7 / 3（4 位元）
  開始           U=00000 V=0111
  1 左移後      U=00000 V=111X
    iteration 後 U=00000 V=1110
  2 左移後      U=00001 V=110X
    iteration 後 U=00001 V=1100
  3 左移後      U=00011 V=100X
    iteration 後 U=00000 V=1001
  4 左移後      U=00001 V=001X
    iteration 後 U=00001 V=0010
  商 2，餘數 1

non-restoring：7 / 3（4 位元）
  ...
  1 左移後 U=00000、iteration 後 U=11101
  2 左移後 U=11011、iteration 後 U=11110
  3 左移後 U=11101、iteration 後 U=00000
  4 左移後 U=00001、iteration 後 U=11110
  最後修正 U=00001
  商 2，餘數 1

13 / 3（影片的手算例子）： (4, 1)
10 萬組隨機的 32 位元除法：錯 0 組；平均每次加減法：restoring 55.7、non-restoring 32.5
```

- Restoring 的每一列和課本 p.338 的表**一模一樣**；non-restoring 的每一列和影片 [42:53]–[46:52] 的手算一樣。
- 10 萬組隨機的 32 位元除法（除數 1 到 32 位元不等），兩種演算法的商和餘數都和 Python 的 `//`、`%` 一樣。
- **加減法次數**：restoring 平均 55.7 次（32 次減法 ＋ 大約 24 次加回去）；non-restoring 平均 32.5 次（32 次 ＋ 大約一半的時候最後修正一次）。少了 **42%**，就是影片說的「工作量大約減半」。

### 15.2 真的 div 指令有多慢

`divlat.c` 讓每一次 `div` 都依賴上一次的結果（相依鏈），量平均時間；扣掉迴圈本身的 `and`／`or`。綁在 P-core（cpu2）跑兩次結果一樣，再跑 E-core（cpu14）：

| 運算 | P-core | E-core |
|---|---|---|
| `imul` 64 位元 | 0.64 ns | 1.39 ns |
| `div` 32 位元 100 / 7（商很小） | 2.57 ns | 3.34 ns |
| `div` 32 位元 4294967295 / 3（商 31 位元） | 2.56 ns | **6.97 ns** |
| `div` 64 位元 100 / 7 | 2.99 ns | 3.34 ns |
| `div` 64 位元 2⁶³ / 3（商 63 位元） | 2.99 ns | **11.43 ns** |
| `div` 64 位元 2⁶³ / 2⁶² （商 2） | 2.99 ns | 3.07 ns |

- **除法比乘法慢很多**：P-core 上 `div` 是 `imul` 的 4–5 倍。P-core 約 4.7 GHz，`imul` ≈ 3 個 cycle，32 位元 `div` ≈ 12 個、64 位元 ≈ 14 個 cycle。這就是影片 [02:01] 說的「除法本來就很慢」。
- **P-core**：時間跟數字無關，只跟 32／64 位元有關。
- **E-core**：時間**跟商有幾個 bit 有關**：商 2 或很小時約 3 ns，商 63 位元時 11.4 ns，差將近 4 倍。這很像本講「一輪算一個（或幾個）商的 bit」的迭代式除法器，而且商很小時可以提早結束。E-core 的除法器實際用什麼演算法、一輪算幾個 bit，Intel 沒有公開，**待補**。

## 16. 一頁速查表

| 主題 | 重點 |
|---|---|
| 只做正數 | 負數先轉正、除完再依慣例調整符號 |
| 式子 | N = D·Q + R |
| 性質 | 0 ≤ R < D；Q 是最大的 |
| 縮小問題 | N′ = N − D·Qₙ·2ⁿ⁻¹ → 商少一位 |
| 決定 Qₙ | 猜 1：N − D·2ⁿ⁻¹ ≥ 0 就是 1，否則 0 |
| 13 / 3 | 0100 餘 1 |
| 暫存器 | D 除數；U（33 位元）一開始 0、最後餘數；V 一開始被除數、最後商 |
| 每一輪 | UV 左移；U − D |
| Restoring | 負的就加回去；每輪最多 2 次 |
| Non-restoring | 正的減、負的加；最後 U < 0 再加一次 D；每輪 1 次 |
| 正確性 | 每次商 bit 是 1，兩種演算法的狀態合併 |
| 複雜度 | 都是 O(n log n) |
| 7 / 3 | 商 0010、餘 0001 |
| 實測 | 照課本暫存器跑出同樣的表；10 萬組隨機全對；non-restoring 少 42% 加減法；P-core div ≈ 12–14 cycle、E-core 依商的長度 3–11 ns |

## 附：本講一句話總結

> **整數除法只處理正數（負數先轉正、最後再調符號），要找滿足 N = D·Q + R、0 ≤ R < D 的最大 Q；把商的最高位拆出來，N − D·Qₙ·2ⁿ⁻¹ = D·Q′ + R 跟原式結構一樣，所以只要一位一位決定商（先猜 1，N − D·2ⁿ⁻¹ ≥ 0 就是 1，否則是 0），問題就一輪縮小一位；硬體用除數 D、33 位元的 U（最後是餘數）和 V（一開始放被除數、最後是商），每一輪把 UV 左移、U 減 D，restoring 在減成負的時候把 D 加回去，non-restoring 則讓它負著、下一輪改成加 D，最後 U 若仍為負再加一次，因為每次商的 bit 是 1 時兩者的狀態會合併所以結果一樣，但 non-restoring 每一輪只做一次加減，兩者都是 O(n log n)。本機實測：照課本的暫存器重跑 7 / 3 得到一模一樣的表，10 萬組隨機除法全對，non-restoring 少做 42% 的加減法；真的 div 指令在 P-core 上要 12–14 個 cycle（imul 的 4–5 倍），在 E-core 上時間還會隨商的長度變化。**
