## 2. 為什麼需要一個新的 ISA

[04:46]–[09:04]　課本 Ch6 開頭（p.225–226）

- 【口頭】從 2000 年開始，大家都覺得 **ISA 設計已經是成熟的領域**，沒必要再設計新的：x86 是市場領導者、有所有 CISC 的功能；RISC 有 PowerPC、UltraSPARC、ARM。
- 但結果發現，**技術上**和**法律上**都需要一個新的 ISA。

**法律（授權）的理由**：

- 例如 ARM 的 ISA 由 ARM 授權給其他公司，某種程度上是**專有的**產品。
- 很多專有 ISA **不允許**廠商在不付授權費的情況下為它做處理器。「看你問誰，很多人會說授權費相當高。」
- 需要一個**開放的** ISA：任何人都可以為它做處理器。

**技術的理由**：

1. 這些年學到了很多東西，應該把這些經驗放進新的 ISA。
2. 出現很多新的加速器（accelerator），需要 ISA 的支援，例如當作擴充：**向量**擴充、**密碼學**擴充、**AI／ML** 擴充。
3. 所以想要一個**模組化**的 ISA：一組基本指令，再依需求加上「附加模組」。
4. 要能用在所有裝置：從小型的 32 位元（甚至 16 位元）裝置，到 64 位元、128 位元，也要能用在伺服器。

**生態系統（ecosystem）的問題**：

- 一個 ISA 需要一大群開發者：binutils（assembler、objdump、靜態／動態連結）、compiler，還要有人把 Linux 移植過去。工作量很大，所以沒人想投資全新的東西。
- 【口頭】到 1990 年代末，**設計一顆處理器核心已經不是什麼尖端科技**：大學的研究團隊、成熟的開發者都做得到，也有錢去製造。他們需要自己的 ISA，主要是為了能接觸到**開發者社群**和生態系統。

【課本補充】課本的分析：

- 2010 年左右，設計一個簡單的 RISC 處理器已經很容易：架構很成熟、EDA 工具成熟、業餘設計者也有足夠的運算能力。很多 fabless 公司（沒有晶圓廠、只做設計的公司）在世界各地出現。
- 晶圓廠擴產，在舊製程上也能做出相當高效能的晶片，**製造變得便宜**。
- 當時普遍認為新的核心應該用 **RISC**：x86 這種 CISC 有 1000 多條指令，**解碼器**很複雜、很耗電，不適合低功耗的嵌入式系統。
- 用 ARM、MIPS 現有的設計可以沿用它們的工具鏈，但**授權限制和費用**讓很多開發者放棄。所以要從零建立一個新 ISA 和整個生態系統，而且授權要非常寬鬆，把門檻降到最低。

## 4. Base ISA 與擴充

[09:21]–[13:36]　課本 §6.1.1、Table 6.1（p.226–227）

- RISC-V **不是一個 ISA，而是一組 ISA**：有不同的變體、擴充、版本。【口頭】「這和我們之前看到的單一、整塊的 ISA 不一樣。」

**Base ISA**：

| 名稱 | 說明 |
|---|---|
| **RV32** | 32 位元 ISA（最成熟） |
| RV32E | 32 位元，嵌入式版本 |
| RV64 | 64 位元 ISA（伺服器等級） |
| RV64E | 64 位元，嵌入式版本（高效能嵌入式系統） |
| RV128 | 128 位元 ISA |

- RV = RISC-V；32／64／128 是**位元寬度**（暫存器寬度和記憶體位址大小）。
- 影片說截至 2024 年，RV64 和 RV128 還不太成熟，RV32 很成熟。
- ⚠️ 影片 [10:51] 說 RV128「主要是給 SIMD 那類的指令，想把很多資料塞進同一個記憶體 word」。這個說法不太對：RV128 是 **128 位元的位址空間和暫存器**（給未來超大記憶體的機器），SIMD 是 **V（向量）擴充**的工作。課本只說 128 是位元寬度。

**擴充**（用字母表示）：

| 字母 | 說明 |
|---|---|
| E | 嵌入式版本（暫存器減半） |
| **I** | 基本**整數**指令（整數和 load／store）。幾乎一定有，所以常常不寫 |
| **M** | 整數**乘法／除法** |
| **A** | **原子**（atomic）指令 |
| F | 單精度浮點數 |
| D | 雙精度浮點數 |
| V | 向量指令 |

- **M**：乘除法**不在**基本 ISA 裡。【課本補充】理由是要能做出**非常低階、低功耗**、不需要這些指令的實作。
- **A**（[11:59]）：就算只跑單執行緒的程式，只要有 Linux kernel，就有多個 process 同時在跑，kernel 內部需要原子指令。所以 A 某種程度上也算標準。
- 【口頭】所以 **I、M、A 算是標準的**。很多程式不用浮點數，就不需要 F、D；不做矩陣乘法或 AI／ML 就不需要 V。
- 組合起來寫：例如 **RV32IMA** = 整數 ＋ 乘除法 ＋ 原子指令。
- 【課本補充】截至 2024 年，擴充的數量已經很多（大約 20～30 個），大部分是浮點、原子操作、密碼學、memory barrier 等。

## 5. 版本號、G 與 Z 系列

[13:36]–[16:45]　課本 p.227

**版本號**：規格一直在改，所以每個擴充可以有版本號：

```
RV32I1p3   →  I 擴充的主版本 1、次版本 3（p 是分隔符號）
```

- RISC-V 聯盟會定期發布新的規格，有小的改動。硬體設計者和寫軟體堆疊的人要跟著更新。大部分改動是**向下相容**的：原本能跑的東西還是能跑。

**G**（general-purpose）：把常用的擴充**打包**。

- G = 基本整數指令 ＋ 額外的整數指令（M）＋ 浮點指令（F、D）＋ 原子／同步指令（A）……
- **RV32G** 是很多處理器最常用的格式。
- 【課本補充】「就像機票加飯店的套裝行程。」G 被認為是多核心環境裡必備的一組指令。

**Z 系列**：

- 【口頭】「只有 26 個字母，用完了怎麼辦？」所以有 **Z** 開頭的擴充：Z ＋ 描述擴充的字。
- 例：**Zfa** = 額外的浮點指令。
- 這讓 ISA 很豐富，但**沒有一個實作需要支援所有擴充**：只要支援標準的和自己需要的。

## 6. 指令長度、E 版本與 C 版本

[16:45]–[19:46]　課本 p.227–228

- **指令寬度固定是 32 位元**，**就算資料路徑是 64 或 128 位元**也一樣（暫存器和位址變寬，指令不變）。為了相容、好用。
- 【課本補充】「這讓編譯和解碼都很簡單。」三種格式（32／64／128）之間唯一不同的是：支援的指令集合、暫存器寬度、記憶體位址的大小。

**E（embedded）版本**：

- **不縮小指令寬度**，還是 32 位元。
- 【課本補充】E 是把暫存器**減少 50%**：RV32E 只有 **16 個**整數暫存器（一般是 32 個）。和 ARM Thumb 不同，指令大小不變，所以 compiler 和處理器的設計比較簡單。

**C（compressed）版本**：真的把指令變短

- 指令寬度 32 → **16 位元**
- 只能存取 **8 個**暫存器（不是全部 32 個）
- 支援的指令和 opcode 有限
- 立即值更小（一般 RISC-V 是 12 或 20 位元）
- 給**超小型、超低功耗**的處理器用。
- 【課本補充】每一條 16 位元的壓縮指令都對應一條 32 位元的 RV32 指令。好處：程式碼變小、i-cache 用得更好、取指令和解碼更省電。最常見的組合是 **RV32GC**（general-purpose ＋ compressed）。§13.4 實測。

**更長的指令**（[17:57]）：

- 【口頭】有人在討論 **48 位元或 64 位元**的指令，RISC-V 網站上有一些正在制定中的標準。「到 2024 年 12 月 26 日為止還沒完全批准。」
- 【課本補充】指令長度必須是 **16 位元的倍數**。向量、位元操作、密碼學等擴充需要更長的指令。指令格式裡有位元表示指令是否長於 32 位元；目前的標準（v20240411）理論上可以支援到 **176 位元**。

【課本補充】**Important Point 7**：RISC-V 是 RISC ISA，但不像 SimpleRisc 那麼小：有 base、一堆擴充、48／64 位元指令、16 位元壓縮格式……「聽起來比較像 CISC」。但它仍然很規律：只有少數幾種指令格式、大部分指令是 32 位元、base ISA 非常「RISC」。「設計一個要支援從嵌入式處理器到超級電腦的現代 ISA，這種取捨是無可避免的。」RISC 那一方要規律和優雅，CISC 那一方要更多指令和複雜度。

## 7. 32 個整數暫存器

[19:46]–[27:29]　課本 §6.1.2、Table 6.2（p.228–229）

- **32 個**暫存器，每個 32 位元（RV32）。
- 有兩種名字：**x0～x31**，或 **mnemonic**（助憶名稱，**建議用這個**）。
  - 【口頭】組合語言有非常嚴格的**暫存器使用慣例**，assembler、compiler 都遵守。mnemonic 代表了這個慣例，用它就自然會遵守，知道什麼時候該用哪個暫存器。

| 暫存器 | Mnemonic | 說明 |
|---|---|---|
| **x0** | **zero** | **永遠是 0**（hardwired） |
| x1 | ra | return address |
| x2 | sp | stack pointer |
| x3 | gp | global pointer |
| x4 | tp | thread pointer（thread-local storage） |
| x5–7 | t0–t2 | 暫存（temporary） |
| x8 | s0／fp | saved register／frame pointer |
| x9 | s1 | saved register |
| x10–11 | a0–a1 | 函式參數／**回傳值** |
| x12–17 | a2–a7 | 函式參數 |
| x18–27 | s2–s11 | saved register |
| x28–31 | t3–t6 | 暫存 |

- **x0（zero）**：【口頭】「這是 RISC-V 才有的新概念，我們之前沒看過。」它有很多用途，例如搬移數值（§8）。
- **gp**（global pointer）：指向**全域變數**存放的區域。所有全域變數和 static 變數放在一個地方，gp 指向那裡。對 OS 這種很大、常要存取某個全域表格的程式特別有用。
  - ⚠️ 老師一開始說 gp「像是 activation window 的底部」，馬上更正：gp 指向**全域變數的區域**。
- **tp**（thread pointer）：指向一個 thread 存放**私有變數**的區域。
- **t0–t6**：在函式內部用的暫存暫存器，**不保存**（7 個）。
- **s0–s11**：**跨函式呼叫保存**（12 個）。s0 也可以當 **frame pointer**，指向目前的 frame（activation block）的開頭。
- **a0–a7**：參數（8 個）。**a0、a1 也放回傳值**。為什麼有兩個？例如在 32 位元 ISA 想回傳 64 位元（乘法的結果常常是 64 位元）。
- 【課本補充】**s 是 callee saved**（跨呼叫保留），**t 是 caller saved**（不保留）。ISA 本身**沒有規定**呼叫慣例，但這個慣例已經被大家採用。

**PC**：

- 有一個專門的 PC 暫存器，**不能直接操作**，但可以**間接**存取。
- 【課本補充】課本說「有一個專門的 pc 暫存器**公開**了程式計數器」。

**Endian**：

- 影片說 RISC-V 是 **bi-endian**，「這是它的另一個優點」。
- 【課本補充】課本講得更精確：RISC-V 一開始是 **little endian**，現在**也支援** big endian 和 bi-endian 模式。

**暫存器寬度**（[26:33]）：RV32 是 32 位元、RV64 是 64 位元、RV128 是 128 位元。【口頭】就像 x86 隨資料路徑變寬而把暫存器加寬。PC 也是一樣。

## 8. 沒有 mov：用 zero 暫存器

[27:29]–[30:44]　課本 §6.2.1、Table 6.3（p.229）

| 語意 | 例子 | 解釋 |
|---|---|---|
| `addi rd, rs1, imm` | `addi x1, x0, 5` | x1 ← 0 + 5 |
| `add rd, rs1, rs2` | `add x1, x2, x3` | x1 ← x2 + x3 |

- **addi** = add immediate。格式和其他 RISC 一樣：rd 是目的地、rs1 是第一個來源、imm 是立即值。
- **把立即值加到 x0（= 0）再放到暫存器，就等於把立即值搬進暫存器**。
- 【口頭】「所以**不需要另外的 mov 指令**。所有東西都很聰明地摺疊進同一條 addi 指令裡。」寫 x0 或寫 zero 都可以。
- 不用 x0 的話，就是一般的「暫存器加上立即值」。
- **暫存器之間搬移**：`add x1, x2, x0`（或 `add x1, x0, x2`）就是 x1 ← x2。
- 【口頭】所以有一個很漂亮的技巧：第一個來源是 zero 時，就等於 mov 立即值或 mov 暫存器。
- **也不需要 subi**：因為立即值是**有號數**，加一個負數就是減法。

§13.2 實測：assembler 提供 `mv`、`nop` 這些**別名**，實際上都編成 addi。

## 9. 載入 32 位元常數：lui 與 li

[30:44]–[38:45]　課本 Table 6.4、Example 91–92（p.230）

- addi 的立即值只有 **12 位元**（有號：−2048 ～ 2047），因為指令裡還要放其他暫存器的編號。
  - ⚠️ 逐字稿 [51:29] 把範圍聽成「−248 到 +247」「496 個數」，應該是 −2048 ～ +2047，共 4096 個數。

| 語意 | 例子 | 解釋 |
|---|---|---|
| `lui rd, imm` | `lui x1, 5` | x1 ← 5 << 12 |
| `li rd, imm`（pseudo） | `li x1, 0xABCD1234` | x1 ← 0xABCD1234 |

**lui**（load upper immediate）：

- 載入一個 **20 位元**的立即值，放到暫存器的**高 20 位**；低 12 位是 0。
- 為什麼是高 20 位？因為低 12 位已經可以用 addi 這些指令處理了。
- 例：`lui x15, 5`：5 = `101`，放在高 20 位，等於 **5 左移 12 位**。
- 所以載入 32 位元常數**不能用一條指令**，要兩條：lui 放高 20 位、addi 放低 12 位。
  - ⚠️ 影片 [33:05] 口誤說「用 add 處理**低 20 位**」，應該是低 **12** 位。

**li**（load immediate）是 **pseudo instruction**（假指令）：

- Pseudo instruction 像是給 assembler 的指示詞，實際上會被換成**好幾條**機器指令。li 會變成 lui ＋ addi。
- 【口頭】寫組合語言時，用 assembler 提供的 pseudo instruction 讓生活輕鬆一點是好事，但要記得它會被換成多條機器指令。

**Example 91**：409932 + 409823

```
.main:
	lui  t0, 100          # t0 = 4096 * 100 = 409600
	addi t0, t0, 332      # t0 = t0 + 332
	lui  t1, 100          # t1 = 4096 * 100 = 409600
	addi t1, t1, 223      # t1 = t1 + 223
	add  t2, t0, t1       # t2 = t0 + t1
```

- 【口頭】4096 = 2¹²，「這時應該要想到：低 12 位全是 0，接著一個 1」。lui 100 就是 100 × 4096 = 409600，再加 332 就是 409932。

**Example 92**：用 li

```
.main:
	li  t0, 409932
	li  t1, 409823
	add t2, t0, t1
```

- 【口頭】注意第一個表格用 x1、x2，程式碼用 t0 這種 mnemonic。「兩種都可以，但程式碼裡應該用 mnemonic，這樣自然會遵守暫存器使用慣例。」

⚠️ li 拆成 lui ＋ addi 有一個陷阱，影片和課本都沒講：**addi 的立即值會 sign-extend**。如果低 12 位 ≥ 0x800（最高位是 1），addi 實際上加的是**負數**，所以 lui 要**多加 1** 來補償。§13.2 實測：`li t3, 0x12345FFF` 被 assembler 換成 `lui t3, 0x12346` ＋ `addi t3, t3, -1`。另外，**小的常數只要一條** addi（`li t4, -5` → `addi t4, zero, -5`）。課本說「assembler 把 li 換成兩條指令：addi 和 lui」，順序是 lui 在前，而且不一定是兩條。

## 10. add、addi、sub

[38:45]–[41:30]　課本 Table 6.5、Example 93–94（p.230–231）

| 語意 | 例子 | 解釋 |
|---|---|---|
| `add rd, rs1, rs2` | `add x1, x2, x3` | x1 ← x2 + x3 |
| `addi rd, rs1, imm` | `addi x1, x2, 5` | x1 ← x2 + 5 |
| `sub rd, rs1, rs2` | `sub x1, x2, x3` | x1 ← x2 − x3 |

- 沒有 subi（立即值有號），但 **sub 還是需要**：兩個暫存器相減。

**Example 93**：4 + 5 − 19

```
	addi t0, zero, 4      # load 4 into t0
	addi t1, zero, 5      # load 5 into t1
	add  t2, t0, t1       # t2 = t0 + t1
	addi t2, t2, -19      # subtract 19 from t2
```

**Example 94**：交換 x1 和 x2（「經典問題」）

```

	add x1, x0, x2        # x1 = x2
	add x2, x0, x3        # x2 = x3 (old x1)
```

- 【口頭】zero 暫存器又出場了，「它好像一直都在扮演重要角色」。

## 11. 乘除法：mul、mulh、div、rem

[41:30]–[54:16]　課本 §6.2.3、Table 6.6、Example 95–97（p.231–233）

| 語意 | 例子 | 解釋 |
|---|---|---|
| `mul rd, rs1, rs2` | `mul x1, x2, x3` | x1 ← x2 × x3（**低 32 位**） |
| `mulh rd, rs1, rs2` | | **有號** × 有號的**高 32 位** |
| `mulhu rd, rs1, rs2` | | **無號** × 無號的高 32 位 |
| `div rd, rs1, rs2` | `div x1, x2, x3` | x1 ← x2 / x3（商） |
| `rem rd, rs1, rs2` | `rem x1, x2, x3` | x1 ← x2 除以 x3 的餘數 |

- 屬於 **M 擴充**，不在 base ISA 裡（但在 general 指令集 G 裡）。
- H = high（高位），U = unsigned。

**乘法要 64 位元**：

- 32 位元 × 32 位元的乘積需要 64 位元。mul 只放低 32 位；要高 32 位就用 mulh 或 mulhu。
- 【口頭】「要得到 64 位元的結果，要下兩條指令，聽起來不公平：硬體其實已經算出 64 位元了，卻要做兩次乘法。」
- **RISC-V 規格的解法**：硬體應該**動態辨認**出 mul 和 mulh 是兩條連續、乘同樣兩個數的指令，把它們**融合**（fuse）成**一次**乘法，結果寫進兩個暫存器。這樣省下一次乘法的時間和電力。
- 這種技術一般叫做 **macro-op fusion**（影片和課本都沒用這個名詞，但描述的就是它）。

**除法的捨入規則**（[46:02]）：

- 正數沒問題：4 ÷ 3 → 商 1、餘 1。
- 有一個是負數時，**餘數的符號要怎麼定**？
- RISC-V 的規則：**往 0 捨入**（round toward zero），也就是**餘數的符號和被除數一樣**。

| 運算 | 兩種可能 | 選（往 0） | 商 | 餘數 |
|---|---|---|---|---|
| 4 ÷ 3 | | | 1 | 1 |
| 4 ÷ (−3) | (−3)(−1) + 1 或 (−3)(−2) − 2 | −1 比較接近 0 | −1 | **1** |
| (−4) ÷ 3 | 3(−1) − 1 或 3(−2) + 2 | −1 | −1 | **−1** |
| (−4) ÷ (−3) | (−3)(1) − 1 或 (−3)(2) + 2 | 1 | 1 | **−1** |

- 餘數的符號：+、+、−、−，和被除數完全一致。
- **div 和 rem 也可以融合**：連續的 div 和 rem、同樣的被除數和除數，硬體做一次除法，商和餘數寫進兩個暫存器。
- 【課本補充】課本說這是「**故意設計不足**」（deliberately under-designed）的例子：ISA 不提供一條寫兩個暫存器的指令，而是要程式設計師或 compiler 連續下兩條，由**硬體**負責辨認和融合。把效率的責任交給硬體，換取 ISA 的簡單。

**Example 95**：3 × (−17)

```
	addi t1, zero, 3      # t1 = 3
	addi t2, zero, -17    # t2 = -17
	mul  t3, t1, t2       # t3 = t1 * t2
```

- ⚠️ 影片口頭說「3 乘以 −7」，但程式碼是 −17（和課本一樣）。

**Example 96**：12³ + 1

```
	addi t1, zero, 1      # t1 = 1
	addi t2, zero, 12     # t2 = 12
	mul  t3, t2, t2       # t3 = 12 * 12
	mul  t3, t3, t2       # t3 = 12 * 12 * 12
	add  t4, t3, t1       # 12^3 + 1
```

- 【口頭】投影片上多了一行把 12 載入 T3 的指令，老師說「事後看來這行不需要，我把它刪掉」。

**Example 97**：−50 ÷ 3

```
	addi t0, zero, -50    # t0 = -50
	addi t1, zero, 3      # t1 = 3
	div  t2, t0, t1       # quotient in t2
	rem  t3, t0, t1       # remainder in t3
```

- 【口頭】用 mnemonic 的好處：會遵守暫存器使用慣例，不會亂用。
- 硬體看到連續的 div、rem，會動態融合成一次除法。§13.1 實測：t2 = −16、t3 = −2。

## 12. 邏輯與位移指令

[54:16]–[56:45]　課本 §6.2.4、Table 6.7、Example 98–100（p.233–235）

| 語意 | 例子 | 解釋 |
|---|---|---|
| `and`／`andi` | `and x1, x2, x3`／`andi x1, x2, 6` | AND |
| `or`／`ori` | `or x1, x2, x3`／`ori x1, x2, 9` | OR |
| `xor`／`xori` | `xor x1, x2, x3`／`xori x1, x2, 7` | XOR |
| `sll`／`slli` | `sll x1, x2, x3`／`slli x1, x2, 3` | shift left logical |
| `srl`／`srli` | `srl x1, x2, x3`／`srli x1, x2, 3` | shift right **logical** |
| `sra`／`srai` | `sra x1, x2, x3`／`srai x1, x2, 3` | shift right **arithmetic** |

- 格式都和 add 一樣：`rd, rs1, rs2` 或 `rd, rs1, imm`（加 i 後綴）。
- 和其他 ISA 一樣，**沒有算術左移**。
- ⚠️ **符號的慣例和前面不一樣**：課本 Table 6.7 把 srl 寫成 `x2 >> x3`、sra 寫成 `x2 >>> x3`（已對照 PDF 原頁）。但第 7 支影片（SimpleRisc）說 `>>>` 是**邏輯**右移（「這個寫法來自 Java」），Java 裡 `>>` 才是算術右移。兩邊的符號剛好相反；以指令名稱（srl = 邏輯、sra = 算術）為準就不會錯。

**Example 98**：A OR B（A = 4、B = 1）

```
	addi t1, zero, 4      # t1 = 4
	ori  t2, t1, 1        # bitwise OR of 4 and 1
```

**Example 100**：t1 = t2 + t3 × 4

```
	addi t3, zero, 5      # t3 = 5
	addi t2, zero, 7      # t2 = 7
	slli t4, t3, 2        # t4 = t3 * 4
	add  t1, t2, t4       # t1 = t2 + t3 * 4
```

- 【口頭】一看到「× 4」就想到可以用左移。「這個故事的教訓：**乘法很慢、左移快得多**；只要是 2 的冪次，永遠優先用位移。」

【課本補充】Example 99：50 / 4 → `addi t0, zero, 50` ＋ `srai t1, t0, 2`。

**本講總結**（[56:27]）：

- 為什麼需要 RISC-V：技術上（變體、擴充）和**法律上**（開放、沒有授權費），目標是**開放硬體**。
- 整數指令、暫存器，以及 **zero 暫存器**的重要角色：「你不需要 mov 指令，只需要 add。」

## 13. 【實測】

本機：Intel i7-13650HX、Ubuntu、kernel 6.5.0。用 LLVM 14 的 `llvm-mc` 把 RISC-V 組合語言組譯成 **RV32IM** 機器碼，`ld.lld` 連結到位址 0、`llvm-objcopy` 輸出原始 byte（`experiments/riscv/build.sh`），再用自己寫的 Python 模擬器 `experiments/riscv/rv32sim.py`（約 90 行，解碼 R／I／S／B／U／J 六種格式，實作 RV32I ＋ M）**執行機器碼**。本講的程式在 `experiments/riscv/l15/`。

### 13.1 課本的例子都跑出正確答案

```
$ ../build.sh bigadd.s && python3 ../rv32sim.py bigadd.bin
bigadd.bin: 6 instructions; t0=409932 t1=409823 t2=819755
$ ../build.sh li.s && python3 ../rv32sim.py li.bin

$ ../build.sh arith.s && python3 ../rv32sim.py arith.bin
arith.bin: 10 instructions; t0=4 t1=5 t2=-10 a0=20 a1=10 a2=10
$ ../build.sh muldiv.s && python3 ../rv32sim.py muldiv.bin
muldiv.bin: 16 instructions; t1=3 t2=-17 s0=-50 s1=3 s2=-16 s3=-2 s4=4 s5=-3 s6=-1 s7=1 s8=2147483647 s9=1073741823 s10=1 t3=-51
$ ../build.sh cube.s && python3 ../rv32sim.py cube.bin
cube.bin: 12 instructions; t1=1 t2=12 a0=4 a1=5 a2=3 a3=7 a4=28 a5=31 t3=1728 t4=1729
```

- Example 91／92：409932 + 409823 = **819755**。
- Example 93：4 + 5 − 19 = **−10**。
- Example 94（交換）：a0 = 10、a1 = 20 交換後 a0 = 20、a1 = 10。
- Example 95：3 × (−17) = **−51**。
- Example 97：−50 ÷ 3 → 商 **−16**、餘 **−2**（往 0 捨入，餘數和被除數同號）。
- 4 ÷ (−3) → 商 **−1**、餘 **1**：和 §11 表格一樣。
- **mulh**：(2³¹ − 1)² = 2⁶² − 2³² + 1 = `0x3FFFFFFF_00000001`：mulh 給高 32 位 **1073741823**（0x3FFFFFFF），mul 給低 32 位 **1**。
- Example 96：12³ + 1 = **1729**（就是第 7 支講過的 Ramanujan number）。
- Example 98：4 OR 1 = **5**；Example 100：3 + 7 × 4 = **31**。

### 13.2 li、mv、nop 是 pseudo instruction

```
$ llvm-objdump -d -M no-aliases li.o
       0:      	lui	t0, 100
       4:      	addi	t0, t0, 332
       8:      	lui	t1, 100
       c:      	addi	t1, t1, 223
      10:      	add	t2, t0, t1
      14:      	lui	t3, 74566         ← 74566 = 0x12346（多了 1！）
      18:      	addi	t3, t3, -1        ← 加 −1
      1c:      	addi	t4, zero, -5      ← 小常數只要一條
      20:      	ecall
```

- `li t0, 409932` 被 assembler 換成 `lui t0, 100` ＋ `addi t0, t0, 332`，**和課本 Example 91 手寫的一模一樣**。
- `li t3, 0x12345FFF`：低 12 位是 `0xFFF`，當成有號數是 **−1**。所以 assembler 用 `lui 0x12346`（多 1）再 `addi −1`：0x12346000 − 1 = 0x12345FFF。
- `li t4, −5`：在 12 位元範圍內，**一條 addi 就夠**。

`-M no-aliases` 讓反組譯器顯示真正的指令。不加的話，`addi rd, rs, 0` 會顯示成 `mv rd, rs`，`addi zero, zero, 0` 會顯示成 `nop`：這些都是 addi 的別名，印證了「RISC-V 不需要 mov」。

### 13.3 x0 寫不進去

模擬器照規格實作：寫入 x0 的結果一律丟掉（`if rd: self.x[rd] = r`），所以 `addi zero, zero, 5` 之後 zero 還是 0。這就是「hardwired to zero」。

### 13.4 C 擴充：16 位元的指令

```
$ llvm-mc -triple=riscv32 -mattr=+c -show-encoding <<< 'addi a0, a0, 1'
	addi	a0, a0, 1    # encoding: [0x05,0x05]
$ llvm-mc -triple=riscv32 -show-encoding <<< 'addi a0, a0, 1'
	addi	a0, a0, 1    # encoding: [0x13,0x05,0x15,0x00]
```

- 同一條 `addi a0, a0, 1`：開了 C 擴充只要 **2 byte**（`c.addi`），沒開要 **4 byte**。
- 壓縮指令和 32 位元指令一一對應，assembler 可以自動挑短的。

## 附：本講一句話總結

> **RISC-V 是 2010 年從 Berkeley 開始、2015 年以 Creative Commons 授權公開、現由 RISC-V Foundation 維護的開放 RISC ISA，出現的原因既是技術上（吸收多年經驗、支援向量／密碼學／AI 等加速器、從 IoT 到伺服器都要能用）也是法律上（ARM 等專有 ISA 要授權費）；它不是單一 ISA，而是 RV32／RV64／RV128 加上 E（16 個暫存器）、I、M、A、F、D、V 等擴充，可以打包成 G、用 Z 系列無限擴充、有版本號（RV32I1p3），指令一律 32 位元（C 擴充有 16 位元的壓縮版，實測同一條 addi 從 4 byte 變 2 byte）。它有 32 個暫存器，x0（zero）永遠是 0，所以沒有 mov（addi rd, zero, imm）也沒有 subi（立即值有號）；addi 的立即值只有 12 位元，32 位元常數要用 lui（放高 20 位）加 addi，或用 pseudo instruction li（實測低 12 位 ≥ 0x800 時 assembler 會讓 lui 多加 1）。乘除法在 M 擴充：mul 給低 32 位、mulh／mulhu 給高 32 位，div／rem 往 0 捨入、餘數和被除數同號，而且硬體應該把相鄰的 mul＋mulh、div＋rem 融合成一次運算，這是「ISA 故意設計不足、把效率交給硬體」的例子；邏輯和位移指令（and、or、xor、sll、srl、sra 和 i 版本）格式都和 add 一樣。**
