## 0. 本講地圖

```
CLA Stage II：沿著 (G,P) 樹把正確的 carry 送到每一個小 adder → O(log n)
乘法：multiplicand × multiplier = 部分和（partial sum）的總和
  iterative multiplier：U（33 位元）＋ V（32 位元），每步看 V 的 LSB，加 N 再把 UV 右移
     最後一步如果 MSB = 1 就「減」N（因為 MSB 的權重是 −2ⁿ⁻¹）→ O(n log n)
  Booth：看（目前位元, 前一位元）：01 → 不動、10 → 減 N、01 → 加 N
     一串連續的 1 只要一次減、一次加 → 最壞還是 O(n log n)，但實際上常常比較快
```

## 1. Carry lookahead adder 的 Stage II

[00:42]–[16:18]　課本 Figure 8.9（p.317–318）

**Stage I 回顧**：用一棵樹算出越來越大的塊的 (G,P)：2 個位元對、4 個、8 個、16 個、32 個。約 log₂ n 層，每層常數時間（一個 AND，或一個 OR ＋ 一個 AND），所以 O(log n)。這時候**還沒做加法**。

**Stage II 的目標**：算出**每一個小 adder 的 carry in**。

- Level 0 是一排 **2 位元的 ripple carry adder**（32 位元就有 16 個）。
- 擋住它們做加法的唯一問題，是**不知道 carry in**。例：第 29–30 位元對、第 31–32 位元對的 carry in 是多少？
- 只要知道所有的 carry in，就能在 **O(1)** 時間做完加法。
- 結果其實可以有 33 位元（最後的 carry），圖上為了簡單沒畫出來。

**每個 (G,P) 塊**負責一段範圍 (r2, r1)。知道 carry in，一條式子就能算出 carry out：

```
C_out = G + P · C_in      （一個 OR ＋ 一個 AND，常數時間）
```

**怎麼傳**（[05:22]）：

- t = 0：把 **C_in¹**（第一位的 carry in，通常是 0）接到**最右邊的那些塊**（範圍從 1 開始的）：(2-1)、(4-1)、(8-1)、(16-1)、(32-1)。
- 假設每個塊算 C_out 要 1 個時間單位。t = 1 時，這些塊都算好了：知道第 2、4、8、16、32 位元對**之後**的 carry。
- **連接規則**：範圍 (r2, r1) 的塊，接到**所有**範圍形如 (r3, r2+1) 的塊（從 r2 + 1 開始的）；為了少用線，只接到**比較低的層**。
  - 例：(16-1) 算好之後，送給 (17-18)、(17-20)、(17-24)、(17-32)。
- t = 2：(24-17) 算好，送給 (28-25)……一層一層往下。
- 每個時間單位就**往下走一層**，像一道波前（front）往左推進。

**例**（[11:45]）：

| 位元對 | carry in 從哪來 | 什麼時候拿到 |
|---|---|---|
| 17–18 | (16-1) | t = 1 |
| 23–24 | (16-1) → (20-17) → (22-21) | t = 3 |
| 31–32 | (16-1) → (24-17) → (28-25) → (30-29) | t = 4 |

- 最多 **5 步**（32 位元），每一個 2 位元 adder 都會拿到 carry in。
- ⚠️ 投影片寫「從**最左邊**的塊開始」，老師口頭更正：「應該是最右邊的，看你從哪個方向看；盯著螢幕的話是最右邊。」

**時間**：carry 每個時間單位往下一層，共 O(log n) 層，所以 Stage II 是 **O(log n)**；最後的加法是常數時間。整個 carry lookahead adder 是 **O(log n)**，「而且這也是商用電路裡用的加法器」。

## 2. 三種加法器總結

[16:18]–[19:04]

| 加法器 | 時間 | 想法 |
|---|---|---|
| Ripple carry | O(n) | carry 一位一位傳，最壞要走 n 步 |
| Carry select | O(√n) | 比較大的塊；Stage 1 同時算 carry in = 0 和 1 的結果；k + n/k，k = √n |
| Carry lookahead | **O(log n)** | 先往下算 (G,P) 樹，再往回算 carry，最後用小 ripple adder 加 |

- 【口頭】carry lookahead「非常快，最快的，商用處理器也用它」。

## 3. 小學的乘法，換成二進位

[19:04]–[26:28]　課本 §8.2.1、Definition 56（p.318–319）

【口頭】「回到小學二年級，看看乘法怎麼做的。」

13 × 9 = 117，用二進位（無號數）：

```
        1 1 0 1     ← multiplicand（被乘數）= 13
      × 1 0 0 1     ← multiplier（乘數）= 9
      ---------
        1 1 0 1     ← 部分和（乘數第 1 位是 1）
      0 0 0 0       ←（第 2 位是 0）
    0 0 0 0         ←（第 3 位是 0）
  1 1 0 1           ←（第 4 位是 1）
  -------------
  1 1 1 0 1 0 1     = 117
```

- **multiplicand**（被乘數）：寫在上面的（傳統的寫法）；**multiplier**（乘數）：寫在下面的；**product**：乘積。兩者其實是對稱的。
- 從乘數的 **LSB** 往左看：是 1 就寫下被乘數，是 0 就寫 0；**每一列往左移一位**（等於乘 2）。
- 把它們加起來。和十進位的乘法**完全一樣**。
- 64 + 32 + 16 + 4 + 1 = **117**。

> **Definition 56**：
> - **Partial sum（部分和）**：被乘數左移若干位，或者是 0。
> - **Partial product（部分積）**：一組部分和的總和。

- **乘積需要幾位元**：m 位元乘以 n 位元（無號），最大是 (2ᵐ − 1)(2ⁿ − 1) < 2ᵐ⁺ⁿ，所以需要 **m + n** 位元。

## 4. 有號數乘法要 64 位元時的問題

[26:28]–[30:28]

- 要做：兩個 **32 位元有號數**相乘，產生 **64 位元**的結果。【口頭】「無號數一直都很簡單，我們故意讓生活複雜一點。」
- [第 4 支](lecture04_note.md#7-加法減法乘法) 證明過：只要**沒有 overflow**、結果也存成 32 位元，有號數相乘 = 把兩個 2's complement 表示法當成**無號數**相乘，取低 32 位。
  - 例（4 位元）：2 × (−3) → F(2) × F(−3) = 2 × 13 = 26，丟掉第 5 位 → 26 − 16 = 10 = `1010` = F(−6)。
- 但現在結果要存成 **64 位元**，那個定理**不適用**。需要新的工具：§5。

## 5. 關鍵定理：MSB 的權重是 −2ⁿ⁻¹

[30:28]–[41:07]　課本 Theorem 2.3.4.2（p.73）

> **定理**：一個 n 位元的有號數 A = A₁…ₙ₋₁ − Aₙ × 2ⁿ⁻¹
> （A₁…ₙ₋₁ 是前 n − 1 位組成的無號數，Aₙ 是 MSB）

【口頭】「這段文字很多，看例子就會非常清楚。」（4 位元）

| A | 表示法 | 前 3 位 | 計算 |
|---|---|---|---|
| 3 | `0011` | `011` = 3 | 3 − 0 × 8 = **3** |
| −3 | `1101` | `101` = 5 | 5 − 1 × 8 = **−3** |
| −5 | `1011` | `011` = 3 | 3 − 1 × 8 = **−5** |
| −4 | `1100` | `100` = 4 | 4 − 1 × 8 = **−4** |

- ⚠️ 老師一開始把 −4 寫成 `1010`，馬上說「我寫錯了」，改成 `1100`（= 12）。

**證明**：

- A ≥ 0：MSB 是 0，拿掉 MSB 值不變。很簡單。
- A < 0：設 F(A) 是 A 的表示法（當無號數）。
  1. 負數的 MSB 一定是 1，所以 F(A) = A₁…ₙ₋₁ + 2ⁿ⁻¹。
  2. 依 2's complement 的定義，F(A) = 2ⁿ + A。（例：−3 → 16 − 3 = 13；−2 → 14；−1 → 15。）
  3. 兩式相減：A = A₁…ₙ₋₁ + 2ⁿ⁻¹ − 2ⁿ = A₁…ₙ₋₁ − 2ⁿ⁻¹ = A₁…ₙ₋₁ − Aₙ × 2ⁿ⁻¹。

【口頭】「Chapter 2 已經證明過了，但我們會在乘法和除法的所有工作裡大量用到它，所以想確定大家真的懂。」

## 6. Iterative multiplier 的硬體

[42:29]–[45:06]　課本 §8.2.2、Figure 8.10（p.320）

```
         ┌──────────── N（multiplicand）────────────┐
         │                                          │
         ▼                                          │
     ┌────────┐                                     │
     │  加法器 │ ◀──────────┐                       │
     └────┬───┘            │                       │
          ▼                │                       │
     ┌──────────────┬──────────────┐               │
     │ U（33 位元）   │ V（32 位元）   │  ← 一起右移
     └──────────────┴──────────────┘
```

- **N**：放被乘數。
- **U**：**33 位元**，一開始全是 0。多一個位元是為了**避免 overflow**。
- **V**：32 位元，一開始放**乘數**（M）。
- **U 和 V 位移時看成一個大暫存器**：右移時 U 的 LSB 變成 V 的 MSB。
- 一個加法器：U + N（或 U − N），結果寫回 U。
- 結束時，UV 的**低 64 位**就是乘積。

## 7. 演算法

[45:06]–[51:10]　課本 Algorithm 1（p.321）

```
Data: Multiplier in V, U = 0, Multiplicand in N
for i = 1 to 32:
    if LSB of V is 1:
        if i < 32:  U ← U + N
        else:       U ← U − N       ← 最後一步：減！
    UV ← UV >> 1                     （算術右移，保留符號）
```

- 跑 32 次，每次看 V 的 **LSB**（就是乘數「這一輪」的那一位）。
- LSB 是 **0**：部分和是 0，**什麼都不用做**。
- LSB 是 **1**：把被乘數加到累積的部分積上。
- 然後 UV 一起**算術右移**一位（保留符號位）。
- 第一輪：U 本來是 0，所以 U ← N，部分積就是被乘數本身。

**UV 裡面的樣子**（第 i 輪之後）：

```
┌──────── U ────────┬──────────── V ────────────┐
│     部分積（高位）     │ 部分積（低位） │ 還沒看的乘數位元 │
└───────────────────┴──────────────┴──────────┘
```

- 每右移一次，部分積多佔一位，乘數最低的一位從右邊**掉出去**（已經處理完了）。

## 8. 為什麼往右移部分積

[51:10]–[60:42]　課本 p.321

- 紙筆的做法：**每個新的部分和往左移一位**再加。
- 這裡的做法：**被乘數不動，把累積的部分積往右移一位**，再加被乘數。
- 【口頭】「這兩個是一樣的，只是**相對運動**。把一個數往左移再加，或把另一些數往右移再加，效果一樣，看你從哪裡看。」
- 從部分積的 LSB（不斷往右移的那條界線）看過去，被乘數第 k 輪看起來就像**左移了 k 位**：剛好就是第 k 個部分和 = 0 或 N × 2ᵏ。
- 這樣做在**硬體上比較容易**：加法器永遠加在同一個位置（U），不用一個會移動的加法器。

【課本補充】Important Point 9：為什麼 U 要 33 位元？|U ± N| 在過程中最大可能到 2³²，32 位元放不下；用 33 位元就**保證不會 overflow**。

## 9. 最後一步為什麼要減

[60:42]–[64:44]

- 前 31 輪，都**假設乘數是正的**。
- 最後一輪看的是乘數的 **MSB**（符號位）。如果是 **1**（乘數是負的），就**減**掉 N，而不是加。
- 原因就是 §5 的定理：

```
N × M = N × (M₁…ₙ₋₁ − Mₙ × 2ⁿ⁻¹)
      = N × M₁…ₙ₋₁   −   N × 2ⁿ⁻¹ × Mₙ
        └ 前 n−1 輪加 ┘   └ 最後一輪：減掉左移 n−1 位的 N ┘
```

- 最後一輪時，部分積已經相對右移了 n − 1 位，所以從它的 LSB 看，N **剛好就是左移 n − 1 位**。直接從 U 減掉 N 就對了。
- 【口頭】「這是非常非常重要、一定要記住的事。很多學生會犯錯：最後一輪不是加，是**減**。」

## 10. 兩個例子

[64:44]–[74:15]　課本 Example 124–125（p.323）

**例 1**：2 × 3（4 位元；N = 2 = `0010`、M = 3 = `0011`）

| 輪 | V 的 LSB | 動作 | 右移前 U V | 右移後 U V |
|---|---|---|---|---|
| 1 | 1 | U += 2 | `00010 0011` | `00001 0001` |
| 2 | 1 | U += 2 | `00011 0001` | `00001 1000` |
| 3 | 0 | — | `00001 1000` | `00000 1100` |
| 4 | 0（MSB） | — | `00000 1100` | `00000 0110` |

乘積 = `0110` = **6**。

**例 2**：3 × (−2)（N = 3 = `0011`、M = −2 = `1110`）

| 輪 | V 的 LSB | 動作 | 右移前 U V | 右移後 U V |
|---|---|---|---|---|
| 1 | 0 | — | `00000 1110` | `00000 0111` |
| 2 | 1 | U += 3 | `00011 0111` | `00001 1011` |
| 3 | 1 | U += 3 | `00100 1011` | `00010 0101` |
| 4 | **1（MSB）** | **U −= 3** | `11111 0101` | `11111 1010` |

- 最後一輪：U = 2，**減** 3 → −1 = `11111`。
- 乘積 = `1010`，4 位元裡 = 10 − 16 = **−6**；8 位元看 `11111010` 也是 −6（符號延伸）。

§16.1 實測：自己寫的模型印出來的每一步和課本完全一樣。

## 12. Booth multiplier 的想法

[74:49]–[82:38]　課本 §8.2.3（p.324–326）

**觀察**：

- 乘數裡**連續的 0**：什麼都不用做。很好。
- 乘數裡**連續的 1**：iterative multiplier 每一位都要做一次加法（最後還有一次減法）。能不能聰明一點？

**等比級數**：

```
2ⁱ + 2ⁱ⁺¹ + … + 2ʲ = 2ʲ⁺¹ − 2ⁱ       （j > i）
```

- 第 i 到第 j 位全是 1，本來要做 j − i + 1 次加法。
- 改成：**看到第 i 位時減一次 N，看到第 j + 1 位時加一次 N**。
- 因為部分積每輪都右移，第 i 輪減掉的 N 等於減掉 N × 2ⁱ，第 j + 1 輪加的 N 等於加 N × 2ʲ⁺¹，合起來就是 N × (2ʲ⁺¹ − 2ⁱ)。

**動作表**：看（目前位元, 前一位元）

| 目前 | 前一位 | 狀況 | 動作 |
|---|---|---|---|
| 0 | 0 | 在一串 0 裡 | 不做 |
| 1 | 0 | **一串 1 開始** | U ← U − N |
| 1 | 1 | 在一串 1 裡 | 不做 |
| 0 | 1 | **一串 1 結束** | U ← U + N |

- 第一位的「前一位」假設是 **0**。
- 【口頭】用同樣的硬體，只多一點點電路。

## 13. Booth 演算法

[82:38]–[89:27]　課本 Algorithm 2（p.326）

```
Data: Multiplier in V, U = 0, Multiplicand in N
prevBit = 0
for i = 1 to 32:
    currBit = LSB of V
    if (currBit, prevBit) == (1, 0): U ← U − N
    if (currBit, prevBit) == (0, 1): U ← U + N
    prevBit = currBit
    UV ← UV >> 1        （算術右移）
```

**為什麼有號數也對**（[84:37]）：

- 難的地方：如果乘數是負的，例如 `111…10…`，一串 1 會**一直延續到 MSB**。看到 0 → 1 的時候減了一次 N，但這串 1 不會結束，**永遠沒機會加回來**。
- 要證明：在 2's complement 的世界，「只減、不加」剛好是對的。
  - 直覺：一串 1 延續到 MSB，等於 2ⁱ + … + 2ⁿ⁻² − 2ⁿ⁻¹（MSB 的權重是負的），整理後 = −2ⁱ。剛好就是那一次減法。
- 【口頭】證明「相當複雜」，書裡有，大約兩頁（標了星號）；線上課程不是講證明的好地方，看例子比較好。
- 證明的大方向：把 Booth 的狀態和 iterative 演算法的狀態**對應**起來。乘數是正的時候，MSB 是 0，每串 1 都會減一次、加一次。乘數是負的時候，再分成 MSB 兩位是 `10` 和 `11` 兩種情況。

## 14. Booth 的例子

[89:27]–[96:52]　課本 Example 126–127（p.329）

**例 1**：3 × 2（N = 3、M = 2 = `0010`）

| 輪 | (目前, 前一) | 動作 | 右移前 | 右移後 |
|---|---|---|---|---|
| 1 | (0, 0) | — | `00000 0010` | `00000 0001` |
| 2 | (1, 0) | **U −= 3** | `11101 0001` | `11110 1000` |
| 3 | (0, 1) | **U += 3** | `00001 1000` | `00000 1100` |
| 4 | (0, 0) | — | `00000 1100` | `00000 0110` |

- −3 在 5 位元是 `11101`（加 3 會得到 0）。右移時保留符號（算術右移）。
- 乘積 = `0110` = **6**。
- 【口頭】這個例子沒有一串 1，所以看不出 Booth 的威力。

**例 2**：3 × (−2)（M = `1110`，有一串 1 而且乘數是負的）

| 輪 | (目前, 前一) | 動作 | 右移前 | 右移後 |
|---|---|---|---|---|
| 1 | (0, 0) | — | `00000 1110` | `00000 0111` |
| 2 | (1, 0) | **U −= 3** | `11101 0111` | `11110 1011` |
| 3 | (1, 1) | — | `11110 1011` | `11111 0101` |
| 4 | (1, 1) | — | `11111 0101` | `11111 1010` |

- 乘積 = `1010` = **−6**（8 位元看 `11111010` 也是 −6）。
- −3 在 5 位元是 +29 = `11101`。
- **只做了 1 次減法**。iterative multiplier 要做 2 次加法、1 次減法，共 3 次。如果加減法佔了大部分時間，**Booth 快 3 倍**。
- 2's complement 自動處理好了：一串 1 一直到 MSB 才結束，什麼特別的事都不用做，乘積就是對的。

## 15. Booth 的時間複雜度

[96:52]–[98:24]

- **最壞的輸入**：`0101…01`（每一位都是轉換點），每一輪都要加或減。
- 每輪還是 O(log n)，n 輪，所以**最壞還是 O(n log n)**，漸近複雜度沒變。
- 【口頭】「實際上數字總會有一些連續的 1，所以實務上一定會看到加速。這是漸近表示法看不出明顯好處的地方。」
- Booth 乘法器**很流行**，特別是在**小型嵌入式處理器**上。
- 下一步：**快得多**的乘法器，O(log² n) 時間，用在非常高效能的實作上（第 23 支）。

⚠️ 「實務上一定會加速」要看資料。§16.2 實測：對**均勻隨機**的 32 位元乘數，Booth 和 iterative 平均都要 **16 次**加減法，一樣多（隨機的位元裡，相鄰兩位不同的機率是 1/2）。Booth 只有在乘數有**長串的 1**（例如小的負數、`0x0000FFFF`、`0x7FFFFFF0`）時才明顯比較快；遇到 `0x55555555` 這種交錯的數，反而要 32 次，比 iterative 的 16 次還多。

### 16.2 32 位元：正確性與加減法次數

```
32-bit random: wrong = 0; average add/sub per multiply: iterative 16.0, Booth 16.0
multiplier 0x0000FFFF: iterative 16 ops, Booth  2 ops
multiplier 0x7FFFFFF0: iterative 27 ops, Booth  2 ops
multiplier 0x55555555: iterative 16 ops, Booth 32 ops
multiplier 0xFFFFFFFF: iterative 32 ops, Booth  1 ops
```

- **20000 組隨機的 32 位元有號數**，加上 (−2³¹) × (−2³¹)、(−2³¹) × (2³¹ − 1)、(−1) × (−1) 這些邊界情況，兩種乘法器**全部算對**（wrong = 0）。33 位元的 U 確實不會 overflow。

- 有長串 1 時 Booth 大勝：`0x0000FFFF` 從 16 次變 2 次；**−1**（`0xFFFFFFFF`）從 32 次變 **1 次**。
- `0x55555555`（`0101…`）是 Booth 的最壞情況：**32 次**，比 iterative 還多。

## 17. 一頁速查表

| 主題 | 重點 |
|---|---|
| CLA Stage II | C_in¹ 送進最右邊的塊；(r2,r1) 接到 (r3, r2+1)；每單位時間往下一層；O(log n) |
| CLA 總時間 | O(log n)；商用處理器用 |
| 乘法術語 | multiplicand（上）× multiplier（下）= product；partial sum；partial product |
| 乘積位元數 | m 位元 × n 位元 → m + n 位元 |
| 定理 | A = A₁…ₙ₋₁ − Aₙ·2ⁿ⁻¹（MSB 權重為負） |
| Iterative 硬體 | N（被乘數）、U（33 位元，0）、V（32 位元，乘數）；UV 一起算術右移 |
| Iterative 演算法 | 32 輪：LSB = 1 → U += N（最後一輪 U −= N）；UV >>= 1 |
| 為什麼右移 | 部分積右移 = 被乘數左移；加法器固定在 U |
| 為什麼最後減 | MSB 的權重是 −2ⁿ⁻¹ |
| Iterative 時間 | n × O(log n) = O(n log n) |
| Booth 恆等式 | 2ⁱ + … + 2ʲ = 2ʲ⁺¹ − 2ⁱ |
| Booth 動作 | (cur, prev)：(1,0) → U −= N；(0,1) → U += N；其他不動；prev 初值 0 |
| Booth 有號數 | 一串 1 延續到 MSB 時只減不加，剛好正確 |
| Booth 時間 | 最壞 0101…：O(n log n)；有長串 1 時快很多；隨機資料平均和 iterative 一樣 |

## 附：本講一句話總結

> **Carry lookahead adder 的 Stage II 把最低位的 carry in 送進每一層最右邊（範圍從 1 開始）的 (G,P) 塊，每個範圍 (r2, r1) 的塊用 C_out = G + P·C_in 算出 carry 後再送給範圍從 r2 + 1 開始、層級較低的塊，每個時間單位往下一層，所以 O(log n) 後每個 2 位元 ripple adder 都拿到 carry in，整個加法 O(log n)。乘法和小學的直式乘法一樣，是被乘數左移後的部分和相加；iterative multiplier 用 33 位元的 U、32 位元的 V（放乘數）和被乘數 N，每輪看 V 的 LSB，是 1 就 U += N，然後 UV 一起算術右移（部分積右移等於被乘數左移），但最後一輪若乘數的 MSB 是 1 要改成 U −= N，因為 MSB 的權重是 −2ⁿ⁻¹，總時間 O(n log n)。Booth 乘法器利用 2ⁱ + … + 2ʲ = 2ʲ⁺¹ − 2ⁱ，看（目前位元, 前一位元）：一串 1 開始（1,0）時減 N、結束（0,1）時加 N，一串 1 延續到 MSB 時只減不加也剛好正確；最壞情況（0101…）仍是 O(n log n)。實測課本 Example 124、125 的每一步都重現，2 萬組 32 位元有號數全部正確；3 × (−2) 時 iterative 要 3 次加減、Booth 只要 1 次，但對均勻隨機的乘數兩者平均都是 16 次，Booth 只有在乘數有長串的 1 時才真的比較快。**
