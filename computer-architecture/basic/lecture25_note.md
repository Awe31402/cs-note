## 0. 本講地圖

浮點數的加、乘、除（[00:44]）：加法和乘法的做法差不多；除法很不一樣，「也很有趣」。這一講是**加法**：

```
解開 S、E、P → 讓 E_A ≥ E_B → W = P_B，右移 E_A − E_B 位（對齊小數點）
  → 同號：W += P_A；異號：W = P_A − W（W < 0 就取 2's complement、反轉符號）
  → 正規化（W ≥ 2：右移、E+1；W < 1：左移、E−1）
  → 捨入（用 round 位元 r 和 sticky 位元 s）→ 可能要再正規化 → 組回 C
```

- 【課本補充】A − B 就是 A + (−B)，所以**減法是加法的特例**，不另外講。

## 1. 複習：IEEE 754 的格式

[00:44]–[08:04]　課本 Table 8.5（p.341）

（用 32 位元當例子；64 位元同理。[第 5 支](lecture05_note.md) 講過。）

| 種類 | 正規化形式 |
|---|---|
| Normal | A = (−1)^S × P × 2^(E − bias)，1 ≤ P < 2，1 ≤ E ≤ 254 |
| Denormal | A = (−1)^S × P × 2⁻¹²⁶，0 ≤ P < 1 |

- S：符號位；P：**significand**（normal 是 1.xxx，denormal 是 0.xxx）；M：**mantissa**（P 的小數部分，23 位元）；E：指數 ＋ 127（bias）。
- 例：1.5 = 二進位 1.1 = 1.1 × 2⁰ → S = 0、mantissa = `1000…0`、E = 0 + 127 = **127**。
- E = 0：M = 0 是 0，M ≠ 0 是 denormal。E = 255：M = 0 是 ±∞，M ≠ 0 是 NaN。
- ⚠️ 投影片上 denormal 的範圍寫錯，老師口頭更正：「應該是 0，不是 1：0 ≤ P < 1。」

## 2. 同號相加：對齊小數點

[08:04]–[17:13]　課本 §8.4.1（p.342–343）

**輸入**：A、B 兩個 32 位元浮點數（1 位元 S、8 位元 E、23 位元 M），輸出 C 也是同樣的格式。

**解開（unpack）**：

- E_A、E_B：兩個數的 E 欄位；E_C：結果的 E 欄位。硬體裡用一個暫存器 **E** 存指數，最後 E 就是 E_C。
- **Significand 當成無號整數，忽略小數點**，前面再**多加一個 0**（當符號位用）：

```
1.5 = 1.1₂  →  significand 1.100…0（24 位元）  →  W = 0 1.100…0（25 位元）
                                                  ↑ 多加的 0
```

- 為什麼 25 位元：小數點前 1 位 ＋ 23 位元 mantissa = 24 位元，再加一個開頭的 0。
- 小數點的位置是**隱含的**，硬體裡不存。

**對齊**：

- 不失一般性，假設 **E_A ≥ E_B**（硬體用一個比較 ＋ 交換就能做到）。暫存器 E 初始化成 E_A。
- 把 B 的 significand 放進 W。

【口頭】十進位的類比：2 × 10⁻¹ + 4 × 10⁻³

```
  2 × 10⁻¹ + 4 × 10⁻³
= 2 × 10⁻¹ + 0.04 × 10⁻¹      ← 讓指數一樣（小的那個往右移）
= (2 + 0.04) × 10⁻¹
= 2.04 × 10⁻¹                 ← 小數點對齊後直接加
```

二進位做一樣的事：

```
W = W >> (E_A − E_B)          ← 把 B 往右移，指數變成 E_A，小數點就對齊了
W = W + P_A                    ← 普通的加法
```

- 「任何浮點數加法，第一件事永遠是**對齊小數點**。」

## 3. 正規化

[17:13]–[19:55]　課本 p.343

- 加完的 W 代表的 significand 叫 P_W。它有可能 **≥ 2**。
  - 例：1.5 + 1.5 = 1.1₂ + 1.1₂ = 11.0₂ = 3，不是合法的 significand。
- **正規化**（normalization）：W **右移 1 位**，E **加 1**。11.0 × 2⁰ → 1.10 × 2¹。
- 【口頭】十進位：23 × 10⁴ 不要小數點前有兩位，寫成 2.3 × 10⁵（右移一位、指數加一）。
- 結果的符號：**同號相加**，就是 A（或 B）的符號。
- 有了符號、P_W（取出 23 位元 mantissa）、E，就能組回浮點數 C。
- 【課本補充】E 加 1 之後可能變成 **255**，這不是合法的值，要發出 **overflow**。

## 4. 兩個例子

[20:11]–[25:45]　課本 Example 130–131（p.343–344）

（為了方便，**不用 bias**，E 直接存真的指數。小數點只是為了好讀。）

**Example 130**：1.01₂ × 2³ + 1.11₂ × 2¹

1. A = 1.01 × 2³、B = 1.11 × 2¹
2. W = 01.11（B 的 significand）
3. E = 3
4. W = 01.11 >> (3 − 1) = 00.0111
5. W + P_A = 00.0111 + 01.0100 = **01.1011**
6. 介於 1 和 2 之間，不用正規化。結果 C = **1.1011 × 2³**

**Example 131**：1.01₂ × 2³ + 1.11₂ × 2²

1. A = 1.01 × 2³、B = 1.11 × 2²
2. W = 01.11
3. E = 3
4. W = 01.11 >> (3 − 2) = 00.111
5. W + P_A = 00.111 + 01.010 = **10.001**（≥ 2！）
6. 正規化：W = 10.001 >> 1 = 1.0001，E = 4
7. 結果 C = **1.0001 × 2⁴**

## 5. 為什麼需要捨入

[25:45]–[31:12]　課本 §8.4.2（p.344）

- 假設 Example 131 只能存 **2 位** mantissa：1.0001 只能留 1.00，後面的位元要丟掉。如果結果是 1.0011，直接丟掉就不太對，應該**捨入**成 1.01。
- 為什麼會有多餘的位元？因為 B 的 significand **右移**了：例如 `0.000…0xxxx…`，加起來可能超過 23 位元的 mantissa。只能存 23 位，其他要丟掉，但要**丟得最準確**。

**術語**（[28:01]）：

```
W = (P + R) × 2⁻²³        （R < 1）
```

- **P**：要保留的 24 位元 significand，**當成無號整數**（乘上 2²³，小數點就移到最後面）。
- **R**：**residue**（殘餘），要丟掉的部分，乘上 2²³ 之後小於 1。
- 目標：依 R 的值**修改 P**，得到新的 P′，然後丟掉 R。

【口頭】十進位例子：只能存小數點後兩位，10.5093 → 殘餘是 0.0093，應該把 10.50 改成 **10.51**。

- P′ 只有兩種可能：**P′ = P**（直接丟掉殘餘，叫 **truncation**）或 **P′ = P + 1**（捨入）。

## 6. 四種捨入模式

[31:12]–[38:36]　課本 §8.4.2（p.345）

IEEE 754 支援四種捨入模式（例子都捨入到整數）：

| 模式 | 做法 | 例子 |
|---|---|---|
| **Truncation**（截斷） | P′ = P，直接丟掉殘餘 | 9.5 → 9、9.6 → 9、9.99 → 9；−1.5 → −1 |
| **Round to +∞** | ⌈P + R⌉（往比較大的整數） | 9.5 → 10；−3.2 → −3；3.4 → 4；−6.2 → −6 |
| **Round to −∞** | ⌊P + R⌋（往比較小的整數） | 9.5 → 9；−3.2 → −4；4.6 → 4；−3.8 → −4 |
| **Round to nearest** | 捨入到最近的整數；剛好在中間時選**偶數** | 9.4 → 9、9.6 → 10、−2.3 → −2；**9.5 → 10**、**−3.5 → −4** |

- 【口頭】truncation 很簡單，「但一般不建議用」。
- Round to nearest：剛好是 X.5 時，離兩邊一樣近，「慣例上」選偶數。
- 【課本補充】truncation 最容易用硬體實作，也**最不準**。**Round to nearest 最複雜，也最常用**：大部分處理器預設用它。選偶數「是慣例，不是什麼深奧的數學概念」：3.5 → 4、4.5 → 也是 4。
- （對照 [第 17 支](lecture17_note.md#2-fcsr例外旗標與捨入模式)：這四種就是 RISC-V 的 RTZ、RUP、RDN、RNE。）

## 7. 捨入的條件總表

[38:36]–[50:25]　課本 Table 8.6（p.345）

把捨入看成一個黑盒子：輸入 **P**（24 位元無號整數）和 **R**（< 1），輸出 P′ = P 或 P + 1。

下表只列出**要加 1**（P′ = P + 1）的條件；空白就是 truncation（P′ = P）：

| 模式 | 結果是正的 | 結果是負的 |
|---|---|---|
| Truncation | | |
| Round to +∞ | **R > 0** | |
| Round to −∞ | | **R > 0** |
| Round to nearest | **R > 0.5 或（R = 0.5 且 LSB(P) = 1）** | **同左** |

**為什麼**（P 存的是**絕對值**，符號另外存）：

- **+∞、正數**：3.1 → 4。只要殘餘不是 0，就要往上加 1。
- **+∞、負數**：−3.1 → −3。−3.x 都捨入到 −3，就是把 .x 截掉（絕對值變小），什麼都不做。
- **−∞**：剛好相反。3.1 → 3（截掉）；−3.1 → −4（絕對值加 1）。
- **Nearest**：
  - 3.9：R = 0.9 > 0.5 → 4。
  - 3.1：都不成立 → 3。
  - 3.5：R = 0.5，P = 3 是**奇數**（LSB = 1）→ 4。
  - 4.5：R = 0.5，但 P = 4 是**偶數** → 截掉，4。
  - 負數一模一樣：−3.9 → −4、−3.1 → −3、−3.5 → −4、−4.5 → −4。
- **奇數 ⟺ LSB 是 1**：二進位裡除了最低位，其他每一位都是 2 的倍數，所以奇偶只看最低位。

**要實作，需要四個資訊**：

1. LSB(P) 是不是 1
2. R > 0？
3. R = 0.5？
4. R > 0.5？

LSB(P) 很容易拿（就是一個位元）。其他三個要靠 §8。

## 8. 用 round 位元和 sticky 位元實作捨入

[50:25]–[54:55]　課本 §8.4.3、Table 8.7（p.345–346）

```
殘餘 R = 0. r  x x x x x …
            │  └── s = 這些位元的 OR
            └ round 位元
```

- **r**（round bit）：殘餘的**最高位**。
- **s**（sticky bit）：殘餘**其他所有位元的 OR**。s = 1 表示後面至少有一個 1；s = 0 表示後面全是 0。

**只用 r 和 s 就能判斷所有條件**：

| 條件 | 實作 | 理由 |
|---|---|---|
| R > 0 | **r ∨ s = 1** | 殘餘裡至少有一個 1 |
| R = 0.5 | **r ∧ s̄ = 1** | 0.5 = 0.1000…₂：r = 1，後面全是 0 |
| R > 0.5 | **r ∧ s = 1** | 0.1xxx… 而且後面至少有一個 1 |

- 【課本補充】實作捨入就是**一路維護 r 和 s**：初值 0；B 右移時要更新（移出去的位元算進 s）；正規化時再更新。
- **sticky** 這個名字：一旦有 1 被移出去，它就「黏」住變成 1，之後不會再變回 0。

§12.2 實測：拿掉 sticky 位元（移出去的位元直接丟掉），有 **14%** 的加法結果會錯。

## 9. 捨入後再正規化

[54:55]–[55:57]　課本 p.346

- P 加 1 之後，可能又變成 **≥ 2**。例：P 全是 1，加 1 變成 1 後面 23 個 0（= 10.000…）。
- 要**再正規化**：E 加 1、mantissa 設成全 0。
- E 加 1 可能變成 **255**（不合法，那是 NaN／∞ 用的），要明確檢查，發出 **overflow**：「結果超出數字系統的範圍，表示不了。」

## 10. 異號相加

[55:57]–[61:26]　課本 §8.4.4（p.346）

【口頭】在有號數的世界，加法和減法其實沒有差別，所以分成「同號」和「異號」兩種情況討論。

步驟（仍假設 E_A ≥ E_B）：

1. W = P_B（前面加 0）。
2. 異號，等於從 A 的 significand **減掉** B 的（移位後的）significand。所以**把 W 取 2's complement**（W = −W），之後做加法。
3. 對齊：W 右移 E_A − E_B 位。
   - 【課本補充】這裡要用**算術右移**，值才不會變。**取 2's complement 和右移的順序不重要**。
4. W = W + P_A。
5. **結果可能是負的**。例：1.1 + (−1.5)：指數相同，A = 1.1，加上 −1.5 → −0.4。
   - 處理：W = −W（取 2's complement），**反轉結果的符號**。−0.4 → 存 0.4、符號改成負。
6. **正規化**：結果可能 **< 1**。例：1.10₂ + (−1.01₂) = 0.01₂，不是 1.xxx 的形式。（⚠️ 投影片上的例子逐字稿看不出具體數字，這是依口頭描述「結果是 0.01」補的。）
   - **一直左移 W**，直到變成 1.xxx；每左移一次，E **減 1**。0.01 → 1.0 × 2⁻²，E 減 2。
7. 捨入。【口頭】左移時移進來的是 0，所以這種情況通常不需要捨入；但指數一樣、有位元剩下時還是要。
8. 可能要再正規化。

【口頭】為什麼「右移」和「取 2's complement」的順序不重要？因為**電路內部的暫存器可以比 32 位元寬**：輸入、輸出是 32 位元，但中間的 significand 可以多留一些位元，最後再用正確的捨入規則丟掉。只要空間夠，就不會損失精度。

【課本補充】**guard 位元**（影片沒講）：

- 左移正規化時，如果只有 r 和 s，第一次左移就要把 r 移進 W，r 就**永遠消失**了。
- 所以大部分實作多用一個 **guard 位元**：殘餘的最高位是 guard、下一位是 round、其他的 OR 是 sticky。
- 左移時先移進 guard 位元，再移進 0。
- 演算法結束時，把 round 設成 guard，sticky 再 OR 上原本的 round，回到 r、s 的語意。
- 這是為了**左移 1 位**這種常見情況的最佳化。

## 11. 完整的流程圖

[61:26]–[66:47]　課本 Figure 8.17（p.347）

```
C = A + B
  │
  ├─ A = 0 ? → C = B
  ├─ B = 0 ? → C = A
  │
  ▼
交換 A、B，使 E_B ≤ E_A
W ← P_B >> (E_A − E_B)；E ← E_A；S ← sign(A)
  │
  ▼
sign(A) = sign(B) ?
  ├─ 是：W ← W + P_A
  └─ 否：W ← −W（2's complement）；W ← W + P_A
  │
  ▼
W < 0 ? → W ← −W，S ← −S
  │
  ▼
正規化 W，更新 E → overflow／underflow ? → 回報
  │
  ▼
捨入 W
  │
  ▼
正規化 W，更新 E → overflow／underflow ? → 回報
  │
  ▼
用 W、E、S 組出 C
```

- 【口頭】這張圖的順序（先右移、後取 2's complement）和前面講的相反；如前所述，空間夠的話順序不重要。
- 【口頭】「建議所有學生仔細看這張流程圖。只要懂每一步，流程圖本身很簡單；但懂每一步非常重要。」

### 12.1 自己寫的 float32 加法器 vs 硬體

- `ref.c`：產生 **10 萬組**隨機的 normal float（指數 100～149，正負都有），用 x86 的 SSE 硬體在**四種捨入模式**（`fesetround`）下相加，印出 16 進位。
- `fpadd.py`：完全照 §11 的流程，用位元做 float32 加法：解開 → 對齊（右移時把移出去的位元 OR 進 sticky）→ 同號加、異號減 → 正規化 → 用 r、s 和 §7 的表捨入 → 再正規化。W 最低保留 3 位（guard、round、sticky）。

```
$ gcc -O0 -frounding-math -o ref ref.c -lm && ./ref > ref.txt
$ head -2 ref.txt
caece243 c7e01a6d caf062ac caf062ac caf062ad caf062ad
326c5b91 bcd48673 bcd4866b bcd4866b bcd4866c bcd4866c
       a        b      RTZ      RUP      RDN      RNE
$ python3 fpadd.py ref.txt
100000 additions; mismatches vs x86 hardware: {'rtz': 0, 'rup': 0, 'rdn': 0, 'rne': 0}
```

- **四種模式、10 萬組，全部和硬體一模一樣**（一個位元都沒差）。
- 第一行就看得到捨入模式的差別：兩個負數相加，RTZ 和 RUP（往 +∞ 就是往 0）得到 `…ac`，RDN 和 RNE 得到 `…ad`（絕對值大 1）。

### 12.2 拿掉 sticky 位元會怎樣

把「移出去的位元 OR 進 sticky」改成「直接丟掉」：

```
$ python3 fpadd_nosticky.py ref.txt
100000 additions; mismatches vs x86 hardware: {'rtz': 14501, 'rup': 14546, 'rdn': 14257, 'rne': 3752}
```

- 約 **14%** 的結果錯了，**連 truncation 都錯**。
- 為什麼 truncation 也會錯？因為**異號相減**時，B 被移出去的那些位元雖然看不到，但它們讓 A − B 的結果**比較小一點**，會影響要不要從保留的位元「借位」。只看保留的位元，就會算成比較大的值。sticky 位元記住了「後面還有東西」，結果才對。
- RNE 錯得比較少（3.7%），因為只有在殘餘剛好接近 0.5 時才會出錯。

## 13. 一頁速查表

| 主題 | 重點 |
|---|---|
| 減法 | A − B = A + (−B)，是加法的特例 |
| 解開 | E_A、E_B；significand 當無號整數，前面加一個 0 → 25 位元的 W |
| 對齊 | 讓 E_A ≥ E_B；W = P_B >> (E_A − E_B) |
| 同號 | W = W + P_A；符號 = A 的符號 |
| 正規化 | W ≥ 2：右移、E + 1；W < 1：左移、E − 1 |
| Overflow | E 變成 255 |
| 殘餘 | W = (P + R) × 2⁻²³，P 是 24 位元整數，R < 1 |
| Truncation | 直接丟掉 R |
| +∞ | 正數且 R > 0 → P + 1 |
| −∞ | 負數且 R > 0 → P + 1 |
| Nearest（預設） | R > 0.5，或 R = 0.5 且 P 是奇數 → P + 1（ties to even） |
| Round 位元 r | 殘餘的最高位 |
| Sticky 位元 s | 殘餘其他位的 OR |
| R > 0／= 0.5／> 0.5 | r ∨ s／r ∧ s̄／r ∧ s |
| 捨入後 | 可能 ≥ 2 → 再正規化，可能 overflow |
| 異號 | W 取 2's complement（算術右移）；結果 < 0 就再取一次、反轉符號；常要左移正規化 |
| Guard 位元 | 左移正規化時保護 round 位元 |

## 附：本講一句話總結

> **浮點數加法（減法只是加上 −B）先解開符號、指數 E 和 significand（當成無號整數、前面多加一個 0 放進 25 位元的 W），讓 E_A ≥ E_B，把 B 的 significand 右移 E_A − E_B 位對齊小數點；同號就把 A 的 significand 加上去，異號就先把 W 取 2's complement 再加，結果是負的就再取一次並反轉符號；接著正規化（≥ 2 就右移、E + 1，< 1 就左移、E − 1），再依捨入模式決定要不要把保留的 24 位元 significand 加 1：truncation 不加、往 +∞ 是正數且殘餘 > 0 時加、往 −∞ 是負數且殘餘 > 0 時加、round to nearest（預設）是殘餘 > 0.5 或剛好 0.5 且 LSB 是 1 時加（ties to even）；這些條件只要殘餘的最高位 r（round）和其他位的 OR s（sticky）就能判斷（R > 0 是 r ∨ s、R = 0.5 是 r ∧ s̄、R > 0.5 是 r ∧ s），捨入後可能要再正規化，指數變成 255 就是 overflow；課本另外用 guard 位元保護左移時的 round 位元。實測照這個流程用位元寫的 float32 加法器，在四種捨入模式下對 10 萬組隨機數和 x86 硬體結果完全相同，而拿掉 sticky 位元後約 14% 會錯，連 truncation 都會錯。**
