## 0. 本講地圖

Chapter 2 的最後一部分：

```
帶小數點的數 → 二進位小數 → normal form (−1)^S × 1.M × 2^X
   → IEEE 754：1 bit S ＋ 8 bit E（bias 127）＋ 23 bit M
   → 特殊值（E = 0 或 255）：±0、±∞、NaN、denormal
   → 浮點數運算是近似的（不滿足結合律）
文字 → ASCII（7 bit）→ Unicode（UTF-8 / 16 / 32）
```

[00:43]–[05:00]

- **Boolean algebra**：AND（全部是 1 才是 1）、OR（有一個是 1 就是 1）、NOT（取反）、XOR（一個 0 一個 1 才是 1）。

## 2. Fixed point 與 floating point

[05:00]–[06:00]　課本 §2.4–2.4.1（p.74）

- **Floating point number（浮點數）**：任何帶小數點的數，例如 2.356、13 × 10⁻¹⁰。
- **Fixed point number（定點數）**：小數點後的**位數固定**。例：3.29。
  - 錢就是定點數：大部分貨幣小數點後固定兩位。
- 【課本補充】定點數的存法：120.23 存成整數 12023，隱含「小數點後兩位」。加減很容易，**乘除就難了**。
- 【課本補充】整數是浮點數的子集：7 可以寫成 7.0000000。

## 3. 二進位的小數

[06:00]–[09:28]　課本 §2.4.2（p.74–76）

十進位的一般式：

```
A = Σ xᵢ × 10ⁱ   （i 從 −n 到 n，xᵢ 是 0～9）
例：3.29 = 3×10⁰ + 2×10⁻¹ + 9×10⁻²
```

把 10 換成 2 就是二進位（xᵢ 只能是 0 或 1）：

| 數字 | 展開 | 二進位 |
|---|---|---|
| 0.375 | 2⁻² + 2⁻³ | 0.011 |
| 1 | 2⁰ | 1.0 |
| 1.5 | 2⁰ + 2⁻¹ | 1.1 |
| 2.75 | 2¹ + 2⁻¹ + 2⁻² | 10.11 |
| 17.625 | 2⁴ + 2⁰ + 2⁻¹ + 2⁻³ | 10001.101 |

- 負指數是**小數部分**，非負指數是**整數部分**。
- 【口頭】「如果你去一個人們只有兩根手指的星球，他們會用二進位，不會用十進位。」
- 【口頭】例：二進位 `10.11` = 2 + 0.5 + 0.25 = 2.75。
- ⚠️ 影片 [08:09] 老師口頭更正投影片：「這裡應該是 −3」（17.625 的最後一項是 2⁻³）。
- 【課本補充】很多數（例如十進位的 1.11）在二進位需要**無限多項**，只能近似。§14.1 實測：`1.11f` 實際存的是 1.1100000143。

## 4. Normal form：sign、significand、mantissa、exponent

[09:28]–[12:29]　課本 §2.4.2（p.76）

```
A = (−1)^S × P × 2^X ,   P = 1 + M ,   0 ≤ M < 1 ,   X ∈ ℤ
```

| 符號 | 名稱 | 意思 |
|---|---|---|
| S | **sign bit（符號位）** | 0 是正，1 是負 |
| P | **significand（有效數）** | 一定在 1 和 2 之間：1.xxx |
| M | **mantissa（尾數）** | significand 的小數部分，0 ≤ M < 1 |
| X | **exponent（指數）** | 整數 |

- 這裡用 **sign-magnitude** 表示正負。【口頭】「不然會太複雜。」
- 例：2.6 = (−1)⁰ × 1.3 × 2¹。significand 是 1.3，mantissa 是 0.3。
- 十進位的例子：
  - 1.3827 × 10⁻²³：significand 1.3827，mantissa 0.3827，exponent −23，sign 0。
  - −1.2 × 10⁵：significand 1.2，mantissa 0.2，exponent +5，sign 1。
- 這個形式叫做 **normal form（正規化形式）**。

【課本補充】為什麼不用「固定幾位整數、幾位小數」？如果 32 位元平分給整數和小數各 16 位，最大只能到約 2¹⁶ = 65,536，太小了，連 2⁵⁰ 都表示不了。把小數點「浮動」起來（乘上 2^X），範圍就大很多。

## 5. IEEE 754 單精度格式

[12:29]–[18:19]　課本 §2.4.3（p.77）

- IEEE = Institute of Electrical and Electronics Engineers，負責制定各種標準。**IEEE 754** 是浮點數的標準。

```
 31 30        23 22                      0
┌──┬────────────┬─────────────────────────┐
│S │  E (8 bit) │      M (23 bit)         │
└──┴────────────┴─────────────────────────┘
```

- **省一個位元**：significand 一定是 1.xxx，所以那個 **1 不用存**，只存 mantissa。
  - 【口頭】例：1.384 只要存 384 的二進位。
- **Exponent 用 bias 表示**（[14:11]）：存 E = X + 127。
  - X = 0 → 存 127；X = −23 → 存 104；X = +30 → 存 157。
  - 【課本補充】X = 10 → 137；X = −20 → 107。
- **為什麼 exponent 用 bias、不用 2's complement？**（[15:07]）
  - 指數有正有負，所以要有一種有號表示法。
  - 浮點數運算時，指數**大多只做加減**（乘法時指數相加），很少拿指數去乘別的數。
  - Bias 表示法加減很容易（[第 4 支 §4](lecture04_note.md#4-bias-based)），只是乘法難；既然不需要乘，就不用 2's complement 這麼重的東西。
- **Normal 數的範圍**：E 是 1～254，所以 X 是 **−126～+127**。E = 0 和 255 保留給特殊值。

```
A = (−1)^S × (1 + M) × 2^(E − 127) ,   1 ≤ E ≤ 254
```

⚠️ 影片 [14:27] 說 8 位元 exponent「可以表示 −127 到 +128」，那是把 E = 0 和 255 也算進去的範圍；能拿來表示 normal 數的只有 −126～+127。老師在 [17:13] 自己補充了這點。

- 【口頭】「Food for thought：最大的正 normal 數、最小的負 normal 數是多少？答案在書上。」
- 【課本補充】課本 Example 16、17：
  - 最大正 normal 數 = 1.11…1（23 個 1）× 2¹²⁷ = (2 − 2⁻²³) × 2¹²⁷ = **2¹²⁸ − 2¹⁰⁴**
  - 最小正 normal 數 = 1.0 × 2⁻¹²⁶ = **2⁻¹²⁶**
  - normal 數的範圍：±(2¹²⁸ − 2¹⁰⁴)

## 6. 特殊值：∞、NaN、±0、denormal

[18:19]–[22:19]　課本 Table 2.14（p.78）

| E | M | 值 |
|---|---|---|
| 255 | 0 | S = 0：**+∞**；S = 1：**−∞** |
| 255 | ≠ 0 | **NaN**（Not a Number） |
| 0 | 0 | **±0** |
| 0 | ≠ 0 | **denormal number** |

- **∞**：1/0 = +∞，−1/0 = −∞。
- **NaN**：結果沒有定義的時候。例：0/0、log(−1)、sin⁻¹(5)。
  - **任何算式只要有 NaN，結果就是 NaN**。NaN + NaN = NaN，NaN − 9 = NaN。
  - ⚠️ 逐字稿 [20:37] 把 NaN 聽成「9」（「n - 9 is equal to 9」），應該是「NaN − 9 = NaN」。
  - 【課本補充】M ≠ 0 時就是 NaN，M 的確切值不重要。
- **兩個 0**：S 可以是 0 或 1，E 和 M 全是 0。
  - 【口頭】「很可惜 IEEE 格式有兩個 0，不是我們想要的，但沒辦法。」
  - 【課本補充】理想上實作應該把兩個 0 當成一樣，但「可能依處理器廠商而不同」。§14.1 實測：x86 上 `-0.0f == 0.0f` 是真的。

## 7. 例子：−3 的表示法

[22:19]–[26:16]

1. 化成 normal form：−3 = (−1)¹ × 1.5 × 2¹ = (−1)¹ × (1 + 0.5) × 2^(128 − 127)
2. **S** = 1（負數）
3. **E** = 1 + 127 = 128 = `1000 0000`
4. **M** = 0.5 = 2⁻¹。23 位元的 mantissa，第 i 位代表 2⁻ⁱ，所以第 1 位（最高位）是 1，其他是 0：`100 0000 0000 0000 0000 0000`

```
1 | 10000000 | 10000000000000000000000   = 0xC0400000
```

§14.1 實測印出來正好是 `C0400000`。

## 8. Denormal number

[26:16]–[35:28]　課本 §2.4.4（p.79–80）

**問題**（[26:31]）：

```
f = 2^(-126);     // 最小的正 normal 數
g = f / 2;        // 2^(-127)，normal 表示不了
if (g == 0) print("error");
```

- 如果只有 normal 數，g 表示不了，只能變成 0，就會印出 error。
- 【口頭】「直覺上不對：f 是正數，除以 2 還是正數，沒理由是 0。」

**解法**：定義 **denormal number**（E = 0、M ≠ 0），用不同的 normal form：

```
A = (−1)^S × (0 + M) × 2^(−126)
```

- 隱含的 1 換成 **0**。
- 指數固定是 **−126**，不是 −127。
  - 【口頭】「這是學生常犯的錯，也是老師常考的問題：為什麼是 −126？」

**為什麼是 −126**（[29:27]）：

- 最大的 mantissa = 2⁻¹ + 2⁻² + … + 2⁻²³ = **1 − 2⁻²³**（等比級數）。
  - 【口頭】「這個結果在書裡和課堂上會一直出現，可以記起來。」
- 最大的 denormal = (1 − 2⁻²³) × 2⁻¹²⁶ = **2⁻¹²⁶ − 2⁻¹⁴⁹**
- 最小的 normal = **2⁻¹²⁶**
- 兩者只差 2⁻¹⁴⁹，**剛好接上**。如果用 −127，中間就會空出一段。
- 最小的正 denormal：只有 mantissa 最後一位是 1 = 2⁻²³ × 2⁻¹²⁶ = **2⁻¹⁴⁹**。

```
0 ── denormal [2⁻¹⁴⁹, 2⁻¹²⁶ − 2⁻¹⁴⁹] ── normal [2⁻¹²⁶, …)
           （圖不照比例）
```

- 負的 denormal 範圍：[−(2⁻¹²⁶ − 2⁻¹⁴⁹), −2⁻¹⁴⁹]。
- Denormal 只是把範圍**稍微延伸**一點，讓數學和程式的結果合理。

【課本補充】實作 denormal 很難、處理很慢，所以很多小型嵌入式處理器**不支援**；桌機和筆電的處理器大多完整支援。§14.2 實測：開了 `-ffast-math` 之後，gcc 會把 x86 設成 **flush-to-zero**（把 denormal 當 0），那段程式就真的印出 error。

## 9. 範圍：int、float、double

[35:28]–[38:54]　課本 §2.4.5（p.80）

| 型別 | 位元 | 大約範圍 |
|---|---|---|
| 32 位元整數（int） | 32 | ±2³¹ ≈ ±2 × 10⁹ |
| 單精度浮點數（float） | 32 | ±2¹²⁸ ≈ ±10³⁸ |
| 雙精度浮點數（double） | 64 | ±2¹⁰²⁴ ≈ ±10³⁰⁸ |

**Double precision（雙精度）**：

```
1 bit S ＋ 11 bit E ＋ 52 bit M ，bias = 1023
```

- C 和 Java 的 `double`。
- 【口頭】「±10³⁰⁸ 很大，大部分計算不會需要更大的。」
- 【課本補充】為什麼需要 double：研究宇宙學時要表示更大的數；而且 float 只有 23 位元精度，敏感的計算需要更多。±∞、0、NaN、denormal 的規則和 32 位元一樣。

⚠️ 影片的幾個數字和課本不一致：
- 影片 [36:44] 說 2¹²⁸「大約是 10⁴⁰」；課本說約 10³⁸。實際是 3.4 × 10³⁸（§14.1 `FLT_MAX`）。老師在 [37:53] 自己改口說「10³⁷ 或 10³⁸」。
- 影片 [37:19] 說 double 的指數「從 −1023 到 +1023」；課本說 normal 的指數是 **−1022 到 1023**（和 float 一樣，E 的頭尾兩個值保留）。
- 影片對 int 的上限說了「30 多億、40 億」，最後才改成「約 20 億」。有號 32 位元的上限是 2³¹ − 1 = 2,147,483,647。

## 10. 浮點數運算是近似的

[38:54]–[42:46]　課本 §2.4.6（p.81）

```
A = 2^50;  B = 2^10;
C = (A + B) − A;
```

- A + B = 2⁵⁰ × (1 + 2⁻⁴⁰)。mantissa 要表示 2⁻⁴⁰，但最小只到 **2⁻²³**，表示不了。
- 硬體只好得到 A + B = 2⁵⁰，然後 C = 2⁵⁰ − 2⁵⁰ = **0**。數學上應該是 2¹⁰。
- 【口頭】聰明的 compiler 可能會**重排運算順序**來提高精度，但那可能不是程式設計師要的。這是一個灰色地帶。
- 重點：**浮點數運算是近似的**，因為位元數有限，只能表示有限的數。

【課本補充】

- 換個順序 C = B + (A − A) 就對了。所以浮點數運算**不滿足結合律**（括號位置很重要），但**滿足交換律**（A + B = B + A）。
- 有些數在某個進位制能精確表示、在另一個不行：1/7 在 7 進位很簡單，在 2 進位就不精確。
- **無理數**（√2、π）在任何進位制都表示不了，因為浮點數本質上是有理數。但 mantissa 位元夠多，就能任意接近。

§14.1 實測：float 下 (B + A) − A = 0；double 下 = 1024（double 有 52 位元 mantissa，2⁻⁴⁰ 表示得了）。

## 11. 字串：ASCII

[42:46]–[45:08]　課本 §2.5.1（p.82）

- **字串（string）**：一段文字，一串字元。
- **ASCII**（American Standard Code for Information Interchange）：**128 個字元**，每個用 **7 位元**編碼。
- 前 **32 個**是**不可列印**的控制字元，原本用來控制印表機：
  - 8：backspace（刪掉一個字元）
  - 10：line feed（換行；叫印表機跳到下一行）
  - 27：escape（鍵盤上的 Esc）
- 之後是標點符號、數字、大寫字母、小寫字母：

| 範圍 | 編碼 |
|---|---|
| `0`～`9` | 48～57 |
| `A`～`Z` | 65～90 |
| `a`～`z` | 97～122 |

- 【課本補充】大部分語言用 **8 位元**存一個 ASCII 字元，所以 MSB 浪費掉了。
- 【課本補充】第 0 個字元是 **null 字元**，C 語言用它來**結束字串**。
- ASCII 的問題：只適合**英文**。英文字元少，也沒有其他語言的特殊符號和組合字。

## 12. Unicode：UTF-8、UTF-16、UTF-32

[45:08]–[48:07]　課本 §2.5.2–2.5.3（p.82–83）

- **UTF**（Universal character set Transformation Format）。
- 【口頭】投影片上寫了幾個不同語言的字：印地語（Devanagari 天城文）、坦米爾語、可能是韓文、卡納達語。
- **UTF-8**：
  - 大約可以編碼一百萬個字元。【課本補充】精確數字是 **1,112,064** 個。
  - **和 ASCII 相容**：前 128 個字元就是 ASCII，只要 **1 byte**，最高位是 0。
  - 法文、德文、西班牙文（羅馬字母的變體）要 2 byte；希臘文、俄文、希伯來文、阿拉伯文也是 2 byte。
  - 現在所有瀏覽器和作業系統的標準。
- 【課本補充】UTF-8 的多 byte 格式：第一個 byte 用「前面幾個 1，接一個 0」表示總共幾個 byte。例：`1110xxxx` 表示 3 byte。後續的每個 byte 都以 `10` 開頭。§14.3 實測。
- **UTF-16**：2 或 4 byte。Java 和 Windows 用它。
- **UTF-32**：每個字元固定 4 byte，很少用（浪費空間）。
- 顯示時，文書處理程式把 byte 轉回字元，再為每個字元畫出對應的小圖（glyph）。

⚠️ 影片和課本這段有幾個說法和實測不符：
- **長度**：影片和課本 §2.5.2 都說 UTF-8 用「**1～6 byte**」。但課本自己的 Summary 2 第 12 點又寫「**1～4 byte**」。實測（§14.3）：最大的 Unicode 字元 U+10FFFF 只要 4 byte；5 byte 的序列會被 Python 拒絕（invalid start byte）。現行的 UTF-8 最多 4 byte。
- **誰比較流行**：影片 [47:02] 說「UTF-8 已經被 UTF-16 和 UTF-32 取代」「UTF-16 比較流行」，課本 §2.5.3 也這樣寫。但課本 §2.5.2 又說 UTF-8「是全球資訊網的標準」「截至 2012 年是最流行的編碼」。本機的 locale 是 `en_US.UTF-8`，Linux 預設就是 UTF-8。

## 13. Chapter 2 總結

[48:07]–[51:04]

- **Boolean algebra**：用位元做邏輯運算。
- **正整數、負整數**：最後選 2's complement，目前最有效的負整數表示法。
- **浮點數**：要另外表示 exponent，所以換了不同的表示法。
- 【口頭】**本章重要的一課**：「在計算機結構裡，有時候要**退一步、讓事情變簡單**。」浮點數的 exponent 沒用 2's complement 而用 bias，符號也用明確的 sign bit，都是為了簡單，也利用了「通常不會拿 exponent 去乘」這個規律（只有 x^y 這種很少見的運算才需要）。
- **字串**：英文用 ASCII；全世界的語言用 Unicode（UTF-8、UTF-16），還有很多「卡通般的字元」（emoji）。
- 下一章：設計一種低階語言，用位元和處理器溝通，完成複雜的工作 → **組合語言**。

## 14. 【實測】

本機：Intel i7-13650HX、Ubuntu、kernel 6.5.0、gcc 11.4（x86-64）、Python 3.10。程式在 `experiments/lecture05/`。

### 14.1 IEEE 754 的位元長什麼樣

`fp.c` 用 `memcpy` 把 float 的 32 個位元拿出來，拆成 S、E、M：

```
$ gcc -O2 -Wall -o fp fp.c -lm && ./fp
-3.0         C0400000  S=1 E=128 M=0x400000  (-3)
1.0          3F800000  S=0 E=127 M=0x000000  (1)
17.625       418D0000  S=0 E=131 M=0x0D0000  (17.625)
+0           00000000  S=0 E=  0 M=0x000000  (0)
-0           80000000  S=1 E=  0 M=0x000000  (-0)
+inf         7F800000  S=0 E=255 M=0x000000  (inf)
nan          FFC00000  S=1 E=255 M=0x400000  (-nan)
FLT_MIN      00800000  S=0 E=  1 M=0x000000  (1.17549e-38)
FLT_MAX      7F7FFFFF  S=0 E=254 M=0x7FFFFF  (3.40282e+38)
min denorm   00000001  S=0 E=  0 M=0x000001  (1.4013e-45)
max denorm   007FFFFF  S=0 E=  0 M=0x7FFFFF  (1.17549e-38)
g = f/2 = 5.87747e-39, g == 0 ? no
float  (B+A)-A = 0,  B+(A-A) = 1024
double (B+A)-A = 1024
nan == nan ? 0,  nan - nan = -nan
-0 == +0 ? 1
1.11f = 1.1100000143
```

- **−3.0 = `C0400000`**：S = 1、E = 128、M 最高位是 1，和 §7 手算的一模一樣。
- 17.625 = 10001.101 = 1.0001101 × 2⁴ → E = 131，M = `0001101 0…` = 0x0D0000。
- **兩個 0**：`00000000` 和 `80000000`，但 `-0 == +0` 是真的。
- **FLT_MIN** = E 是 1、M 是 0 = 2⁻¹²⁶；**FLT_MAX** = E 是 254、M 全是 1 = 2¹²⁸ − 2¹⁰⁴ ≈ 3.4 × 10³⁸。
- **最小 denormal** 只有最低位是 1 = 2⁻¹⁴⁹ ≈ 1.4 × 10⁻⁴⁵；**最大 denormal** M 全是 1，印出來和 FLT_MIN 幾乎一樣，只差 2⁻¹⁴⁹。
- **g = f/2** 得到 5.9 × 10⁻³⁹，是一個 denormal，**不是 0**。
- **NaN == NaN 是假的**：NaN 和任何東西比較都是不相等，連自己都不等於自己。
- x86 上 0/0 產生的 NaN 符號位是 1（`FFC00000`，印成 `-nan`），這是 x86 預設的「QNaN indefinite」。課本說 NaN 的 M 值不重要，符號也一樣不重要。

### 14.2 Flush-to-zero：沒有 denormal 會怎樣

```
$ gcc -O2 -ffast-math -o fp_fast fp.c -lm && ./fp_fast | grep "g = f/2"
g = f/2 = 0, g == 0 ? error
```

- `-ffast-math` 讓 gcc 在程式啟動時打開 x86 SSE 的 **FTZ**（flush-to-zero）和 **DAZ**（denormals-are-zero），為了速度把 denormal 當成 0。
- 結果就是課本 §2.4.4 說的「數學謬誤」：一個正數除以 2 變成 0，程式印出 error。
- 這也呼應課本說的「denormal 處理很慢，有些處理器乾脆不支援」。

### 14.3 UTF-8、UTF-16、UTF-32 的長度

```
$ python3 utf.py
U+000061 utf8=1B 01100001                                 utf16=2B utf32=4B
U+0000E9 utf8=2B 11000011 10101001                        utf16=2B utf32=4B
U+000416 utf8=2B 11010000 10010110                        utf16=2B utf32=4B
U+000915 utf8=3B 11100000 10100100 10010101               utf16=2B utf32=4B
U+004E2D utf8=3B 11100100 10111000 10101101               utf16=2B utf32=4B
U+01F600 utf8=4B 11110000 10011111 10011000 10000000      utf16=4B utf32=4B
U+10FFFF utf8=4B 11110100 10001111 10111111 10111111      utf16=4B utf32=4B
ord('A'), ord('a'), ord('0') = 65 97 48
5-byte sequence: invalid start byte
```

| 字元 | 語言 | UTF-8 | UTF-16 | UTF-32 |
|---|---|---|---|---|
| a | 英文（ASCII） | 1 | 2 | 4 |
| é | 法文 | 2 | 2 | 4 |
| Ж | 俄文 | 2 | 2 | 4 |
| क | 印地文（天城文） | 3 | 2 | 4 |
| 中 | 中文 | 3 | 2 | 4 |
| 😀 | emoji | 4 | 4 | 4 |
| U+10FFFF | Unicode 最後一個 | **4** | 4 | 4 |

- 看得到 UTF-8 的規則：1 byte 的開頭是 `0`；2 byte 的第一個 byte 是 `110…`；3 byte 是 `1110…`；4 byte 是 `11110…`；後續的 byte 全部以 `10` 開頭。
- 法文、俄文 2 byte，和課本說的一樣。
- 最大的字元也只要 4 byte；5 byte 的序列是無效的。所以「1～6 byte」是舊的說法。
- 中文在 UTF-8 要 3 byte，在 UTF-16 只要 2 byte。所以亞洲文字為主的文件用 UTF-16 比較省；英文為主的文件用 UTF-8 比較省。

| 主題 | 重點 |
|---|---|
| Fixed point | 小數點後位數固定（錢）；存成整數；乘除難 |

| Normal form | (−1)^S × (1 + M) × 2^X，0 ≤ M < 1 |
| Significand／mantissa | 1.xxx 整個／只有 .xxx |
| IEEE 754 float | 1 S ＋ 8 E ＋ 23 M；隱含的 1 不存 |
| Exponent | bias 127；E = X + 127；normal 的 E 是 1～254，X 是 −126～127 |
| 為什麼用 bias | 指數只做加減；比 2's complement 簡單 |
| 特殊值 | E=255,M=0：±∞；E=255,M≠0：NaN；E=0,M=0：±0；E=0,M≠0：denormal |

| 範圍 | 最大 2¹²⁸ − 2¹⁰⁴ ≈ 3.4×10³⁸；最小 normal 2⁻¹²⁶ |
| Denormal | (−1)^S × (0 + M) × 2⁻¹²⁶；範圍 [2⁻¹⁴⁹, 2⁻¹²⁶ − 2⁻¹⁴⁹]；接上 normal |
| Double | 1 ＋ 11 ＋ 52；bias 1023；X 是 −1022～1023；≈ ±10³⁰⁸ |

| UTF-8 | 相容 ASCII；1～4 byte；首 byte 的前導 1 個數 = 長度；後續 byte 是 10xxxxxx |
| UTF-16／32 | 2 或 4 byte（Java、Windows）／固定 4 byte |
| 設計原則 | 有時要退一步，讓事情變簡單 |

## 附：本講一句話總結

> **浮點數就是帶小數點的數：把十進位展開式的 10 換成 2，再化成 normal form (−1)^S × (1 + M) × 2^X，IEEE 754 單精度用 1 位元符號、8 位元 bias 127 的指數（指數只做加減，用 bias 比 2's complement 簡單）、23 位元 mantissa（隱含的 1 不存），normal 指數是 −126 到 127，E = 255 留給 ±∞（M = 0）和 NaN（M ≠ 0），E = 0 留給 ±0 和 denormal；denormal 把隱含的 1 換成 0、指數固定 −126，最大的 denormal 2⁻¹²⁶ − 2⁻¹⁴⁹ 正好接上最小的 normal 2⁻¹²⁶，避免 2⁻¹²⁶/2 變成 0（實測開 -ffast-math 的 flush-to-zero 後就真的變成 0）。Double 是 1 + 11 + 52 位元、bias 1023。浮點運算是近似的，(2⁵⁰ + 2¹⁰) − 2⁵⁰ 在 float 是 0，所以不滿足結合律。文字用 7 位元 128 字元的 ASCII，全世界的語言用 Unicode：UTF-8 相容 ASCII、實測最多 4 byte（影片與課本說的「1～6 byte」是舊說法，課本自己的摘要也寫 1～4），UTF-16 用 2 或 4 byte，UTF-32 固定 4 byte。**
