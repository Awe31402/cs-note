| Sign-magnitude | 兩個 | 難 | 難 | ✗ |

## 1. 問題：怎麼用 0 和 1 表示負數

[00:46]–[04:44]　課本 §2.3（p.65）

- 給一個有號數 u，它的二進位形式是 xₙ…x₁（x₁ 是 LSB，最低位；xₙ 是 MSB，最高位）。
  - 【口頭】「從現在開始，位元編號從 1 開始算，不是從 0。」
- 同一串位元可以有兩種解讀：當**無號數**（unsigned，假設是正的）得到 N，或當**有號數**得到 S。
- 所以我們要找一個**映射函數** F : S → N，把每個有號數對到一個無號數（也就是一串位元）。
- 對 F 的期望：
  1. **一對一**：每個有號數只有一種表示法。
  2. S 裡的每個數都要被對到。
  3. **算術要容易**：加減法好做。
- 定義 **SgnBit(u)**：u < 0 時是 1，u ≥ 0 時是 0。
- 假設是 **n-bit 數字系統**：每個數都用 n 個位元表示。

## 2. Sign-magnitude

[04:44]–[07:32]　課本 §2.3.1（p.65）

最直覺的做法：拿一個位元當**符號位**，其餘當大小。

```
F(u) = SgnBit(u) × 2ⁿ⁻¹ + |u|
```

- 例子（4 位元）：
  - +5 = `0101`，−5 = `1101`（+5 前面的 0 換成 1）
  - −3 = `1011`
- 問題：
  1. **0 有兩種表示**：`0000`（+0）和 `1000`（−0）。
  2. **加減法難**：直接用二進位加法會錯。
- 【課本補充】課本的例子：−2 + 2 = `1010` + `0010` = `1100`，這是 −6，錯了。範圍是 ±(2ⁿ⁻¹ − 1)。
- 【口頭】結論：符號位有它的好處，但「帶來的問題比解決的還多」。

## 3. 1's complement

[07:32]–[15:17]　課本 §2.3.2（p.65–66）

負數就把正數的**每個位元都反過來**。

```
F(u) = u                     (u ≥ 0)
F(u) = ~|u| = 2ⁿ − 1 − |u|   (u < 0)
```

- 例子：+3 = `0011` → −3 = `1100`；+5 = `0101` → −5 = `1010`。
- 符號位的概念**自然出現**了：正數 MSB 是 0，負數 MSB 是 1。但沒帶來更多數學性質。
- **為什麼 ~x = 2ⁿ − 1 − x**（[13:09]）：對一個位元，~x = 1 − x（x = 0 → 1，x = 1 → 0）。2ⁿ − 1 是 n 個 1（4 位元是 15 = `1111`），所以用 `1111` 減任何數，每一位都是 1 − xᵢ，就是取反。
- 問題：
  1. **0 有兩種表示**：`0000` 和 `1111`。
  2. 正數相加沒問題（3 + 2 = `0011` + `0010` = `0101` = 5）。但**加負數就錯**。
- 影片的例子（[10:47]）：3 + (−2) = `0011` + `1101` = `1 0000`，留下 `0000`，還多一個進位。答案應該是 1。
- 【課本補充】課本的例子更直接：−0 + 1 = `1111` + `0001` = `0000`，**零加一還是零**，數學上矛盾。
- 【口頭】但「取補數」這個點子本身有價值，後面會用到。

## 4. Bias-based

[15:17]–[18:30]　課本 §2.3.3（p.66）

```
F(u) = u + bias
```

- 例子（4 位元，bias = 7）：
  - −3 → −3 + 7 = 4 = `0100`
  - +3 → 3 + 7 = 10 = `1010`
- 【口頭】「這會用在另一種數字系統裡，之後有機會講。」（就是下一講浮點數的指數。）
- **加法**：F(u + v) = F(u) + F(v) − bias。
  - 影片例子：3 + (−3) → `1010` + `0100` = 14，減 bias 7 = 7 = F(0)。答案正確。
- **減法**：加回 bias 就好，也容易。
- 優點：0 只有一個表示法（就是 bias 本身，`0111`）；加減法容易。
- 缺點：**乘法難**。
  - 【課本補充】原因：(A + bias) × (B + bias) 很難還原出 AB。
- 【課本補充】課本寫 bias = 7 時範圍是 **−7 到 +8**（0 到 15 各減 7）。

## 5. 2's complement 與 number circle

[18:30]–[28:05]　課本 §2.3.4（p.67–69）

要求整理（課本列的三點）：表示法要簡單；有號運算要能用**和無號數一樣的硬體**；0 只能有一種表示。

**Number circle（數字圓）**

先把 4 位元的無號數 0～15 排成一個圓（課本 Figure 2.6）：

- 順時針走一步 = 加 1；逆時針 = 減 1。
- 15 和 0 之間有一個**不連續點**。

然後把 8～15 改成 **−8～−1**（課本 Figure 2.7）：

```
                0000 (0)
       1111 (-1)        0001 (1)
   1110 (-2)                0010 (2)
 1101 (-3)                    0011 (3)
 1100 (-4)     順時針 = +1     0100 (4)
 1011 (-5)                    0101 (5)
   1010 (-6)                0110 (6)
       1001 (-7)        0111 (7)
                1000 (-8)
                  ↑ break point（7 和 −8 之間）
```

- 現在 −1 和 0 之間是**連續的**；不連續點移到 7 和 −8 之間，叫做 **break point**（Definition 21）。
- 兩個性質：
  1. 除了 break point，**順時針走就是加 1**。
  2. 符號位的概念保留了：正數 MSB 是 0，負數 MSB 是 1。

**最關鍵的一點**（[23:14]）：

> 在 n 位元系統裡，**逆時針走 m 步 = 順時針走 2ⁿ − m 步**。
> 例：從 4 逆時針走 2 步，和順時針走 14 步，到同一個地方。

- 越過 break point 就是 **overflow**（數字太大或太小，表示不了）。

**定義**（Equation 2.12）：

```
F(u) = u          (0 ≤ u ≤ 2ⁿ⁻¹ − 1)
F(u) = 2ⁿ − |u|   (−2ⁿ⁻¹ ≤ u < 0)
```

- 為什麼負數是 2ⁿ − |u|？例：−5 = 0 − 5，從 0 逆時針走 5 步 = 順時針走 11 步，所以表示法是 11 = `1011`。
- 例子：+4 = `0100`；−4 = 16 − 4 = 12 = `1100`；+5 = `0101`；−3 = 16 − 3 = 13 = `1101`。

【課本補充】Definition 20：**overflow** = 數字太大，表示不了；**underflow** = 數字太小，表示不了。課本有時用 overflow 同時指兩者。

## 6. 2's complement 的性質

[28:05]–[36:10]　課本 p.70

1. **範圍**：−2ⁿ⁻¹ 到 2ⁿ⁻¹ − 1（4 位元是 −8 到 +7）。負數**多一個**，因為 0 要占一個正數的位置。
2. **0 只有一種表示**：全部是 0。
3. **MSB 就是符號位**：看 MSB 就知道正負。
   - 證明：負數的表示法 ≥ 2ⁿ⁻¹（越過了 break point），所以 MSB 是 1；正數 < 2ⁿ⁻¹，MSB 是 0。
4. 範圍內每個數都有**唯一**的表示法（圓上唯一的一點）。

**≡ 運算子**（[30:42]）：

```
a ≡ b   ⟺   a mod 2ⁿ = b mod 2ⁿ
```

- 意思是 a 和 b 是數字圓上的**同一點**。
- 例：4 位元系統裡 3 ≡ 19，因為從 3 順時針走 16 步又回到 3。
- 【課本補充】mod 2ⁿ 的物理意義：只留**最低 n 位**，其他丟掉。硬體本來就是這樣做的。

**Negation rule（取負）**（[32:14]）：

```
F(−u) ≡ 2ⁿ − F(u)
```

- 例：F(−4) = 16 − F(4) = 12 = `1100`。
- **這就是為什麼叫「2's complement」**：用 2ⁿ 去減。
- 證明（number circle）：−u 是從 0 逆時針走 u 步 = 順時針走 2ⁿ − u 步。

## 7. 加法、減法、乘法

[36:10]–[47:07]　課本 p.70–72

**Addition rule**：

```
F(u + v) ≡ F(u) + F(v)
```

- 意思：**兩個表示法直接做普通的二進位加法，結果就是答案的表示法**。
- 證明：從 F(u) 出發。v ≥ 0 就順時針走 v = F(v) 步；v < 0 就逆時針走 |v| 步 = 順時針走 2ⁿ − |v| = F(v) 步。兩種情況都是「F(u) + F(v)」。
- 例：2 + 3 = `0010` + `0011` = `0101` = 5。
- 例：2 + (−4) = `0010` + `1100` = `1110` = 14 = F(−2)。正確。
- 【課本補充】Example 15：4 + (−3) = `0100` + `1101` = `10001`，硬體丟掉第 5 位，得到 `0001` = 1。

**Subtraction rule**：

```
F(u − v) ≡ F(u) + (2ⁿ − F(v))
```

- **減法就是加上 v 的 2's complement**，所以只要有加法器就夠了。
- 例：3 − 5 = 3 + (16 − 5) = 14 = F(−2)。

**Multiplication rule**（[43:14]，假設沒有 overflow）：

```
F(u × v) ≡ F(u) × F(v)
```

- 【口頭】「Food for thought：乘法也成立嗎？」答案：**成立**。除法**不成立**。
- 例：2 × (−3) → F(2) × F(−3) = 2 × 13 = 26 ≡ 10（mod 16，只留低 4 位）= F(−6)。正確。
- 證明（兩個都負的情況）：(2ⁿ − |u|)(2ⁿ − |v|) 展開後，含 2ⁿ 的項 mod 2ⁿ 都消掉，剩 |u| × |v|。
- 【口頭】一正一負的情況「留給讀者當練習」。
- 【課本補充】課本把一正一負的情況也證完了，用到 **loop rule**：F(u) ≡ 2ⁿ + F(u)（繞圓一圈回到原點）。
- ⚠️ 課本 Equation 2.17 的第二行印成 `2^{n+1} − 2ⁿ(F(|u|) + F(|v|) + F(|u|)×F(|v|)`。正確展開應該是 **2²ⁿ − 2ⁿ(F(|u|) + F(|v|)) + F(|u|)×F(|v|)**：指數是 2n 不是 n+1，而且括號位置不對。結論（≡ F(|u|)×F(|v|)）不受影響，因為前兩項 mod 2ⁿ 都是 0。

## 8. 快速算 2's complement：取反加一

[47:07]–[49:24]　課本 Equation 2.19（p.72）

```
2ⁿ − u = (2ⁿ − 1 − u) + 1 = (~u) + 1
```

- 2ⁿ − 1 − u 就是 1's complement（§3），所以：

> **取負 = 每個位元取反，再加 1。**

- 例：−4：`0100` → 取反 `1011` → 加 1 → `1100`。

## 9. Sign extension

[49:24]–[56:40]　課本 p.72

問題：把 n 位元的數轉成 m 位元（m > n），例如 4 位元轉 8 位元。

- **正數**：前面補 m − n 個 **0**。+4 = `0100` → `0000 0100`。
- **負數**：前面補 m − n 個 **1**。−4 = `1100` → `1111 1100`（= 252 = 256 − 4，對了）。

為什麼負數要補 1：

```
Fₘ(−u) = 2ᵐ − u = (2ᵐ − 2ⁿ) + (2ⁿ − u)
                 = 11…1 00…0  +  Fₙ(−u)
                   (m−n 個 1)(n 個 0)
```

- 2ᵐ − 2ⁿ 寫成二進位，就是高 m − n 位全是 1、低 n 位全是 0。
  - 【口頭】例：2⁴ − 2² = 16 − 4 = 12 = 2² + 2³ = `1100`。
- 加上原本的 n 位元表示法，就等於在前面補一串 1。

> **Sign extension**：不管正負，**把符號位（MSB）複製到新增的高位**。

- 【課本補充】課本用 16 位元轉 32 位元當例子：補 16 個符號位。

## 10. Overflow 定理

[56:40]–[64:34]　課本 Theorem 2.3.4.1（p.73）

- 例：4 位元裡 5 + 5 = 10，但最大只到 +7 → **overflow**。−5 + (−5) = −10，最小只到 −8 → 也 overflow。
- **越過 break point 才會 overflow**。

> **Overflow 定理**：
> - u、v **異號**（uv < 0）或其中一個是 0 → **永遠不會** overflow。
> - u、v **同號** → 可能 overflow；**結果的符號和 u、v 不同**時就是 overflow。

**證明的直覺**（[60:48]）：

- 異號時，要越過 break point，至少要走過 0、break point、全部的正數（或負數），也就是 2ⁿ⁻¹ + 1 步。但範圍內的 |v| 都比這小，所以走不到。
- 【口頭】「最有機會的情況」：u 盡量小（0）、|v| 盡量大（−4）。0 + (−4) 還是在範圍內，沒越過。
- 同號時，結果**不可能**越過 break point 又回到同號那一半：同樣要走太多步。所以只要看結果的符號。

⚠️ 影片 [58:40] 之後改用一個較小的數字圓舉例（1 + 3、−3 + (−2)），逐字稿說是「2 bit number system」。但這些例子的數字要 **3 位元**（範圍 −4～+3）才對得上：

- 1 + 3 = `001` + `011` = `100` = −4（應該是 +4）→ overflow
- −3 + (−2) = `101` + `110` = `011` = +3 → overflow

（在 4 位元裡，−3 + (−2) = −5 是正常的，§13.1 實測。）

⚠️ 影片說「結果的符號和兩個運算元**不同**」就是 overflow。課本的定理多寫了一句：「結果符號相反**或結果是 0**」。差在 **−8 + (−8)**：`1000` + `1000` = `0000`，結果是 0（不算負也不算正），但確實 overflow 了。§13.1 實測。

## 11. 【課本補充】另一種解讀：MSB 的權重是 −2ⁿ⁻¹

課本 Theorem 2.3.4.2（p.73），影片沒講。

> 一個 n 位元的有號數 A = A₁…ₙ₋₁ − Aₙ × 2ⁿ⁻¹
> （低 n−1 位照無號數算，MSB 的權重是 **負的** 2ⁿ⁻¹）

- 例：−2 = `1110`。低 3 位 `110` = 6，MSB 代表 −8。6 − 8 = −2。對了。
- 好用的地方：看一個二進位數，不用先取反加一，直接加權就能算出值。

## 12. 【原始碼】Linux 的 sign_extend32 與 check_add_overflow

Kernel 常常要把硬體暫存器裡的「k 位元有號欄位」擴展成 32 位元。`include/linux/bitops.h:186-190`：

```c
static __always_inline __s32 sign_extend32(__u32 value, int index)
{
	__u8 shift = 31 - index;
	return (__s32)(value << shift) >> shift;
}
```

- 先左移，把欄位的符號位（第 `index` 位）推到第 31 位（MSB）。
- 再轉成**有號**數右移。有號數右移是**算術右移**（arithmetic shift），會把 MSB 複製進來，正好就是 §9 的 sign extension。
- 例：`sign_extend32(0xC, 3)`：4 位元的 `1100` → 左移 28 位 → `0xC0000000` → 算術右移 28 位 → `0xFFFFFFFC` = −4。

Overflow 檢查，`include/linux/overflow.h:66-67`：

```c
#define check_add_overflow(a, b, d)	\
	__must_check_overflow(__builtin_add_overflow(a, b, d))
```

- 直接用 gcc 的 `__builtin_add_overflow`。在 x86 上，它編譯出來就是 `add` 之後看 **OF（overflow flag）**。OF 的硬體規則正是 §10 的定理：同號相加、結果異號。
- 為什麼 kernel 要特別包一層？因為 C 語言裡**有號整數 overflow 是 undefined behavior**（§13.3），不能事後用「結果變負了」去檢查。

## 13. 【實測】

本機：Intel i7-13650HX、Ubuntu、kernel 6.5.0、gcc 11.4（x86-64）。程式在 `experiments/lecture04/`。

### 13.1 4 位元 2's complement 的加法與乘法

`twos.c` 用 `& 0xf` 模擬 4 位元系統（只留低 4 位 = mod 16），overflow 用課本的定理判斷：

```
$ gcc -O2 -Wall -o twos twos.c && ./twos
  2 +  -4 : 2 + C = E →  -2
  4 +  -3 : 4 + D = 1 →   1
  5 +   5 : 5 + 5 = A →  -6  overflow
 -5 +  -5 : B + B = 6 →   6  overflow
 -8 +  -8 : 8 + 8 = 0 →   0  overflow
 -3 +  -2 : D + E = B →  -5
2 * -3 : 2 * D = A → -6
-4 as int8 = 0xFC, as int32 = 0xFFFFFFFC
~4 + 1 = -4
INT32_MAX + 1 overflow? 1
```

- 影片的 2 + (−4) = −2、課本的 4 + (−3) = 1、影片的 2 × (−3) = −6：直接用無號加法、乘法就對了。
- 5 + 5 和 −5 + (−5)：同號相加、結果異號 → overflow。
- **−8 + (−8) = 0**：結果是 0，只看「符號不同」會漏掉。這就是課本定理多寫「或是 0」的原因。
- −3 + (−2) 在 4 位元是 −5，沒有 overflow（影片的 overflow 例子是 3 位元的）。
- −4 從 8 位元擴成 32 位元：`0xFC` → `0xFFFFFFFC`，前面補的都是 1（sign extension）。

### 13.2 硬體怎麼做 sign extension

```c
int sext(signed char c) { return c; }
int zext(unsigned char c) { return c; }
```

```
$ gcc -O2 -c ub.c && objdump -d --no-show-raw-insn ub.o
<sext>:  movsbl %dil,%eax     ← move with sign extension（補符號位）
<zext>:  movzbl %dil,%eax     ← move with zero extension（補 0）
```

- x86 有專門的指令：`movsx`（AT&T 語法寫成 `movsbl`）做 sign extension，`movzx`（`movzbl`）補 0。
- 同樣一個 byte，C 型別是 `signed` 還是 `unsigned`，決定 compiler 選哪一條。

### 13.3 有號 overflow 在 C 裡是 undefined behavior

```c
int always(int x) { return x + 1 > x; }
```

```
$ gcc -O2 -c ub.c          → mov $0x1,%eax; ret          （直接回傳 1）
$ gcc -O2 -fwrapv -c ub.c  → cmp $0x7fffffff,%edi; setne %al   （x 是 INT_MAX 時回傳 0）
```

- 硬體上 INT_MAX + 1 會**繞到 −2³¹**（越過 break point）。所以 x = INT_MAX 時，`x + 1 > x` 應該是假的。
- 但 C 標準說有號 overflow 是 undefined behavior，所以 gcc 可以假設它不會發生，**直接把整個比較變成「永遠是真」**。
- 加 `-fwrapv`（告訴 gcc「有號數照 2's complement 繞圈」）之後，gcc 才乖乖檢查 x 是不是 INT_MAX。
- Linux kernel 就是用 `-fno-strict-overflow` 編譯的（`Makefile:1073`），理由一樣。

## 14. 一頁速查表

| 主題 | 重點 |
|---|---|
| Sign-magnitude | F(u) = SgnBit × 2ⁿ⁻¹ + \|u\|；兩個 0；加法錯 |
| 1's complement | 負數 = 每位取反 = 2ⁿ − 1 − \|u\|；兩個 0；加負數錯 |
| Bias | F(u) = u + bias；一個 0；F(u+v) = F(u)+F(v)−bias；乘法難 |
| 2's complement | F(u) = u（u ≥ 0）或 2ⁿ − \|u\|（u < 0） |
| Number circle | 順時針 +1；逆時針 m 步 = 順時針 2ⁿ − m 步；break point 在 2ⁿ⁻¹−1 和 −2ⁿ⁻¹ 之間 |
| 範圍 | −2ⁿ⁻¹ ～ 2ⁿ⁻¹ − 1（負數多一個） |
| 符號 | MSB 就是符號位 |
| ≡ | a ≡ b ⟺ mod 2ⁿ 相等 ⟺ 低 n 位相同 |
| 取負 | F(−u) ≡ 2ⁿ − F(u) = ~F(u) + 1 |
| 加／減／乘 | 直接用無號運算，結果 mod 2ⁿ；除法不行 |
| Sign extension | 把 MSB 複製到新增的高位（x86：movsx） |
| Overflow | 異號或有 0 不會；同號相加、結果異號或為 0 就是 overflow |
| MSB 權重 | A = 低 n−1 位 − Aₙ × 2ⁿ⁻¹ |
| C 語言 | 有號 overflow 是 UB；`-fwrapv`、kernel 用 `-fno-strict-overflow` |

## 附：本講一句話總結

> **要用 0 和 1 表示負數，sign-magnitude 和 1's complement 都有兩個 0 而且加法會錯，bias-based 只有一個 0、加減容易但乘法難；2's complement 把 4 位元的 8～15 改成 −8～−1 排成數字圓，break point 移到 7 與 −8 之間，於是「逆時針 m 步 = 順時針 2ⁿ − m 步」，負數表示成 2ⁿ − |u|，0 只有一個、MSB 就是符號位，而且加、減、乘都能直接用無號硬體做（取負 = 取反加一）。轉成更寬的位元數時要把符號位複製到高位（sign extension，x86 的 movsx，Linux 的 sign_extend32）；異號相加不會 overflow，同號相加結果異號或為 0 就是 overflow（實測 −8 + (−8) = 0 正是影片漏掉的「為 0」情況）。影片後段 overflow 的例子其實是 3 位元系統；課本 Eq 2.17 的展開式指數印錯；而 C 語言把有號 overflow 當成 undefined behavior，gcc -O2 會把 x + 1 > x 直接最佳化成 1。**
