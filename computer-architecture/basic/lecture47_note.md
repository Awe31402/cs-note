## 1. 什麼是計算機結構

[00:00] 計算機結構研究的是**處理器（processor）和計算機系統**。手機、桌機、筆電、Amazon 和 Netflix 的大型伺服器，現在還有智慧手錶、智慧感測器，全部都算。

[01:07] 它們什麼都做：財務計算、遊戲、氣象預報、跟世界另一邊的朋友聯絡。【口頭】老師舉例：印度很紅的 app 之一是占星，以前要找占星師，現在電腦就能幫你排命盤。

[02:07] 電腦的核心是**處理器（CPU）**，像是電腦的大腦。旁邊接著很多周邊：網路、鍵盤、滑鼠、USB、螢幕、印表機、硬碟。⚠️ 投影片上把硬碟寫成 network，老師說「腦中把它擦掉，當成硬碟」。

[03:29] 老師說這個領域在工作、創新、創業上都很有潛力。

## 2. 古代的計算：會計師與算盤

[03:45] 從 3000 年前說起。人類用數學，一開始主要是為了**記帳**：土地紀錄、付款紀錄、牲口紀錄（「我借你 20 隻羊，你還我 30 隻」）。

[04:55] 古人在腦中「寫程式」：對帳、算支出、預測需求。例如村子今年 1000 人、5 年後預估 2000 人，水和糧食夠不夠？這就是計算：有數學運算，也有做決定。

[05:40] 投影片上是一張古埃及會計師拿著象形文字卷軸的圖。

[06:26] 很多史學家說大約 3000 年前，**算盤（abacus）**在中國出現。用珠子的組合就能很快做很多運算，是一種機械式的計算方法。【口頭】現在中國北方、俄羅斯、蒙古還有老人在用，旁邊有計算機也照樣用算盤，因為從小用、比較快。

## 3. Analog、機械、水的計算機

### 3.1 Analog computer

[08:01] 老師說算盤之後兩千年，數字計算沒什麼進展，直到**電流**被發現。

[08:35] 有了電流，就能做很簡單的計算：

| 運算 | 做法 | 物理定律 |
|---|---|---|
| 加法 | 把兩個電流接在一起：I = I₁ + I₂ | Kirchhoff 定律 |
| 乘法 | 控制電流和電阻：V = I × R | Ohm 定律 |
| 除法 | 控制電壓和電阻：I = V / R，輸出是電流 | Ohm 定律 |

[09:34] 這就是 **analog computer（類比計算機）**的想法：20 世紀初發展，大約用到 1940–60 年代。只能做加減乘除，沒有現代程式語言那些複雜的結構，但很多事情夠用了。

⚠️ [10:10] 老師說「1969 年把人送上月球的是 analog computer，不是 digital computer」。課本沒有提到這件事，這份筆記不引用外部資料，**待查證**。

### 3.2 機械計算機

[11:12] 用一組**齒輪**做的計算機。齒輪是固定接好的（hardwired），專門解一種數學問題，例如比例和乘積：轉一個齒輪 R₁ 圈，另一個會轉 R₂ 圈，量另一個齒輪轉了多少就得到答案。

[12:07] 老師說希臘人在西元前 3、4 世紀就用過；19 世紀後期和 20 世紀是機械計算機的全盛期。Blaise Pascal、Charles Babbage 在 1600、1800 年代做的機器，很大程度受這類機械計算機啟發。

[12:44] 缺點：很難存 state（狀態，見 §4）；要用力氣推；又大、又重、又慢（被機械速度限制）。

### 3.3 Water computer

[13:18] **水的計算機**：用水流代替電子流。大約 1950–70 年代發展，投影片的照片是 1970 年代末、80 年代初的蘇聯（USSR）。原理：水庫、幫浦、進水口、出水口、閥門，最後看小窗裡的水位就是答案。

⚠️ [14:23] 老師一下說是蘇聯的設計，一下說「我相信這張照片是在法國某個計畫拍的，請上 Wikipedia 查」。來源不確定。

## 4. State 與 logic

[10:25] Digital computer 內部用 0 和 1 存資料，所以有 **state** 的概念。

> **State（狀態）**：系統的一種設定，沒有外力就不會改變。例如一個 transistor 的狀態是 0，你對它做了什麼它才變成 1，再做一次才變回 0。

[10:43] 很多早期的計算機沒有 state：給兩個數，它加完就給你。但你沒辦法說「只有上一次加的結果小於 15，才做這次加法」。

[14:56] 這些計算機（analog、機械、水）基本上都是**數字處理器**：拿一組數字，做一些算術。例如拿 A、B，算 B ÷ A，放進變數 result：

| 名詞 | 意思 | 例子 |
|---|---|---|
| **State** | 一組會長時間保持值的變數 | A、B、result |
| **Logic** | 運算 | 加、減、乘、除、sin、cos、exp |

[15:42] 計算機把程式當輸入，最後產生有意義的輸出。可以用水、槓桿、齒輪、電子來算，未來也許用更多種基本粒子（例如 quantum computer）。不管用什麼，都要**花能量**：動齒輪、動水花機械能，動電子花電能。

[16:27] 到 1900 年為止，大家知道：有一串要做的事（就是**程式**），也懂 state 和 logic 的分別。除此之外就不知道了。

## 5. Turing 與 Church-Turing thesis

[17:26] 1930–40 年代、二次大戰前後，**Alan Turing** 問了一個很基本的問題：

> 要實作**任何**程式，需要哪些基本運算？加減乘除夠不夠？會不會以後有一個工作，只靠這些運算就做不到？

[18:12] 老師說：Turing 是計算機科學之父，也是「史上最偉大的計算機架構師」，因為他回答了整個領域最重要的問題。

[18:42] **Church-Turing thesis**：Alan Turing 和 Alonzo Church 用很不一樣的方法說了同一件事，Turing 的版本比較有名：

> 一個函式，人用 algorithm（一串步驟）算得出來 ⟺ Turing machine 算得出來。

[19:30] 也就是：我們想得到的事，Turing machine 都做得到；Turing machine 做得到的，我們也想得到。

- 它是 **thesis（論點）**，不是 theorem（定理），**沒辦法證明**。
- 但 80 年來沒人找到反例。

[19:59] 【口頭】在那個年代這很驚人：一台這麼簡單的機器，竟然跟大家以為極度複雜的人腦一樣強。

[23:20] Church 的研究變成 **lambda calculus**，也是很重要的理論工具，但沒有 Turing 的研究用得那麼廣。

## 6. 從 Turing machine 到電晶體

### 6.1 Turing machine

[20:43] Turing machine 只有三樣東西：

| 部分 | 內容 |
|---|---|
| **Tape** | 往兩邊無限延伸，分成很多格（cell），每格放一個符號 |
| **Tape head** | 每個時間點指著某一格 |
| **State table** | 告訴機器下一步要做什麼 |

[21:15] 每一步只做三件事：

1. 讀 tape head 下面那格的符號。
2. 查 state table，照它說的，在這格寫一個新符號（或保留原來的）。
3. 把 tape head 往左或往右移一格。

【課本補充】課本 §1.6.2（p.23）有同樣的結構圖（Figure 1.6），還有「把數字加 1」的 Turing machine 例子；第 2 支 §8 有詳細說明。

### 6.2 von Neumann 機器

[22:32] von Neumann、Eckert、Mauchly 等人從 Turing machine 做出有 **CPU** 的機器：

| Turing machine | 現代電腦 |
|---|---|
| 讀符號、查 state table、移 tape head 的引擎 | **CPU** |
| Tape | **記憶體** |
| （沒有） | **I/O 裝置**（螢幕、印表機…），跟外界溝通 |

[33:20] 【口頭】老師後面又回頭說：compiler 產生的機器指令很簡單，「就像 Turing machine 的 state table」，笨笨的 CPU 也看得懂。

### 6.3 電晶體

[23:35] 理論有了，還需要做實驗的人。**1947 年，Bardeen 和 Brattain 發明了 transistor（電晶體）**：一個三隻腳的元件，像**用電控制的開關**。投影片上有早期插在麵包板上的三腳電晶體照片。

[24:21] 一開始電腦其實沒用電晶體，用的是**真空管**（triode、diode），概念上跟日光燈管差不多。到 1950、60 年代，理論和技術都到位了，電腦時代開始。

## 7. Moore's law 與 feature size

### 7.1 Moore's law

[24:53] Intel 共同創辦人 **Gordon Moore** 提出 Moore's law：

- 電晶體會決定計算機技術的演進。
- **每顆晶片上的電晶體數量大約每年翻倍。**

[25:11] 大約 55 年、一直到 2015 年左右都成立；後來從「每年」變成「每 1–2 年」，但一直在翻倍，像指數一樣成長。電腦變這麼強，就是因為電晶體一直變小。

⚠️ **年份**：影片說 Moore 在 **1961 年**提出（[24:53]），講到一半又說「1960」（[25:11]）；課本 §12.1.1（p.568）和 Historical Note 3 都說 **1965 年**。

【課本補充】課本 p.568：一開始真的是每年翻倍，後來慢到 18 個月，現在大約 2 年（跟影片一致）。

### 7.2 Feature size

[25:40] **Feature size**：矽晶片上能可靠做出來的**最小尺寸**，用來做電晶體。

- 每一代，feature size 縮小 **√2 倍**。
- 長和寬都縮 √2 → 面積變一半 → 晶片大小不變的話，**電晶體數量翻倍**。

[26:14] 影片給的數字：

| 年份 | 電晶體大約多寬 |
|---|---|
| 1980 | 1 µm（micron） |
| 2016 | 14 nm |
| 2020（錄影時） | 7 nm |
| 以後 | 5 nm，大概就到底了 |

[26:31] 為什麼 5 nm 是極限？一個原子大約 1 Å（0.1 nm），5 nm 只有大約 **50 個原子**寬。這些小電晶體快、小、省電，但已經快飽和了。

【課本補充】課本 Table 12.1（p.569）列了 Intel 2001–2011 的 feature size：130、90、65、45、32、22 nm，大約每 2 年縮 √2（1.41）倍。

### 7.3 電晶體數量的圖

[27:19] 一張 1970–2030 的 log 圖（資料到 2018）：Intel、AMD、Motorola 的處理器電晶體數。不管是早期微處理器、桌機、手機、伺服器，在 log 圖上都**穩定上升**。

[28:18] 從 **2,000 個到 20 億個**；很多現代晶片有 **100–150 億個**。我們現在玩的華麗遊戲，都是 Moore's law 的直接結果。

【課本補充】課本 p.568：1971 年一顆晶片大約 2000–3000 個電晶體；1960 年代電晶體的 channel length 有好幾 mm，現在大約 20–30 nm。

## 8. Performance equation

[28:33] 問題：今天的手機比 1970 年的超級電腦快多少？要回答，需要計算機結構裡「像牛頓定律一樣」的式子：**performance equation（效能公式）**。

[29:04] 第一件事：**沒有「電腦的效能」這種東西，只有「程式的效能」**。

- 同一個程式（例如下棋程式）在兩台機器上跑，用碼表量真實時間（wall clock time）。
- 「頻率比較高」「RAM 比較多」就比較好？老師說這些答案**全都不對**。跑同一個程式、量時間，就這樣。
- 相對效能 = 處理器 1 的執行時間 ÷ 處理器 2 的執行時間。

[30:03] 拆開來，效能有三個因素：

```
            IPC × f
效能  ∝  ───────────
           #insts
```

| 因素 | 意思 | 影片說的 |
|---|---|---|
| **f**（clock frequency，時脈） | 數位電路的週期計時器 | 從 kHz（500 kHz）到 3 GHz，現在約 4 GHz |
| **#insts**（指令數） | 程式編譯後有幾條機器指令 | 更好的 compiler（gcc、Intel compiler）讓指令數少了至少 2–3 倍 |
| **IPC**（instructions per cycle） | 每個 cycle 做幾條指令 | 靠架構的技巧拉高，這就是計算機結構 |

[30:19] 【口頭】Clock 像學校的**上下課鐘**：一節課結束，鐘一響，大家去下一堂課。每個電路要在一個 cycle 內做完，把答案寫進 state element，下一個 cycle 別人再拿去用。這是一種「契約」。

【課本補充】課本 §10.9.1（p.467）的 Equation 10.3 就是這條式子，第 32 支 §11 有完整推導。

## 9. IPC 從哪裡來：pipeline、記憶體、out-of-order、speculation

[33:52] 現代計算機結構的基本流程：程式 → 編譯 → 給處理器；處理器穩定時每個 cycle 做 n 條指令，IPC = n。我們用各種架構技巧把 IPC 拉到最大。處理器這個「黑盒子」裡發生的事，就是計算機結構。

[34:24] 老師說新手不用聽太多，只講大方向：

| 影響 IPC 的東西 | 說明 |
|---|---|
| **Pipeline** | 把處理器拆成幾段，一段接一段串起來，是處理指令的核心（第 30 支起） |
| **On-chip 記憶體**（CPU 裡面一點點） | 把 pipeline 要的資料放在旁邊，很快就拿得到（第 34–36 支的 cache） |
| **Off-chip 記憶體**（主機板上插的記憶體） | 很遠、很慢；它的效率影響效能也影響功耗 |

[35:40] Pipeline 和 on-chip 記憶體系統，各有**上百種**讓它更有效率的技巧。

### 9.1 Out-of-order execution

[36:37] 簡單的 pipeline 照程式順序做指令。複雜的 pipeline 做 **out-of-order execution（亂序執行）**：

- 指令 1、2、3、4 進到處理器裡，用最快的順序去做。
- 出來的時候，再排回**原來的順序**。

### 9.2 Speculation

[37:18] 很多時候我們會**猜**。例如一個變數在 off-chip 記憶體，要等幾百個 cycle：

- 要等嗎？大概不要。
- 歷史上它的值都是 5，那就**猜它是 5**，先做下去。
- 猜對 → 賺到效能；猜錯 → 大部分工作要重做。

[38:22] 這叫 **speculation（推測執行）**。可以猜的東西很多：

- `if` 會走 if 還是 else（branch 的方向）。
- 指令之間有沒有相依（一條指令不會用到另一條的結果）。
- 一個值會在 on-chip 還是 off-chip 記憶體。

[39:15] 猜錯的時候要 **roll back and recover**：把做錯的事修回來，確保程式結果還是對的。

[39:30] 【口頭】老師說：架構在 machine learning 流行之前，就已經在做「從歷史學習、預測」了。

（本機實測：猜得到和猜不到的 `if`，速度差 12 倍，見 [§17.3](#173-speculation猜錯要付多少)。）

## 10. IBM 360 vs 手機

[40:09] 投影片左邊：1960 年代初的傳奇 **IBM 360**，大到像一個櫃子、一座圖書館、一間廚房。右邊：**Samsung S5** 手機。

[40:38] 「IBM 360 倒下，Samsung S5 站著」：手機大約快 **10,000 倍**，全靠電晶體技術和計算機結構的進步。

⚠️ **快多少倍**：影片說 **10,000 倍**；課本 §12.1.1（p.568）說手機處理器比 1960 年代初的 IBM 360 快大約 **160 萬倍**（1.6 million），第 38 支 §4 也用 160 萬。兩個數字差 160 倍。

## 11. 現在：power wall 與 think parallel

### 11.1 時脈停住了

[41:15] 1999–2012 的時脈圖：大約 **13 年都差不多一樣**；錄影時（2020）還是一樣。

[41:48] 原因：**功耗和溫度**。頻率這條路走不下去了。

[42:02] 單一核心（core，一個處理單元）的效能（用 SPEC 分數這種相對效能看）也在 **2008 年左右**開始飽和。【口頭】手機裡就有 8 個 core，可以同時跑 8 個程式；一個 core 一次只跑一個程式。

### 11.2 可以煎蛋

[42:46] 投影片上一張「用處理器煎荷包蛋」的圖。

[43:02] 因為 **功率 ∝ 頻率³**：頻率加倍 → 功率變 **8 倍**。

| 東西 | 大約多少瓦 |
|---|---|
| 多核心處理器 | 150 W |
| 加上記憶體、硬碟 | 200–300 W |
| 再加 GPU | 再多約 200 W |
| 合計 | 大約半千瓦，像一台電暖器 |

【課本補充】課本 p.477 叫這個 **power wall**：「經驗法則，功率隨頻率的三次方增加；頻率加 10%，功率增加 30% 以上」，所以設計者避免很深、很高頻的 pipeline。

（本機實測：全部 20 個 thread 一起跑，1 秒內就到 100°C，時脈掉到 3 GHz，見 [§17.1](#171-power-wall本機一秒就到-100c)。）

### 11.3 Think parallel

[43:45] Compiler 的進步遞減、IPC 的技巧也用得差不多了。那計算機結構死了嗎？

[44:00] **沒有。** 死掉的是「只有一條 pipeline、讓單核變更快」這件事。現代的口號是 **think parallel**：

- **Multicore**：一顆晶片上很多 core。
- 每個 core 跑不同的程式；或把**同一個程式**切成很多小程式，分給不同 core。

[44:52] 平行計算機結構大約從 2010 年開始，是過去 10 年大部分創新發生的地方，也會繼續。晶片上有 core、cache bank、memory controller 等電路，但重點是**很多 core**。

[45:20] 【口頭】老師的例子：他用影片剪輯軟體做這支影片，最後 render（把原始影片變成要上傳的檔案）時，軟體把工作切成很多小程式，分給筆電上的各個 core，還有一部分給 GPU。

## 12. 現在的研究問題：大小核、散熱、process variation

### 12.1 平行帶來的新問題

[46:04]

- 怎麼寫有效率的平行程式。
- 怎麼把現有的循序程式改成平行。
- 怎麼設計**好寫程式**的平行架構。
- 怎麼替平行架構設計有效率的記憶體系統。

[46:20] 取捨（tradeoff）：要幾個 core？每個 core 多快？頻率多少？**所有 core 都要一樣嗎？大概不用。** 很多 ARM 手機有幾個小 core、幾個大 core，大小怎麼搭是重要的研究問題。

【實測】本機就是大小核：6 個 P-core（大）＋ 8 個 E-core（小），見第 38 支 [§14.1](lecture38_note.md#141-本機是一個-multicore而且核心不一樣)；也見 [§17.2](#172-一個-thread-vs-全部-thread)。

### 12.2 散熱

[47:02] 以前是處理器上面一個小風扇，強制空氣對流（convective cooling）。現在流行**水冷**：彩色水管把冷卻液帶到整台機器。老師說這還不普遍，2020–2030 這十年會有很多研究。

### 12.3 Process variation

[48:03] 「能用鈍刀寫精細的書法嗎？」不能。那怎麼用 **193 nm 的光**去做 **14 nm 的電晶體**？

[48:52] 想印四個電晶體的長方形，印出來卻是**圓角**、像骨頭的形狀。

[49:05] 原因：電晶體比光的波長還小，有**繞射（diffraction）**效應。

[49:20] 做不準 → 電晶體的效能會偏離規格 → 架構要有**容錯和時間餘裕（timing margin）**。這叫 **process variation tolerant architecture**。

## 13. 可靠度：soft error 與 electromigration

### 13.1 Soft error

[49:49] 【口頭】有學生問：散熱這麼麻煩，把電腦搬到喜馬拉雅山、西藏、喀什米爾，開窗就好了？老師說不行。

[50:16] 1000 顆處理器，不能連續跑 10 ÷ 1000 年 = 1/100 年 ≈ **3.6 天**而不出問題。原因：處理器一直被**宇宙粒子**打。

[50:50] 主要的兇手：**alpha 粒子**和**中子**（老師先說了 beta，馬上改口）。

1. 粒子打到電晶體 → 電荷位移。
2. 電荷位移 → 一個電流脈衝。
3. 電流脈衝 → 可能**翻轉一個 bit**。

[51:20] 【口頭】想像銀行帳戶的一個 bit 被翻轉：你突然變成百萬富翁，或從百萬富翁變成只剩幾千盧比。

[51:50] 這叫 **soft error**。架構要能容忍它，讓它發生了也不會造成故障。

[52:08] 現代**記憶體**大多有 **ECC（error correcting code）**，能偵測並更正 soft error（第 44 支 §3）。但**處理器本身沒有被保護**。

### 13.2 Electromigration

[52:24] 處理器跑 10 年還會怎樣？投影片上一條銅線，原本是均勻的一條，現在到處斷斷續續，有一段變很細：

1. 變細的地方電阻變高。
2. 那裡局部溫度升高。
3. 線變得更細……
4. 線一斷，整顆處理器就壞了。

[53:10] 這叫 **electromigration（電遷移）**：電流流動時會帶著一點點質量移動。電子往一個方向跑，把一些銅（老師說「質子和中子」，就是銅原子的質量）也帶走，所以一邊變細、變粗糙，另一邊還很結實。

## 14. 安全：hardware Trojan

[54:10] 老師先聲明：這是從間諜小說和報紙看來的，**他不保證真實性**。

[54:25] 故事：2007 年 9 月，以色列戰機轟炸敘利亞的核設施，敘利亞的雷達莫名其妙停了。傳說以色列送了一個無線訊息給雷達裡的處理器，讓它自己關掉。

[54:53] 這叫 **kill switch**，也叫 **hardware Trojan（硬體木馬）**。研究問題：怎麼讓設計能抵抗 hardware Trojan？不然有人對你發射飛彈，你駭進飛彈讓它掉頭打回發射的地方。

[55:40] 類似的還有伊朗核反應爐的 **Stuxnet** 蠕蟲（worm，像病毒）造成很大破壞。

[55:57] 手機和 IoT 裝置越來越多，**安全**變成非常重要的問題。

⚠️ 這一節的故事，老師自己說是「流行媒體看來的、不保證」；課本沒有，本筆記也不另外查證。

### 14.1 現在的結論

[56:13] 傳統計算機結構的一大塊（讓單核變快）因為功耗和溫度**已經死了**；但平行計算、可靠度、安全、省電設計，是過去十年的熱門題目，也會繼續熱下去。

## 15. 未來：誰來取代矽

[56:43] 「過去是歷史，未來是謎。」試著預測：

[56:59] 現在 7 nm，2022 年也許 5 nm，那只有 30–50 個原子寬。幾個原子跑掉，電晶體的規格就差很多。**矽快走到盡頭了。** 但這不是死路，很多新元件在競爭：

| 候選 | 影片怎麼說 |
|---|---|
| **Graphene（石墨烯）** | 不是石墨，是一層 2D 的碳，只有一個原子厚；省電和頻率很好；能量產的話可以取代矽。老師說最有希望之一 |
| **Spintronics** | 用電子的**自旋**存 state、做計算 |
| **Quantum computing** | 把資訊存在量子狀態，叫 qubit（老師說「半句話解釋：像一次存很多 bit，但其實不是那樣」）。只有少數 algorithm 在量子上有效率，大部分傳統 algorithm 在量子上很沒效率 → **頂多是補充，不會取代** |
| **Photonics（光子）** | photon 是 boson、electron 是 fermion；photon 沒有質量 → 不能存起來、做不出電容；但**沒有 I²R 損耗**，很省電。還沒人做出明確的光電晶體 |

## 17. 【實測】

本講沒有課本章節可以驗證，所以挑三個影片的主張，在本機量看看。程式在 `experiments/lecture47/`。

### 17.1 Power wall：本機一秒就到 100°C

RAPL（Intel 的功率計數器，`/sys/class/powercap/intel-rapl*/energy_uj`）只有 root 能讀，所以改看**溫度**和**時脈**。`heat.sh N`：讓 N 個 hardware thread 空轉 15 秒，每隔一段時間記錄封裝溫度（`x86_pkg_temp`）和 `scaling_cur_freq`。

```
$ bash experiments/lecture47/heat.sh 20
cpu0 最高 4700 MHz，cpu12 最高 3600 MHz
閒置       溫度 72°C  cpu0 1890 MHz  P-core 平均 1407 MHz  E-core 平均 874 MHz
滿載 1s  溫度 99°C  cpu0 3177 MHz  P-core 平均 3165 MHz  E-core 平均 2717 MHz
滿載 3s  溫度 100°C  cpu0 3033 MHz  P-core 平均 3041 MHz  E-core 平均 2627 MHz
滿載 10s  溫度 100°C  cpu0 3032 MHz  P-core 平均 2987 MHz  E-core 平均 2603 MHz
滿載 15s  溫度 100°C  cpu0 3000 MHz  P-core 平均 2970 MHz  E-core 平均 2549 MHz
停止後 5s 溫度 76°C  cpu0 2072 MHz  P-core 平均 1043 MHz  E-core 平均 872 MHz
```

- **1 秒**就從 72°C 衝到 99°C，之後一直卡在 100°C。
- P-core 標示最高 4.7 GHz，全部一起跑時只能跑 **3.0 GHz**；E-core 標示 3.6 GHz，只跑 **2.6 GHz**。
- 停下來 5 秒就降回 76°C。

這就是影片 [41:48] 說的：頻率不是做不出來，是**熱受不了**。（這是筆電，散熱比桌機差；閒置就 72°C。）

### 17.2 一個 thread vs 全部 thread

`heat.sh 1`：只有 cpu0 在跑。

```
滿載 1s  溫度 100°C  cpu0 4499 MHz  P-core 平均 2483 MHz  E-core 平均 800 MHz
滿載 5s  溫度 100°C  cpu0 4300 MHz  P-core 平均 2029 MHz  E-core 平均 1279 MHz
滿載 15s  溫度 100°C  cpu0 4300 MHz  P-core 平均 2487 MHz  E-core 平均 1257 MHz
```

- 只跑一個 core 時，cpu0 能跑 **4.3 GHz**；20 個一起跑，每個只剩 **3.0 GHz**。
- 用課本的 f³ 估：(4.3 / 3.0)³ ≈ **2.9 倍**功率。也就是一個 core 跑快 43%，要花將近 3 倍的電。晶片的總功率是固定的，所以 core 多的時候每個都要慢下來。
- ⚠️ 只跑一個 thread 也到 100°C。溫度感測器是整個封裝的最高點，一個熱點就能讓它到頂，所以 100°C 不代表整顆晶片都那麼熱。

`moore.py` 用同一個 f³ 算其他數字：

```
頻率 ×1.10 → 功率 ×1.33     ← 課本 p.477「加 10%、多 30% 以上」
頻率 ×2.00 → 功率 ×8.00     ← 影片 [43:02]「加倍就 8 倍」
```

兩個都對得上。

### 17.3 Speculation：猜錯要付多少

`spec.c`：一個 0–255 的亂數陣列（100 萬個），`if (a[i] >= 128)` 才加起來，跑 50 次。先用亂數跑，再排序後跑一次。`experiments/lecture47/spec.c:17-20`：

```c
	for (int r = 0; r < REP; r++)
		for (int i = 0; i < N; i++)
			if (a[i] >= 128)	/* 分支：值在 0–255，一半成立 */
				sum += a[i];
```

**第一次（`gcc -O1`）**：兩種一樣快，0.43 ns/元素。`objdump` 一看，gcc 把 `if` 換成了 **`cmovg`**（conditional move：兩個值都算好，照條件挑一個）。沒有 branch，就沒有東西要猜。

**第二次（`gcc -O1 -fno-if-conversion -fno-if-conversion2`，強迫留下 branch）**，綁在 P-core（cpu2）：

```
亂數   2.84 ns/元素 (sum=5026738600)
排序後 0.24 ns/元素 (sum=5026738600)
亂數 / 排序後 = 11.8 倍
```

E-core（cpu14）：亂數 3.98、排序後 0.52 ns/元素，**7.6 倍**。

- 同一個程式、同樣的資料、同一個答案，只是順序不一樣，就差 **12 倍**。
- 排序後，前一半都不成立、後一半都成立，處理器幾乎每次都**猜對**（影片 [37:49]「歷史上都是 5，就猜 5」）。
- 亂數時，大約一半猜錯，每次都要 **roll back**（影片 [39:30]）。粗估：多出來 2.6 ns ÷ 每個元素一半機率猜錯 ≈ 每次猜錯 **5 ns**，以 4.3 GHz 算大約 20 個 cycle。
- 一個 benchmark 跑出來的效能，跟資料有關。這呼應影片 [29:04]：「沒有電腦的效能，只有程式的效能」。

### 17.4 Moore's law 的翻倍時間

`moore.py` 用影片和課本給的數字算：

```
電晶體 2000→2e9（1971→2018）：每 2.36 年翻倍
feature size 1000→14 nm（1980→2016，影片）：12.3 代，每代 2.92 年
feature size 14→7 nm（2016→2020，影片）：2.0 代，每代 2.00 年
feature size 130→22 nm（2001→2011，課本 Table 12.1）：5.1 代，每代 1.95 年
5 nm / 0.1 nm = 50 個原子寬
```

- 電晶體數：影片沒給 2,000 是哪一年，用課本 p.568 的「1971 年 2000–3000 個」和影片圖的 2018 → **每 2.4 年翻倍**，比「每 1–2 年」慢一點。
- Feature size（每代縮 √2）：課本的 2001–2011 正好每 **2 年**一代；影片的 1980–2016 平均每 **2.9 年**一代。⚠️ 影片「1 µm 在 1980、14 nm 在 2016」平均是每 2.9 年一代，比影片和課本說的「每 1–2 年翻倍」慢；影片沒解釋，待補。

## 附：本講一句話總結

> **計算機結構研究處理器和計算機系統：人類從記帳和算盤開始計算，後來有用 Kirchhoff 和 Ohm 定律做加減乘除的 analog computer、用齒輪的機械計算機、用水位的水計算機，但它們都只是數字處理器、很難存 state；Turing 用一條無限 tape、一個 tape head 和一張 state table 回答了「要哪些運算才能做任何事」，Church-Turing thesis 說人用 algorithm 算得出的 Turing machine 都算得出，von Neumann 等人把它變成 CPU＋記憶體＋I/O，1947 年的電晶體再讓它變成真的；Moore's law 讓電晶體每 1–2 年翻倍（feature size 每代縮 √2，從 1 µm 到 7 nm，5 nm 只剩約 50 個原子），效能則由 performance equation 決定，效能 ∝ IPC × f / 指令數，IPC 靠 pipeline、記憶體系統、out-of-order 和 speculation（猜錯就 roll back）拉高；現在因為功率 ∝ f³，時脈從 2000 年代就停住，單核變快這條路死了，改走 think parallel 的 multicore 和大小核，同時要面對散熱、process variation、soft error、electromigration 和 hardware Trojan，未來可能由 graphene、spintronics、photonics 取代矽，quantum 只是補充。本機實測：20 個 thread 一起跑 1 秒就到 100°C、每個 core 只剩 3.0 GHz（只跑一個時 4.3 GHz），而同一個 if 在資料猜不到時比猜得到慢 12 倍。**
