## 0. 本講地圖

計算機算術的最後一講：

```
乘法：S = S_A ⊕ S_B；E = E_A + E_B − bias；W = P_A × P_B；正規化、捨入、再正規化 → O(log n)
除法：
  簡單：E = E_A − E_B + bias；W = P_A ÷ P_B（整數除法 O(n log n)）→ 慢
  Goldschmidt：1/P_B = ½ × 1/(1 − y) ≈ ½ × (1+y)(1+y²)(1+y⁴)(1+y⁸)(1+y¹⁶) → O(log² n)
  Newton-Raphson：f(x) = 1/x − b 的根；x_{k+1} = 2x_k − b·x_k²；誤差每次平方 → O(log² n)
```

【口頭】乘法「和加減法的做法差不多，只差一點點」；除法「不一樣」。

## 1. 浮點數乘法

[00:43]–[06:43]　課本 §8.5（p.347–348）

【口頭】十進位的例子（約定 significand 小數點前只有一位）：

```
(4.0 × 10⁻⁴) × (5.0 × 10⁻⁵)
= (4.0 × 5.0) × 10^(−4 + −5)     ← significand 相乘、指數相加
= 20.0 × 10⁻⁹                     ← 不是 normal form
= 2.0 × 10⁻⁸                      ← 正規化
```

二進位做一樣的事：

**指數相加，要減掉一次 bias**：

```
E_A = X_A + bias,  E_B = X_B + bias
E_A + E_B = X_A + X_B + 2·bias      ← bias 加了兩次！
E = E_A + E_B − bias = (X_A + X_B) + bias    ← 這才是結果的 bias 表示法
```

**significand 相乘**：W = P_A × P_B。

**之後的步驟和加法完全一樣**：

1. **正規化**：significand ≥ 2 就右移、調整指數。
2. **捨入**：如果有位元被移掉，要讓剩下的 significand 反映出它們的影響。
3. **再正規化**：捨入可能又造成問題。

**符號**：同號 → 正；異號 → 負。

**時間**：一次加法、一次減法（算指數）和一次乘法，都是 O(log n)，所以浮點數乘法是 **O(log n)**。

【課本補充】W 的寬度要是運算元的**兩倍**才放得下乘積：24 位元 × 24 位元的 significand，乘積在小數點後有 **46 位**。要丟掉一些位元，讓 mantissa 變回 23 位元。正規化可能要右移（normal 數），也可能要左移（denormal 數）。乘法**不需要對齊指數**。

## 2. 乘法的流程圖

[06:43]–[09:50]　課本 Figure 8.18（p.348）

```
C = A × B
  ├─ A = 0 ? → C = 0
  ├─ B = 0 ? → C = 0
  ▼
S ← sign(A) ⊕ sign(B)
E ← E_A + E_B − bias  → overflow／underflow ? → 回報
  ▼
W ← P_A × P_B
  ▼
正規化 W，更新 E      → overflow／underflow ? → 回報
  ▼
捨入 W
  ▼
正規化 W，更新 E      → overflow／underflow ? → 回報
  ▼
用 W、E、S 組出 C
```

- **符號 = 兩個符號位的 XOR**：同號（0 ⊕ 0 或 1 ⊕ 1）是 0（正），異號是 1（負）。
- 【口頭】投影片上「多了一步，應該刪掉」。
- 指數相加可能超出範圍，所以算完 E 就要檢查。

§11.1 實測：照這個流程用位元寫的 float32 乘法器，10 萬組、四種捨入模式，和 x86 硬體完全一樣。

## 3. 簡單的浮點數除法

[09:50]–[14:56]　課本 §8.6.1（p.348–349）

- **和整數除法的第一個差別：沒有餘數**。整數除法的商只能是整數，所以有餘數；浮點數的商本身就可以是浮點數。「這讓我們的工作變簡單。」
- 【口頭】十進位：(5 × 10⁵) ÷ (2 × 10³) = (5 ÷ 2) × 10^(5 − 3) = 2.5 × 10²。乘法是指數**相加**，除法是指數**相減**。

**指數相減，要加回一次 bias**：

```
E_A − E_B = (X_A + bias) − (X_B + bias) = X_A − X_B     ← bias 被消掉了
E = E_A − E_B + bias                                    ← 加回 bias，結果才是 bias 表示法
```

**significand 相除**：W = P_A ÷ P_B。

**之後一樣**：正規化 → 捨入 → 再正規化。

- 【口頭】這三步在**所有**浮點數演算法裡都一樣，不只加減法，乘法、除法和其他運算都是。
- 【口頭】書裡有證明：**再正規化一次就夠了**，不需要做兩次。

**時間**：由最慢的 significand 除法決定。用整數除法（restoring、non-restoring，第 24 支）要 **O(n log n)**，很慢。

## 4. 用整數除法做出小數

[14:56]–[20:05]

【口頭】嚴格來說這不是一般的整數除法。小學教的除法：

- 5 ÷ 2：整數除法的商是 2。但如果先算 **50 ÷ 2 = 25**，再把小數點放回去，就得到 **2.5**。
- 5 ÷ 3：要更精確，就算 500 ÷ 3 = 166 → 1.66；50000 ÷ 3 = 16666 → 1.6666。
- **把被除數往左移**（乘上 10 的冪次），做整數除法，再把商往右移同樣的位數。每一步都是普通的整數除法，但**精度提高了**。
- 浮點數也一樣：把 P_A 左移若干位、做除法、再把商右移同樣的位數。（投影片上沒寫，免得太亂。）
- 結論：還是慢。能不能做得快很多？

## 5. Goldschmidt 除法：先算倒數

[20:05]–[25:47]　課本 §8.6.2、Equation 8.26（p.349）

**想法**：A ÷ B = A × (1/B)。乘法已經有快的演算法，所以問題變成：**怎麼快速算出倒數 1/B**。

- B = P_B × 2^X，所以 1/B = (1/P_B) × 2^(−X)。指數只要變號，很簡單；**核心是算 1/P_B**。
- 只考慮 normal 數：**1 ≤ P_B < 2**。（denormal 數可以用很簡單的延伸處理，影片為了時間不講。）

推導：

```
P_B = 1 + X              （0 ≤ X < 1）
```

- X = 0 時 P_B = 1，倒數也是 1：**特例另外處理**。所以以下假設 **0 < X < 1**。

```
令 X′ = 1 − X          （0 < X′ < 1）

1/P_B = 1/(1 + X) = 1/(1 + 1 − X′) = 1/(2 − X′)
      = ½ × 1/(1 − X′/2)
      = ½ × 1/(1 − Y)       （Y = X′/2，所以 Y < ½）
```

- **Y = X′/2 = (1 − X)/2**：一次減法加一次右移，很容易算。
- **乘以 ½ 就是右移一位**。例：6 = `110`，右移一位 = `11` = 3。「這個 ½ 不是什麼大事。」
- **難的是算 1/(1 − Y)**。

## 6. 1/(1 − y) 的乘積展開

[25:47]–[35:01]　課本 Equation 8.27（p.349–350）

上下同乘 (1 + Y)，再同乘 (1 + Y²)……

```
1/(1 − Y) = (1 + Y)/(1 − Y²)
          = (1 + Y)(1 + Y²)/(1 − Y⁴)
          = …
          = (1 + Y)(1 + Y²)(1 + Y⁴)(1 + Y⁸)(1 + Y¹⁶) / (1 − Y³²)
          ≈ (1 + Y)(1 + Y²)(1 + Y⁴)(1 + Y⁸)(1 + Y¹⁶)
```

**為什麼可以把分母丟掉**：

- Y < ½，所以 **Y³² < 2⁻³²**。
- float32 只有 **23 位元**的 mantissa。1 − Y³² 和 1 的差小於 2⁻³²，**根本表示不出來**：在我們的數字系統裡，1 − Y³² **就是 1**。
- 同樣地，再乘上 (1 + Y³²) 也**完全沒有差別**。
- 【口頭】另一個角度：1/(1 − x) 展開成 1 + x + x² + …，除了 1 之外，其他項乘上去都小於 2⁻³²，表示不出來，只能忽略。

**結果：分數變成一串乘積，沒有分母了。**

**怎麼算**：

1. 先算 Y。
2. Y × Y = Y²；Y² × Y² = Y⁴；Y⁴ × Y⁴ = Y⁸；Y⁸ × Y⁸ = Y¹⁶（每次自己乘自己）。
3. 把 (1 + Y)、(1 + Y²)、(1 + Y⁴)、(1 + Y⁸)、(1 + Y¹⁶) 乘起來。
4. 乘以 ½（右移一位）→ 1/P_B。
5. 乘以 P_A → P_A / P_B。之後的除法步驟（正規化等）和前面一樣。

- 【課本補充】5 個加法可以**平行**做；算 Y 的冪次要 **4 次**乘法；把 5 個括號乘起來要 **4 次**乘法。共 **8 次乘法、5 次加法**。

**時間**：

- n 位元的系統要 **log n 項**（log n 步），每一步一次乘法 O(log n)。
- 所以求倒數是 **O(log² n)**，比 O(n log n) 快得多。
- ⚠️ 投影片上這裡的時間複雜度寫錯了，老師口頭更正：「求倒數的時間是 log² n，總時間也是 log² n，我之後的版本會修正。」
- 【課本補充】**浮點數除法在漸近上比整數除法快得多**，主要是因為浮點數運算是**近似的**，整數運算要**精確**。

## 7. Newton-Raphson 法

[35:01]–[42:48]　課本 §8.6.3、Figure 8.19、Equation 8.28–8.29（p.350–351）

另一個求 1/b 的方法（b = P_B，1 ≤ b < 2）。【口頭】「Newton-Raphson 和 Goldschmidt 很像，但為了學點新東西，我們學一個新方法。」

**把求倒數變成求根**：

```
f(x) = 1/x − b       f(x) = 0  ⟺  x = 1/b
```

**Newton-Raphson 法**（標準的解方程式方法）：

```
     f(x)
      │\
      │ \  ← 在 (x₀, f(x₀)) 畫切線
      │  \
 ─────┼───\──────── x
      │ x₂ x₁ x₀
```

1. 隨便猜一個 x₀。
2. 在曲線上找到 (x₀, f(x₀))，畫**切線**，切線和 x 軸交在 **x₁**。
3. 在 (x₁, f(x₁)) 再畫切線，交在 x₂……
4. 一直重複，越來越接近根。硬體裡就是把這些數學實作出來。

**推導**：

- 斜率 f′(x₀) = −1/x₀²。
- 切線 y = mx + c = −x/x₀² + c。
- 在 x₀，y = 1/x₀ − b，代入：1/x₀ − b = −x₀/x₀² + c → **c = 2/x₀ − b**。
- 切線：y = −x/x₀² + 2/x₀ − b。
- 和 x 軸相交（y = 0）的點 x₁：

```
x₁ = 2x₀ − b·x₀²
```

一般式：**x_{k+1} = 2x_k − b·x_k²**，**只有乘法和減法**。

## 8. 誤差每次平方

[42:48]–[47:54]　課本 Equation 8.30–8.31（p.351）

**誤差函數**：

```
E(x) = b·x − 1         x = 1/b 時 E = 0
```

- 【口頭】「這些函數的定義其實是一門藝術，不同的問題要定義不同的函數。」

```
E(x₁) = b·x₁ − 1 = b(2x₀ − b·x₀²) − 1
      = 2b·x₀ − b²x₀² − 1
      = −(b·x₀ − 1)²
      = −E(x₀)²
```

> **|E(x₁)| = |E(x₀)|²**：**誤差每一次迭代就平方**。

- 一般：|E(x_n)| = |E(x_{n−1})|² = |E(x_{n−2})|⁴ = …
- 只要一開始的誤差 < 1，就會**收斂到 0**。

**初始猜測 x₀ = ½**：

- 1 ≤ b < 2，所以 b·x₀ − 1 介於 **−½ 和 0** 之間。
- 所以 **|E(x₀)| ≤ ½**。這是個好的初始值：誤差有界，而且會一直變小。

| 迭代 | 最大誤差 |
|---|---|
| 0 | 1/2 |
| 1 | 1/2² |
| 2 | 1/2⁴ |
| 3 | 1/2⁸ |
| 4 | 1/2¹⁶ |
| 5 | **1/2³²** |

## 9. 要幾次迭代、多少時間

[47:54]–[53:22]

**E 的物理意義**（[49:01]）：

```
E(x) = b·x − 1 = b·(x − 1/b) = b·Δ
```

- Δ = **目前的估計值和真正的根的距離**。【口頭】「我說這個誤差函數是隨便定義的，現在要收回一點：它其實有物理意義。」
- 5 次迭代後 b·Δ ≤ 2⁻³²。b 在 1 和 2 之間，所以 **Δ 在 2⁻³² 和 2⁻³³ 之間**。
- 這遠小於 23 位元 mantissa 能表示的精度。所以 **5 次迭代就夠了**：x₅ 和 1/b 的差，比我們最小的精度還小，反正也表示不出來，可以忽略。

**時間**：

- 32 位元系統，n = 32；誤差的指數每次加倍，所以要 **log n 次迭代**。
- 每次迭代只有乘法和減法，**O(log n)**。
- 總共 **O(log² n)**，和 Goldschmidt 一樣。
- ⚠️ 投影片上這裡的時間也寫錯了，老師口頭更正：每一步 O(log n)，乘上 log n 步，是 O(log² n)。
- 【口頭】Newton-Raphson 有**圖形上的意義**，而且除了倒數，**還能用來算其他數學函數**。

§11.2 實測：Newton-Raphson 的誤差真的是 2⁻¹ → 2⁻² → 2⁻⁴ → 2⁻⁸ → 2⁻¹⁶ → 2⁻³²；Goldschmidt 用 1、2、3、4、5 項的誤差**一模一樣**。

### 11.2 Goldschmidt 和 Newton-Raphson 收斂得多快

用 Python 的 `Fraction`（精確的有理數）對 b = 1.001～1.999 共 999 個值，算最大誤差：

```
$ python3 recip.py
Newton-Raphson: x0 = 1/2, x_{k+1} = 2x_k − b·x_k²；|E| = |b·x − 1| 的最大值
  iteration 0: max |E| = 4.995e-01  (≈ 2^-1.0)
  iteration 1: max |E| = 2.495e-01  (≈ 2^-2.0)
  iteration 2: max |E| = 6.225e-02  (≈ 2^-4.0)
  iteration 3: max |E| = 3.875e-03  (≈ 2^-8.0)
  iteration 4: max |E| = 1.502e-05  (≈ 2^-16.0)
  iteration 5: max |E| = 2.255e-10  (≈ 2^-32.0)
Goldschmidt: 1/b = 1/2 × 1/(1−y)，y = (1 − x)/2 = (2 − b)/2；只乘到 (1+y^(2^k))
  1 terms (up to 1+y^1): max relative error 2.495e-01 (≈ 2^-2.0)
  2 terms (up to 1+y^2): max relative error 6.225e-02 (≈ 2^-4.0)
  3 terms (up to 1+y^4): max relative error 3.875e-03 (≈ 2^-8.0)
  4 terms (up to 1+y^8): max relative error 1.502e-05 (≈ 2^-16.0)
  5 terms (up to 1+y^16): max relative error 2.255e-10 (≈ 2^-32.0)
float32 的 mantissa 精度：2^-23 = 1.192e-07
```

- **Newton-Raphson**：誤差真的**每次平方**，指數 −1、−2、−4、−8、−16、−32，和 §8 的表一樣。
- **5 次迭代後誤差 ≈ 2⁻³²**，遠小於 float32 的 2⁻²³。第 4 次迭代（2⁻¹⁶）還不夠。
- **Goldschmidt 用 k 項的誤差和 Newton-Raphson 第 k 次迭代一模一樣**（數字完全相同）。這不是巧合：x₀ = ½ 時，Newton-Raphson 第 k 次迭代的值剛好等於 ½ × (1 + y)(1 + y²)…(1 + y^(2^(k−1)))。兩種方法是**同一件事的兩種寫法**，所以影片說它們「很像」，複雜度也一樣。

### 11.3 真正的處理器：除法比乘法慢得多

```
$ gcc -O2 -o fplat fplat.c && taskset -c 2 ./fplat
addsd 1.20, mulsd 2.40, divsd 8.37 ticks;  mul/add = 2.0, div/add = 7.0  (x=2e+07)
```

- 一串互相依賴的雙精度運算：**乘法是加法的 2 倍、除法是加法的 7 倍**。（第 23 支量到整數 add 是 0.6 ticks = 1 個週期，所以這裡 addsd 約 2 個週期、mulsd 約 4 個、divsd 約 14 個。）
- 硬體用了 §5–9 這類方法和其他技巧，除法還是比乘法慢很多。所以 compiler 會盡量把「除以常數」換成「乘以倒數」（在允許的情況下）。

## 12. 一頁速查表

| 主題 | 重點 |
|---|---|
| 乘法 | S = S_A ⊕ S_B；E = E_A + E_B − bias；W = P_A × P_B（46 位小數）；正規化、捨入、再正規化 |
| 乘法時間 | O(log n) |
| 除法（簡單） | 沒有餘數；E = E_A − E_B + bias；W = P_A ÷ P_B；O(n log n) |
| 共同的三步 | 正規化 → 捨入 → 再正規化（一次就夠） |
| 小數除法 | 被除數左移、整數除法、商右移 |
| 倒數 | A/B = A × (1/B)；1/B = (1/P_B) × 2^(−X) |
| Goldschmidt | P_B = 1 + X；Y = (1 − X)/2 < ½；1/P_B = ½ × 1/(1 − Y) |
| 乘積展開 | 1/(1−Y) ≈ (1+Y)(1+Y²)(1+Y⁴)(1+Y⁸)(1+Y¹⁶)；Y³² < 2⁻³² 表示不出來 |
| Goldschmidt 成本 | 8 次乘法、5 次加法；O(log² n) |
| Newton-Raphson | f(x) = 1/x − b；x_{k+1} = 2x_k − b·x_k² |
| 誤差 | E(x) = bx − 1 = b·Δ；\|E(x_{k+1})\| = \|E(x_k)\|² |
| 初始值 | x₀ = ½ → \|E\| ≤ ½ |
| 迭代次數 | 5 次 → 2⁻³² < 2⁻²³；一般 log n 次 |
| Newton-Raphson 時間 | O(log² n)；和 Goldschmidt 一樣（實測兩者完全等價） |
| 習題 | 用 Newton-Raphson 設計 √x |

## 附：本講一句話總結

> **浮點數乘法和加法很像但更簡單：符號是兩個符號位的 XOR，指數 E = E_A + E_B − bias（扣掉多加的一次 bias），significand 直接相乘（24 × 24 位元，小數點後 46 位），再正規化、捨入、再正規化，O(log n)；除法沒有餘數，E = E_A − E_B + bias，但 significand 用整數除法相除要 O(n log n)，太慢。Goldschmidt 法改成乘以倒數：P_B = 1 + X，令 Y = (1 − X)/2 < ½，1/P_B = ½ × 1/(1 − Y)，而 1/(1 − Y) 上下不斷乘以 (1 + Y^(2^k)) 後分母 1 − Y³² 小到表示不出來，所以 ≈ (1+Y)(1+Y²)(1+Y⁴)(1+Y⁸)(1+Y¹⁶)，只要 8 次乘法、5 次加法，O(log² n)；Newton-Raphson 法求 f(x) = 1/x − b 的根，迭代 x_{k+1} = 2x_k − b·x_k²，誤差 E = bx − 1 每次平方，從 x₀ = ½（|E| ≤ ½）開始 5 次就到 2⁻³²，比 float32 的精度還小，也是 O(log² n)。實測照流程寫的 float32 乘法器 10 萬組和硬體完全一致；兩種求倒數的方法誤差一模一樣（2⁻¹、2⁻²、2⁻⁴ … 2⁻³²），其實是同一件事；本機的 divsd 延遲是 addsd 的 7 倍、mulsd 的 3.5 倍。**
