# 讀書筆記製作 Brief

> 這份 brief 定義 `reading-notes.md` 的製作規格。第 1 章是已確認的樣本，第 2–11 章照此模子完成。

## 1. Purpose（目的）

這份筆記要**代替讀原書**。讀者讀完筆記後，應該能說出每章在講什麼、核心觀點是什麼、書中主張的做法是什麼——不需要再翻 330 頁的原文。

不是查詢用的操作手冊，所以不追求指令完整可貼上執行；但概念的完整度要夠，能讓讀者判斷「這章的東西我用不用得上」。

## 2. Situation（背景）

- **書**：《The Ultimate AI Guide for Linux Engineers》，Ezequiel Lanza & Eduardo Spotti，Packt，2026 年 6 月，330 頁，英文
- **讀者**：Linux 底子熟、AI 不熟
  - → AI 名詞（LLM、RAG、agent、embedding、fine-tuning、vector DB…）第一次出現時要用白話解釋
  - → Linux 名詞（cron、systemd、journalctl、inotify…）不用解釋，帶過即可
- **筆記語言**：中文（繁體）
- **引用語言**：英文原文照抄，附頁碼

## 3. Inputs（來源）

- **唯一來源**：`linux-ai-guide.pdf`（已用 `pdftotext -layout` 抽成純文字）
- **不引入外部資料**。書中沒寫的，標註「書中未提」，不補充、不推測、不用常識填空
- 引用必須是原文逐字，不改寫、不翻譯後再回譯
- 頁碼取自 PDF 內文的頁眉／頁腳數字（書本頁碼，非 PDF 檔案頁次）

## 4. Limits（界線）

- **跳過第 12 章**（Unlock Your Exclusive Benefits）——只是 Packt 的購書贈品領取說明，無知識內容
- 不寫成教學文，不加練習題以外的作業
- 不評論書寫得好不好，不比較其他書
- 程式碼只留關鍵骨架，不貼完整檔案；長腳本用文字描述它做了什麼

## 5. Done-when（完成定義）

每章包含以下區塊，順序固定：

1. `## 第 N 章：英文原標題（中文標題）` + 對應原書頁碼範圍
2. `### 這章在幹嘛` — 3–5 句，講這章的動機和骨架
3. `### 重點 N：<標題>` — 每章 8–14 個，每個重點包含：
   - 中文說明（白話，短句）
   - `> **原文引用（p.XX）**` 區塊，1–3 句英文原文
   - 需要時附程式碼骨架、表格、名詞解釋
   - `**要記住的觀點**：` 一句話收尾（用於關鍵重點）
4. `### 本章 Summary（作者原話）` — 引用書中 Summary 段落
5. `### 練習題` — 若該章有，照列
6. `### 我的整理：本章帶走的 N 句話` — 3–5 句，我自己的濃縮
7. `### 延伸資源` — 若該章有，列出

**每章長度**：約 3–4 頁（Markdown 約 300–450 行）

**格式規則**：
- 每章之間用 `---` 分隔
- 引用一律用 blockquote，標題行為 `**原文引用（p.XX）**`
- 程式碼用 fenced code block，標語言（bash / python / text）
- 表格照抄書中表格，欄位名保留英文並附中文
