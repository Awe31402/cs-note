## 1. 嵌入式系統與即時系統

### 1.1 嵌入式系統

[01:32]–[02:01] **嵌入式系統（embedded system）**：**嵌在**某個真實世界應用裡的電腦系統。

[02:01] 兩個關鍵詞：

| 詞 | 意思 |
|---|---|
| **real world（真實世界）** | 嵌在會影響人類生活的**實體系統**裡 |
| **real time（即時）** | **實際的牆上時鐘時間**很重要 |

大部分應用不在乎實際時間，即時系統在乎。

### 1.2 為什麼處理器大多在即時應用裡

[02:30] 根據最近的估計，用在即時應用的處理器（從微控制器到 IoT 處理器）數量，**遠遠超過**一般非即時的處理器。

【課本補充】課本的數字：全世界製造的處理器中，約 **70%** 用在即時嵌入式應用（引用 Brian Santo, IEEE Spectrum, 2001）。

[02:30]–[03:01] 微波爐、洗衣機、烘衣機……每台都有一顆小處理器，必須是即時處理器，因為它要處理**實體刺激**。【口頭】老師說：家裡也許只有一台電腦，卻有很多這種小裝置。我們看不到它們，但它們很重要。

[03:31]–[04:01] 為什麼嵌入式應用激增？

- 以前洗衣機是機械的，頂多有簡單電路，沒有完整的處理器和程式環境。現在有了。
- **成本降低**、彈性大增。
- **網際網路**：例如 Amazon Alexa 能控制燈、風扇。
- **功耗降低、體積縮小**。
- 最重要：**處理能力大幅增加**，軟硬體的可靠度也提高到可以放心使用的程度。

[04:01]–[04:30] 嵌入式系統到處都是：印表機、飛機、汽車（現代汽車有非常多處理器）、攝影機、咖啡機、玩具、手機、火箭、火車、雷達、導航系統……

【課本補充】課本把計算的歷史分成三個時代：**大型主機**（昂貴，一台服務很多人）、**PC**（個人負擔得起）、**後 PC**（小型、可攜，嵌在日常用品裡，一個人每天跟好幾台電腦互動）。前兩個時代即時嵌入式應用很少，只用在太空、國防等特殊領域。

### 1.3 即時：定量的時間

[04:30]–[05:32] **即時（real time）**：有**定量**的時間觀念，用**實體時鐘**量測，而且它決定系統的行為。

例：溫度超過 500°C 時，要在 **100 毫秒內**噴灑冷卻劑。這是一個**即時限制（real-time constraint）**，實作它的系統就是即時系統。

[05:32]–[06:00] 對照：一般分散式系統用的是**定性**的時間：之前、之後、某個時候、最終……。例如 OS 課第 18 講的 **happens-before**：A 先於 B，但兩者之間的時間**可以任意長**，沒關係。

> **課本的定義**：如果描述一個系統的行為時，**需要用到定量的時間表示**（也就是即時），這個系統就叫**即時系統**。

【課本補充】課本的對照例子：

| | 例子 | 時間 |
|---|---|---|
| **real time** | 化學反應槽達到 250°C 時，系統要在 30 毫秒內關掉加熱器 | 實體時鐘的讀數 |
| **logical time**（邏輯時間，也叫虛擬時間） | 圖書館系統：「使用者下了查詢指令**之後**，顯示所有符合的書」 | 只有事件的先後順序，不需要時鐘 |

課本也提醒：一個即時系統的描述裡，**不是每一條**都要有定量的時間，只要有一部分需要，就算即時系統；完全不需要的就不是。

### 2.1 各領域的例子

[06:00]–[09:32]

| 領域 | 例子 |

| 行動電話 | [09:00] |
| 航空 | [09:00] 非常安全攸關。現代飛機用 **fly-by-wire**（線傳飛控），很多處理器要遵守即時限制 |

| 消費電子 | 手機、數位相機 |
| 國防 | [09:32] 飛彈、雷達 |

### 2.2 汽車：一台車上的網路

[09:32]–[10:30] 一般汽車（這是比較舊的例子）大約每台 **100 顆處理器**，現代汽車更多：引擎控制、煞車、安全氣囊、雨刷、門鎖、娛樂系統……

[10:02] **自動駕駛**又完全不同：它是「即時到了極點」。有很多不能忽略的即時限制，否則車子會出事或停住。

[10:30]–[11:00] 例子：**BMW 7 系列**（用舊版 Windows Mobile 作業系統）：

- **200 萬行**程式碼。
- **60 多顆**微處理器：53 顆很小的 8 位元、11 顆 32 位元、7 顆 16 位元。（⚠️ 53 + 11 + 7 = 71，跟「60 多顆」對不起來，逐字稿照錄，原始數字待補。）
- 車內有**好幾個網路**：**CAN bus**、LIN、MOST 等協定。

[11:00]–[11:31] 每個模組（安全氣囊、車身、駕駛座車門、巡航控制……）有一個小處理器，叫 **ECU**（Engine Control Unit；老師說他自己偏好 **Electronic Control Unit** 這個說法）。它們互相通訊，當然要遵守即時限制。

[11:31]–[12:32] 車內網路圖：

- **CAN bus**（Controller Area Network）：【口頭】老師說記不住的話可以記成 "**Car** Area Network"，雖然不正確。
- 主控制線管引擎、懸吊、煞車；較小的控制線管雨刷、車燈、方向燈。

[12:32]–[13:00] 車內主要的即時應用：燃油噴射（決定引擎震動和輸出）、**巡航控制**（維持例如 60 km/h，車子變快就要減速）、防鎖死煞車、安全氣囊、無鑰匙進入、空調、GPS。全部接在 bus 上，每一個都是即時系統。本課要學的就是：這些系統怎麼設計、怎麼通訊。

[13:00]–[14:00] **多點燃油噴射（MPFI）**：

- 多汽缸引擎，燃料由進氣閥噴入，電腦控制噴多少。
- 決定引擎輸出的扭力；要在**最少燃料下產生最大動力**，並**減少震動**（震動取決於活塞怎麼動）。
- 從各種感測器接收訊號、處理、再送訊號給致動器（控制燃料量）。

【課本補充】課本 Example 6：舊車用**化油器**（機械裝置）依車速和加速調整噴油量。實驗顯示最佳噴油量跟車速、加速度是**高度非線性**的關係，而且多點噴射比單點有效。MPFI 主要控制點火時機和噴油量（靠控制噴油閥開啟的時間，叫 **pulse width**）。感測器監測環境溫度、冷卻液溫度、排氣溫度、廢氣成分、引擎轉速、車速、曲軸和凸輪軸位置。就算用 8 位元電腦，也比化油器準得多，省油又減少污染。

[14:00]–[15:02] **巡航控制**：目標 60 km/h。重要的是電腦**多常**檢查目前車速、多快做決定、多快把決定傳給致動器。車速太高就減少引擎輸出，反之亦然。

### 2.3 其他例子：雷射印表機、手機、SCADA、飛機、反飛彈

[17:30]–[19:01] **雷射印表機**：

1. 把影像切成矩陣。黑白印表機的每一列是一串白色和黑色的像素，叫 **raster image（點陣影像）**。
2. 雷射光**中和**黑色部分的電荷，白色部分保持帶電 → 產生一個靜電的負像。
3. 噴上細小的碳粉，碳粉會黏在被中和過的地方，其他地方被排斥。
4. 這是**即時**的：紙在旋轉的滾筒上一直移動，**下一列來之前**，這一列的計算一定要做完。

【課本補充】課本 Example 5：雷射引擎只會「在紙上打一個黑點」，不知道字型、大小、斜體、底線。嵌入的處理器接收列印指令，算出要怎麼用一連串的點組成文件，再管理雷射引擎。處理器還要從通訊埠收資料、排版字型、偵測卡紙、缺紙、面板按鍵、顯示訊息。時間限制是幾毫秒。

[19:01]–[19:30] **手機**：老師稱它是「**即時系統之王**」。不管 GSM、CDMA、3G、4G、5G，都有大量通訊。

[19:30]–[20:00] **SCADA**：用在水壩、發電廠這種非常大的系統。一個大型電腦系統監控程序，很多感測器把資料存進一個**分散式的即時資料庫**，再加上監督系統。工業規模的分散式即時系統。

[20:00]–[21:00] **飛機**：很多飛機用**自動駕駛**模式飛。有目前位置 x、y、z、速度、加速度。要往某個目的地以某個速度飛，就有很多致動器取得即時資料、算出引擎該產生多少推力。截止時間從**幾微秒到幾毫秒**，非常短。

【課本補充】課本 Example 8：自動駕駛時，電腦週期性取樣速度和加速度，算出目前的 x、y、z 座標，跟預定航線比較；**下一次取樣之前**就要算出偏差、做出修正。

[21:00]–[22:01] **反飛彈系統**：【口頭】老師說很多人在關注相關新聞，很多國家在購買反飛彈、反無人機系統。

- 對方發射飛彈，我方發射另一枚去攔截、把它炸碎。
- 攔截飛彈的攝影機（可見光或其他波段）要持續**鎖定（home into）**目標，算出軌跡、找到撞擊點、在那裡引爆。
- 反應時間通常是**微秒**等級，甚至更短。非常精密的即時系統。

## 3. 反應式系統與三種事件

[15:02]–[15:32] 大部分嵌入式系統是**反應式（reactive）**的：

- 從環境讀取輸入，也叫**刺激（stimuli）**。
- 對它們做出**回應（action）**。例如車子變快了，回應是讓車子減速。

[15:32]–[17:01] 三種事件：

```
週期性（periodic）：  │     │     │     │     │      固定間隔 = 週期
                     ─┴─────┴─────┴─────┴─────┴──▶

偶發性（sporadic）：  │   │         │  │       │     隨機，但兩個事件之間
                     ─┴───┴─────────┴──┴───────┴──▶  至少隔一個最小間隔

非週期（aperiodic）： │ ││   │││      │   ││         完全隨機，可以同時發生
                     ─┴─┴┴───┴┴┴──────┴───┴┴──▶     （最小間隔 = 0）
```

| 類型 | 定義 |
|---|---|
| **Periodic（週期性）** | [16:01] 有固定的週期：一個事件，過一個週期又一個……。小系統裡幾乎所有活動都是週期性的：週期性感測環境、做出回應 |
| **Sporadic（偶發性）** | [16:01]–[16:31] 統計上隨機發生，但有一點秩序：兩個事件之間通常有一個**最小間隔**，t₂ − t₁ > 某個門檻 |
| **Aperiodic（非週期）** | [16:31]–[17:01] 也是偶發，但門檻是 **0**：多個事件可以同時發生 |

[17:01] 真正的非週期事件在即時系統裡很少見，通常是週期性和偶發性。但要做一個很通用的系統，就要考慮非週期事件。

（這三種的嚴格定義在第 3–4 支影片的任務模型裡。）

[17:01]–[17:30] **怎麼規格化一個嵌入式系統？** 要對所有事件和動作建模。複雜的系統可能有上千種事件和動作，要切成子系統，有意義地建模。

## 4. 為什麼用軟體做

[22:01]–[22:31] 關鍵問題：為什麼嵌入式系統用很多**軟體**？為什麼不全部用硬體做？

- 硬體**沒彈性**：一旦設計好就固定了。
- 軟體給我們**彈性**。
- 很多事情用硬體很難做，軟體可以用進階的程式語言和資料結構。

所以除了最底層的微控制器，嵌入式系統大致上是一個**軟體產物**。

[22:31]–[23:31] 近年趨勢：

- 智慧電視、視訊會議：同時跑 YouTube、接衛星訊號，還看不到抖動（jitter）。
- 現代嵌入式系統很容易**監控和除錯**，通常有網頁介面可以看狀態。
- 越來越容易寫程式和管理。
- 但關鍵是：要仔細地做**軟硬體協同設計**，而且要很懂**即時的基礎**，這就是本課的內容。

【課本補充】課本：本書只談**軟體**議題，硬體討論降到最低。軟體議題很廣：作業系統、程式開發，也包括網路和資料庫。

## 5. 即時系統的基本模型

### 5.1 方塊圖

[23:31]–[24:30]（課本 Figure 3）：

```
          ┌────────────┐   ┌───────────┐
sensor ──▶│ 輸入調理單元 │──▶│  輸入介面  │──┐
          └────────────┘   └───────────┘  │   ┌──────────┐    ┌──────────┐
                                          ├──▶│ 即時電腦  │◀──▶│ 人機介面  │◀── 操作員
          ┌────────────┐   ┌───────────┐  │   └──────────┘    └──────────┘
actuator◀─│ 輸出調理單元 │◀──│  輸出介面  │◀─┘
          └────────────┘   └───────────┘
```

- [24:00] **輸入調理單元**：從環境取得事件。
- 輸入介面 → **即時電腦**：處理事件、算出回應。也可能接到人機介面。
- [24:30] 輸出介面 → 輸出調理單元 → **致動器**：執行動作。

【課本補充】課本：除非特別說明，後面所有討論都隱含假設這個模型。

### 5.2 控制系統與週期性任務

[24:30]–[25:30] 很多即時系統其實是**控制系統**：

```
            參考值 ─┐
                   ▼
      ┌──▶ [ADC] ─▶ 控制演算法 ─▶ [DAC] ─▶ 致動器 ─▶ 受控系統（plant）
      │                                                    │
      └──────────────────── 感測器 ◀────────────────────────┘
```

1. 進來的是**類比**訊號，轉成數位。
2. 算出致動器該怎麼調整。
3. 調整致動器 → 改變受控系統（**plant**）的某個實體性質。
4. 感測器量到變化，再送回來。我們知道**參考值**（應該是多少），也知道感測器量到多少；演算法據此一直算出新的致動器設定。

[25:30] 決策要**快**，否則系統可能失控。

[25:30]–[26:02] 虛擬碼：

```
設定一個計時器，每 T 時間中斷一次（週期性任務）
每次計時器中斷：
    做類比轉數位（ADC）
    算出控制輸出
    轉回類比（DAC），送給致動器
```

這就是一個**週期性任務**的例子。

### 5.3 【實測】週期性迴圈：相對 sleep vs 絕對時間

「每 T 時間做一次」在一般 Linux 上怎麼寫？`periodic.c`：週期 T = 1 ms，跑 2000 個週期，每個週期做一點計算（代表 ADC + 控制運算 + DAC）。量每次醒來時，比理想的第 k 個週期起點晚了多少：

```c
/* 寫法一：每次做完就 sleep 1 ms（相對時間） */
struct timespec d = {0, T_NS}; nanosleep(&d, NULL);

/* 寫法二：睡到「下一個週期的絕對時間點」 */
next.tv_nsec += T_NS;  /* 進位處理略 */
clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, &next, NULL);
```

結果：

```
relative (sleep 1ms)  : after 2000 periods, drift = 631.673 ms, mean lateness = 317483.8 us, max |lateness| = 631672.8 us
absolute (TIMER_ABSTIME): after 2000 periods, drift = 0.171 ms, mean lateness = 173.6 us, max |lateness| = 263.5 us
```

| 寫法 | 2000 個週期後的累積漂移 | 每次醒來平均晚多少 |
|---|---|---|
| 相對 sleep | **632 ms** | 越來越晚 |
| 絕對時間 | **0.17 ms** | 約 174 μs，不累積 |

- 相對寫法：每個週期實際上是「計算時間 + 1 ms + 喚醒延遲」，每個週期多約 0.32 ms，2000 個週期就漂移了 0.63 秒。控制迴圈的取樣週期根本不是 T。
- 絕對寫法：不管計算花多久，都睡到第 k 個週期的起點，誤差**不會累積**。剩下約 0.17 ms 的延遲，來自一般（非即時）task 的計時器寬限（timer slack，預設 50 μs）和排程延遲。
- 這也預告了後面的主題：一般作業系統只能給「大致準時」，要嚴格保證就需要即時排程（第 4 支以後）和 RTOS（第 17 支以後）。

### 5.4 多速率與階層式系統

[26:02]–[27:02] **多速率（multi-rate）控制系統**：複雜的控制系統有多個感測器和致動器，例如**直升機**，不同任務有不同週期：

- 每 1/180 秒驗證一次感測器資料。
- 每 6 個週期做一些控制運算。
- 每隔一個週期做另一些事。

關鍵：很複雜的系統 = 一堆**不同週期**的週期性任務，各做不同的事。

[27:02]–[28:33] **階層式系統**：例如飛機與航管：

```
操作員
  │（取樣率高）
航管（air traffic）
  │
飛行管理（flight management）◀── 導航（navigation）的狀態估計
  │
飛行控制（flight control）   ◀── 狀態估計
  │
飛機本體 / 空氣資料（air data）（取樣率低）
```

- 一層提供輸入給下一層：航管 → 飛行管理 → 飛行控制 → 飛機。
- **即時任務之間有相依性**。
- 需要訊號處理系統做格式轉換，回應時間各不相同。

⚠️ [27:31] 逐字稿說「操作員那端取樣率較高、飛機那端較低」，一般的階層式控制是**越接近實體（內層）取樣率越高**、越外層越低。這裡照錄，原意待確認。

[28:33]–[29:02] **雷達**：數位化的資料存在記憶體，用 DSP 處理，再用另一個資料處理器處理，最後顯示在螢幕上，辨識友機或敵機。

## 6. 感測器、致動器、訊號調理、ADC

[29:02]–[29:31] **感測器（sensor）**：把實體輸入轉成電訊號。種類很多：太陽能電池（光 → 電）、溫度、壓力、震動、加速度、紅外線、GPS、CMOS 攝影機、電子羅盤……通常很**便宜**。

【課本補充】課本：溫度感測器常用**熱電偶（thermocouple）**原理，或電阻隨溫度變化的**熱敏電阻（varistor）**；壓力感測器常用**壓電（piezoelectricity）**原理。

[29:31]–[30:30] **致動器（actuator）**：感測器的反向：把電訊號轉成**實體動作**去改變環境：運動，或熱、電、氣動、液壓等性質的改變。通常是**馬達**（例如機器人移動肢體），也可能是加熱器、液壓或氣動致動器。

[30:30]–[31:31] **伺服機（servo）**：機器人常用的致動器。有一根軸，軸的**角度**可以用訊號控制。只要訊號持續送，伺服機就維持那個角度；訊號一變，角度就變。大量用在機器人、玩具、遙控車，也越來越多用在其他電子產品。

[31:31]–[32:01] **訊號調理（signal conditioning）**：感測器的訊號電壓通常不能直接處理，要**平移**或**放大**；還要做**頻率範圍平移**等等，「訊號要用各種方式加工」。

【課本補充】課本列出四種調理：

| 調理 | 說明 |
|---|---|
| **電壓放大** | 感測器輸出可能只有毫伏，電腦輸入介面要約 1 V |
| **電壓準位平移** | 例：感測器輸出 −0.5 到 +0.5 V，電腦只接受 0 到 1 V |
| **頻率範圍平移與濾波** | 雜訊常在窄頻帶，把訊號移開雜訊頻帶再濾掉 |
| **訊號模式轉換** | 直流 ↔ 交流；或把類比訊號轉成定振幅的脈衝串，脈衝頻率或寬度跟電壓成正比（給不通直流的**變壓器耦合電路**用） |

輸出那一側叫**輸出調理（output conditioning）**，輸入那一側叫**輸入調理**。

[32:01]–[32:30] 整個系統一再出現的模式：類比世界 → **ADC（類比轉數位）** → 處理 → **DAC（數位轉類比）** → 致動器。

【課本補充】課本的 ADC 兩步驟（Figure 5–7）：

1. **取樣**：用電容電路（sample and hold）定期取樣類比訊號，存下電壓，得到**階梯狀**的波形。
2. **量化**：用 ADC 把存下的電壓轉成二進位數字（例如 16 位元），存在暫存器。

輸出介面（Figure 4）：CPU 把值寫到輸出介面的資料暫存器，DAC 把它轉成類比，送到輸出調理單元。介面也負責緩衝和交握（handshake）。

## 7. 【課本補充】即時系統的特性

本講沒講完，課本 §4 開頭的幾項（下一講會繼續）：

| 特性 | 說明 |
|---|---|
| **時間限制** | 每個即時任務都有時間限制，最常見的是**截止時間（deadline）**；還有延遲、持續時間等（§1.7）。RTOS 要負責讓所有任務都滿足限制 |
| **新的正確性標準** | 不只結果在**邏輯上**要對，產生結果的**時間**也重要。邏輯正確但超過截止時間的結果 = 錯的結果 |
| **嵌入式** | 絕大多數即時系統是嵌入式的（Figure 8：感測器收集環境資料 → 即時電腦 → 致動器作用回環境） |
| **安全攸關** | 一般系統的安全性和可靠度是兩回事；很多即時系統裡兩者綁在一起。**安全（safe）**= 失效時也不造成損害；**可靠（reliable）**= 能長時間不失效。安全攸關系統必須高度可靠（§1.5） |
| **並行** | 要在很短的時間內回應好幾個獨立事件。例：化學工廠的各個感測器以不同速率非同步產生資料，要並行處理，否則訊號會遺失。這類系統可視為**非確定性**的：相同輸入跑兩次，可能因為輸入的時間不同而得到不同輸出 |

## 8. 一頁速查表

### 8.1 定義

| 名詞 | 意思 |
|---|---|
| 嵌入式系統 | 嵌在真實世界應用裡的電腦系統 |
| 即時系統 | 描述行為時需要**定量**時間（實體時鐘） |
| 邏輯時間 | 只有先後順序（happens-before），不需要時鐘 |
| 反應式系統 | 讀刺激、做回應 |

### 8.2 事件

| 類型 | 間隔 |
|---|---|
| 週期性 | 固定週期 |
| 偶發性 | 隨機，但有最小間隔 |
| 非週期 | 隨機，最小間隔 = 0 |

### 8.3 模型

感測器 → 輸入調理 → 輸入介面（ADC）→ 即時電腦 ↔ 人機介面；即時電腦 → 輸出介面（DAC）→ 輸出調理 → 致動器。控制迴圈 = 週期性任務。

### 8.4 訊號調理

電壓放大、準位平移、頻率平移與濾波、模式轉換。ADC = 取樣 + 量化。

### 8.5 週期性迴圈

用**絕對時間**（`clock_nanosleep(..., TIMER_ABSTIME, ...)`）睡到下一個週期起點，誤差不累積；相對 sleep 會累積漂移（實測 2000 個 1 ms 週期漂移 632 ms）。

## 附：本講一句話總結

> **即時系統是描述行為時需要用實體時鐘「定量」表達時間的系統（例：超過 500°C 就要在 100 ms 內噴冷卻劑），不同於只講先後的邏輯時間；這類系統大多嵌在實體世界裡，數量遠超一般電腦（約 70% 的處理器），從汽車（一台車上幾十到上百個 ECU、用 CAN bus 互連）、雷射印表機、手機、SCADA 到飛機自動駕駛和反飛彈系統都是。它們多半是反應式的，處理週期性、偶發性（有最小間隔）和非週期（間隔可為 0）三種事件；基本模型是感測器 → 訊號調理 → ADC → 即時電腦 → DAC → 訊號調理 → 致動器，控制迴圈本身就是一個週期性任務，複雜系統則是多個不同週期、彼此相依的任務。實測在一般 Linux 上寫週期迴圈時，必須睡到絕對時間點，否則 2000 個 1 ms 的週期就會累積 0.63 秒的漂移。**
