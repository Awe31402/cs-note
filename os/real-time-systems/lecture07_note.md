## 0. 本講地圖

上一講 EDF 是**動態**優先權；這一講 RMA（Rate Monotonic Algorithm）是**靜態**優先權。

1. 規則：頻率越高（週期越短），優先權越高，而且**不變**。
2. 兩個可排程性測試：
   - **Liu-Layland**：Σ uᵢ ≤ n(2^{1/n} − 1)，n → ∞ 時 → ln 2 ≈ 0.69。簡單但保守。
   - **Lehoczky**：零相位下，每個任務在第一個 deadline 前的需求 ≤ 週期。比較準。
3. 調和週期的任務：Σ uᵢ ≤ 1 就夠了。
4. RMA 雖然 bound 比 EDF 低，但**過載時穩定**、實作簡單，實務上大量使用。

---

## 1. RMA 的規則：週期越短、優先權越高

[00:00]–[02:00]

- 任務的優先權 ∝ 頻率 = 1/週期。

```
priority                     priority
   │      ╱                     │╲
   │    ╱                       │ ╲__
   │  ╱                         │    ╲____
   └──────── rate (1/p)         └────────────── period
```

- 不管什麼時候被排，**同一個任務的優先權永遠一樣** → **靜態優先權**演算法。EDF 則是同一個任務的優先權隨時間改變。
- 和 EDF 一樣**可搶占**。
- 記號：eᵢ 和 cᵢ（completion / execution time）混用，都是執行時間。

【課本補充】（p.50）priority = k / pᵢ，k 是常數。

## 2. 可排程性測試一：必要條件與 Liu-Layland bound

### 2.1 兩個任務的例子

[02:00]–[05:00]

**例 1**：T1 = (e=2, p=4)、T2 = (e=1, p=8)。

- U = 2/4 + 1/8 = **0.625**。
- 兩個任務的 bound = 2(√2 − 1) ≈ **0.82**。
- 0.625 ≤ 0.82 → **保證**可以用 RMA 排。

**例 2**：U = **1**，超過 0.82。

- 但實際排看看（T1 週期短、優先權高，先跑兩單位，再跑 T2……）發現**排得出來**。
- 所以 bound 是**充分條件**，不是精確條件：U > 0.82 時，可能排得出，也可能排不出。

### 2.2 RMA 是靜態優先權裡的最佳演算法

[05:00]–[05:31]

> **RMA 是單處理器、靜態優先權排程演算法中最佳的**：若 RMA 排不出一組週期任務，那沒有任何靜態優先權演算法排得出。

### 2.3 Liu-Layland bound：n(2^{1/n} − 1)

[05:31]–[09:31]

| 條件 | 式子 | 性質 |
|---|---|---|
| 必要 | Σ eᵢ/pᵢ ≤ 1 | 永遠要成立。對 EDF 來說也是充分條件，對 RMA 不是 |
| 充分（Liu & Layland） | **Σ uᵢ ≤ n(2^{1/n} − 1)** | n = 任務數。課本式 2.10 |

- n = 2：2(2^{1/2} − 1) = 2(√2 − 1) ≈ 0.82。
- 隨 n 增加，bound 遞減，最後飽和：n → ∞ 時 → **ln 2 ≈ 0.69**（課本：用 L'Hospital 法則算 ∞·0 型）。
- 意思：**只要使用率 < 約 69%，RMA 一定排得出來**，不管有幾個任務。
- 【口頭】RMA 某種意義上比 EDF 簡單：不用一直維護 deadline、不用維護 priority queue。
- 名稱：RMA（rate monotonic analysis）或 RMS（rate monotonic scheduling），老師兩個混用。
- 本講假設 **d = p**。d > p 會造成緩衝堆積、不實際；d < p 用下一講的 **DMA**。

【課本補充】（p.51）Liu-Layland 的結果發表於 **1973** 年；正式推導超出課本範圍。

## 3. RMA 與 EDF 的排程不同

[10:30]–[15:04]

**能不能造一個 RMA 和 EDF 排法不同的例子？**

- 最簡單：U ≤ 1 但 RMA 排不出的任務集合 → EDF 排得出、RMA 排不出。
- 比較不簡單的：某任務在 RMA 下被高優先權任務搶占；在 EDF 下因為它的 deadline 比較近，**不被搶占**、繼續跑完。

老師的例子：T1 = (3, 8)、T2 = (6, 12)，U = 3/8 + 6/12 = **7/8 = 0.875**，超過 RMA bound 0.83。

- RMA：T2 跑到一半，T1 在 t = 8 到達，優先權高 → **搶占 T2**。
- EDF：t = 8 時，T2 的 deadline（12）比 T1 新實例的 deadline（16）近 → **不搶占**，T2 跑完。
- 兩者 T2 都趕上 deadline，但**排程不同**。

**最壞完成時間**（worst case completion time, WCCT）[13:02]–[14:01]：

- RMA：有 **Lehoczky 的公式**可以直接算最壞情況。
- EDF：沒有封閉公式，要檢查一整個 major cycle（LCM），計算量大。

⚠️ 老師說 WCCT「也叫 worst case execution time」。在本課的用語裡，**WCET 是任務本身的執行時間 e**；WCCT 是加上被高優先權任務干擾後的完成（回應）時間，兩者不同。

**誰的 context switch 比較多？**

⚠️ 老師在 [14:01] 說「RMA 的 context switch **比較多**」（不看 deadline，高優先權一來就切）；但在 [35:01] 的 RMA vs EDF 總比較又說「EDF context switch 多、RMA 少」。前後矛盾。上面 (3,8)、(6,12) 的例子裡，RMA 在 t = 8 多搶占一次，支持第一種說法；§6 的實測兩個例子切換次數一樣。課本沒有比較這點。

**留給學生的問題**【口頭】：如果一組任務在 RMA 下可排程，RMA 和 EDF 會產生一樣的排程嗎？（老師只給提示「看這張投影片」，這裡不附答案。）

## 4. 可排程性測試二：Lehoczky 的條件

### 4.1 為什麼需要更好的測試

[15:04]–[17:01]

- Liu-Layland 的 69% **非常保守**（只是充分條件）。
- 很多實驗顯示，**69%–88%** 是一個灰色地帶：很多任務集合不滿足 bound，但其實排得出來。
- 例：三個任務 U = 0.753，通過；稍微調高使用率就不通過 Liu-Layland，但很可能仍然可排。

【課本補充】（p.57）實驗發現，週期彼此獨立的大量任務集合，平均可排程的最高使用率接近 **88%**。

### 4.2 零相位是最壞情況

[17:01]–[23:31]

> **定理**（課本 Theorem 2.3）：一組週期任務在**任何相位**下都能用 RMA 排，**若且唯若**在**零相位**（全部在 t = 0 同時釋出）下，每個任務都趕上它的**第一個** deadline。

非正式證明【口頭】：T1、T2，p₁ < p₂，T1 優先權較高。

- **情況 1**：T2 在 t = 0 釋出，T1 稍後才來。T2 先做了一點工作，T1 來了搶占它，T2 之後再繼續。
- **情況 2**：T1、T2 同時釋出。T1 先跑完，T2 才開始。T2 一點先機都沒有。
- 情況 2 對 T2 比較糟（或一樣），不會比較好。
- 推廣到多個任務：把高優先權任務往前挪，只會讓排程**一樣或更糟**，絕不會變好。
- 所以從任一任務看，**所有高優先權任務都和它同時釋出**就是最壞情況。

做法：考慮零相位，檢查每個任務的第一個 deadline。全都趕上 → 整組可排。

課本 Fig.12 例子：T1 = (10, 30)、T2 = (60, 120)。

| | T2 的回應時間 |
|---|---|
| T1 和 T2 同相位 | **90 ms** |
| T1 相位落後 20 ms | **80 ms** |

（§6 實測重現。）

### 4.3 Lehoczky 的式子

[23:31]–[26:31]（課本式 2.11–2.12）

任務依週期排序：p₁ ≤ p₂ ≤ … ≤ pₙ（優先權反過來：T1 最高）。

看任務 Tᵢ 的第一個週期 pᵢ 內：

- 高優先權任務 Tⱼ（j < i）在這段時間內釋出 **⌈pᵢ/pⱼ⌉** 次。取上取整：可能最後一個實例釋出時，pᵢ 還剩一點時間，但我們要它們全部做完。
- 每次要 eⱼ。
- 加上 Tᵢ 自己的 eᵢ，就是 pᵢ 內對 CPU 的總需求：

> **eᵢ + Σⱼ₌₁^{i−1} ⌈pᵢ/pⱼ⌉ · eⱼ ≤ pᵢ**

【口頭】和 EDF 證明的邏輯很像（需求 ≤ 時間）。注意那個**上取整**。

【課本補充】（p.55）d < p 時，把 pᵢ 換成 dᵢ：eᵢ + Σ ⌈dᵢ/pₖ⌉·eₖ ≤ dᵢ（式 2.13）。

### 4.4 例題

[26:31]–[30:01]

**例 A**（課本 Ex 2.7）：T1 = (20, 100)、T2 = (30, 150)、T3 = (60, 200)。

- U = 0.2 + 0.2 + 0.3 = **0.7** ≤ 3(2^{1/3} − 1) = **0.78** → Liu-Layland 通過。

**例 B**（課本 Ex 2.8 / 2.9）：T3 改成 (90, 200)。

- U = **0.85** > 0.78 → Liu-Layland **不通過**。
- Lehoczky：

| 任務 | 需求 | 第一個 deadline | |
|---|---|---|---|
| T1 | 20 | 100 | ✓ |
| T2 | 30 + ⌈150/100⌉·20 = 30 + 40 = **70** | 150 | ✓ |
| T3 | 90 + ⌈200/100⌉·20 + ⌈200/150⌉·30 = 90 + 40 + 60 = **190** | 200 | ✓ |

→ 三個都通過，**可以用 RMA 排**。

- Lehoczky 比 Liu-Layland 難算一點，但 bound 更好。

【課本補充】課本 Ex 2.9 對 T2 寫的是 e₁ + e₂ = 50 < 150（直接看排程，T1 在 T2 完成前只出現一次）。照公式取上取整會得到 70（老師的算法）。兩者都 < 150，結論相同；公式算的是保守的上界。

【課本補充】課本 Ex 2.10：T1 = (10, 20)、T2 = (15, 60)、T3 = (20, 120)，U = 0.91（課本寫的值；精確是 0.917），Liu-Layland 不通過；Lehoczky：T1 = 10 ≤ 20；T2 = 15 + ⌈60/20⌉·10 = **45** ≤ 60；T3 = 20 + 6·10 + 2·15 = 110 ≤ 120 → 可排。

⚠️ 課本 Ex 2.10 的 T2 寫成「10 + ⌈60/20⌉ × 10 ≤ 60，即 20 + 30 = 50 ≤ 60」，算式和數字都對不上（應是 e₂ = 15 加上 3 × 10 = 45）。結論不受影響。

【課本補充】課本 Ex 2.11：**可能出現高優先權任務錯過、低優先權任務趕上**。T1 = (15, 20)、T2 = (6, 35)、T3 = (3, 100)：T3 需求 3 + 3·6 + 5·15 = 96 ≤ 100 ✓；T2 需求 6 + 2·15 = 36 > 35 ✗。所以**不能只檢查最低優先權的任務**，每個都要查。

### 4.5 測試不通過時

[30:01]–[31:00]

- 這些在 Lehoczky 等人 **1989** 年的論文裡有詳細討論。老師講的是**簡化版**；完整版是**若且唯若**（充要）。
- 簡化版是**充分條件**。
- 而且它檢查的是零相位的最壞情況；如果實際上不會出現零相位，任務集合可能仍然排得出，但這個測試抓不到。

課本 p.55–56 也說：不滿足式 2.13 仍可能排得出，因為實際任務可能有非零相位。

## 5. 調和週期的任務

[32:30]–[35:01]（課本 Theorem 2.4，p.57）

- **調和相關（harmonically related）**：任兩個任務 Tᵢ、Tₖ，若 pᵢ > pₖ，則 pᵢ 是 pₖ 的整數倍。
- 例（課本）：T1 = (5, 30)、T2 = (8, 120)、T3 = (12, 60)。

> **調和任務：Σ uᵢ ≤ 1 是 RMA 可排程的充要條件**（和 EDF 一樣）。

證明：從 Lehoczky 的式子出發，⌈pᵢ/pₖ⌉ = pᵢ/pₖ（整除，上取整沒作用）：

```
eᵢ + Σₖ (pᵢ/pₖ)·eₖ ≤ pᵢ
兩邊除以 pᵢ：eᵢ/pᵢ + Σₖ eₖ/pₖ ≤ 1
取 i = n：Σ uₖ ≤ 1
```

Lehoczky 的條件**自動**變成必要條件 → 若且唯若。

## 6. 【實測】RMA 分析與 RM / EDF 模擬

```python
r = min(ready, key=(lambda r: (ts[r[1]][1], r[1])) if policy == "RM" else (lambda r: (r[0], r[1])))
#                  RM：週期（固定）                              EDF：絕對 deadline
```

```
U~0.85: RM 81.0%  EDF 100.0%

U~1.00: RM  4.0%  EDF 54.7%
```

- U ≤ 0.70（低於 5 任務的 bound 0.743）：RM 全部排得出，符合 Liu-Layland。
- 0.8–0.9：RM 還能排出大部分——就是老師說的 69%–88% 灰色地帶。
- EDF 在 U < 1 幾乎都排得出（U ≈ 1 時有些集合因取整超過 1）。

## 7. RMA 的其他性質

### 7.1 暫時過載下穩定

[31:00]–[32:01]

- RMA 在暫時過載下**穩定**。EDF 對過載反應不好。
- 高優先權任務**一定**繼續執行：就算某個任務延遲了，也要把 CPU 讓給高優先權任務。
- EDF 沒有把優先權綁在任務上，我們認為重要的任務可能被擠掉。
- 所以要**確定性（deterministic）**排程時，RMA 是比較好的選擇。

課本 p.58：低優先權任務就算超時，也不能讓高優先權任務等——高優先權任務一就緒就搶占它。

### 7.2 實作：多層佇列

[32:01]–[32:30]

| 做法 | 找最高優先權 | 插入 |
|---|---|---|
| 簡單 FIFO 佇列 | O(n) | O(1) |
| Priority queue | O(1) | O(log n) |
| 和 EDF 一樣的類 radix sort 技巧：依**優先權等級**組織的多層佇列 | 很快 | O(1) |

（老師在這裡把多層佇列稱為 multi-level feedback queue。）

【課本補充】（p.57–58）幾乎所有商用 RTOS 都支援 RMA：提供**即時（靜態）優先權等級**，每個等級一個佇列（Fig.15）。同一等級內，通常可選時間片輪流或 FIFO——下一章會講這個選擇對資源共享協定的影響。

### 7.3 【原始碼】Linux SCHED_FIFO 的優先權陣列

Linux 的 `SCHED_FIFO` / `SCHED_RR` 就是課本 Fig.15 的結構：每個即時優先權一個佇列，加一個 bitmap 記錄哪些佇列非空。

`kernel/sched/sched.h:273`

```c
struct rt_prio_array {
	DECLARE_BITMAP(bitmap, MAX_RT_PRIO+1); /* include 1 bit for delimiter */
	struct list_head queue[MAX_RT_PRIO];
};
```

`kernel/sched/rt.c:1769`

```c
static struct sched_rt_entity *pick_next_rt_entity(struct rt_rq *rt_rq)
{
	struct rt_prio_array *array = &rt_rq->active;
	struct sched_rt_entity *next = NULL;
	struct list_head *queue;
	int idx;

	idx = sched_find_first_bit(array->bitmap);
	BUG_ON(idx >= MAX_RT_PRIO);

	queue = array->queue + idx;
	if (SCHED_WARN_ON(list_empty(queue)))
		return NULL;
	next = list_entry(queue->next, struct sched_rt_entity, run_list);

	return next;
}
```

對照：

| 本講 | Linux |
|---|---|
| 依優先權等級的多層佇列 | `queue[MAX_RT_PRIO]`（100 個等級） |
| 找最高優先權 O(1) | `sched_find_first_bit()`：在 bitmap 找第一個 1 |
| 同等級 FIFO / 輪流 | `SCHED_FIFO` / `SCHED_RR` |
| 靜態優先權 | `sched_priority` 由使用者設定，kernel 不會自己改 |

重點：Linux **不會**幫你做 RMA。RMA 是一種「怎麼**指定**靜態優先權」的規則：要用 RMA，就自己把週期越短的執行緒設成越高的 `SCHED_FIFO` 優先權。kernel 只負責「永遠跑最高優先權」。

【實測】本機 `ulimit -r` = 0，一般使用者 `chrt -f 10 true` 回傳 `Operation not permitted`。要設 SCHED_FIFO 需要 root 或 `CAP_SYS_NICE`（或提高 RLIMIT_RTPRIO），所以這裡只用模擬器實驗。

### 7.4 RMA vs EDF 總比較

[35:01]–[36:34]

| | EDF | RMA |
|---|---|---|
| 優先權 | 動態（看 deadline） | 靜態（看週期） |
| 單處理器最佳性 | 所有演算法中最佳 | 靜態優先權中最佳 |
| 可排程性（d = p） | Σ uᵢ ≤ 1（充要） | Liu-Layland（充分）、Lehoczky |
| 調和週期 | Σ uᵢ ≤ 1 | Σ uᵢ ≤ 1（充要） |
| 最壞完成時間 | 要檢查整個 major cycle | Lehoczky 公式 |
| 暫時過載 | 骨牌效應、不可預測 | 穩定，高優先權不受影響 |
| 實作 | 要追蹤 deadline | 簡單，不用追蹤 deadline |

- RMA **大量使用**：太空、很多嵌入式應用；影響了許多 IEEE 標準（例如 IEEE Futurebus+）；廣泛用於時間關鍵系統的離線分析與驗證。
- 老師：RMA 和 EDF 在很多方面**定義了這個領域的方向**。

【課本補充】（p.58）RMA 的缺點：很難支援非週期和偶發任務；d ≠ p 時不再最佳（→ DMA，下一講）。

## 8. 一頁速查表

### 8.1 規則

優先權 ∝ 1/週期，固定不變，可搶占。靜態優先權中最佳。

### 8.2 測試

| 測試 | 式子 | 性質 |
|---|---|---|
| 必要 | Σ eᵢ/pᵢ ≤ 1 | — |
| Liu-Layland（1973） | Σ uᵢ ≤ n(2^{1/n} − 1) | 充分；n=2: 0.828、n=3: 0.780、∞: 0.693 |
| Lehoczky（簡化） | eᵢ + Σⱼ<ᵢ ⌈pᵢ/pⱼ⌉·eⱼ ≤ pᵢ，每個 i | 充分；d < p 時 p 換成 d |
| 調和週期 | Σ uᵢ ≤ 1 | 充要 |

- 零相位 = 最壞情況：零相位下第一個 deadline 都趕上 ⇔ 任何相位都可排。
- 每個任務都要檢查（Ex 2.11：中間的任務可能錯過）。
- 69%–88% 是灰色地帶：不過 Liu-Layland，但常常排得出。

### 8.3 RMA vs EDF

EDF bound 高（1），但過載不穩定；RMA bound 低（≥ 0.69），但過載穩定、實作簡單、實務常用。

### 8.4 Linux

`SCHED_FIFO` = 靜態優先權 ＋ 每級一個佇列 ＋ bitmap 找最高。RMA 的優先權要自己依週期指定。

## 附：本講一句話總結

> **RMA 依頻率給靜態優先權（週期越短越高、永不改變），是單處理器上靜態優先權排程的最佳演算法；可排程性的必要條件是 Σ uᵢ ≤ 1，充分條件是 Liu-Layland 的 Σ uᵢ ≤ n(2^{1/n} − 1)（n=2 為 0.828、n→∞ 為 ln 2 ≈ 0.69），但它很保守，69%–88% 之間常常仍可排；更準的是 Lehoczky 的條件——因為零相位（所有高優先權任務同時釋出）是最壞情況，只要每個任務都滿足 eᵢ + Σ⌈pᵢ/pⱼ⌉eⱼ ≤ pᵢ 就能排（例：U=0.85 的 Ex 2.8 算出 190 ≤ 200），而且每個任務都要查，因為可能中優先權的任務錯過、最低的反而趕上；週期彼此調和時，Lehoczky 會化成 Σ uᵢ ≤ 1 的充要條件。RMA 的 bound 雖比 EDF 低（實測 U≈0.9 時 RM 只排出 45%、EDF 99%），但暫時過載時高優先權任務完全不受影響（實測 RM 只有超時的任務錯過、EDF 三個任務全受害），實作也簡單，所以在太空、嵌入式與 IEEE 標準中被大量使用；Linux 的 SCHED_FIFO 提供每級一佇列的靜態優先權，RMA 的優先權則要自己依週期指定。**
